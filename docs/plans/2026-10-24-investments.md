## Образец в 1С

1С:Управление холдингом 3.3, глава 13 «Инвестиционные проекты» (its.1c.ru, `uhdoc33`):
- справочник «Проекты и этапы»;
- вкладка «Ключевые показатели» с колонками План / Факт / Отклонение / % выполнения;
- ставка дисконтирования задаётся вручную;
- стоимость планируется бюджетами (БДДС, БДР) по периодам;
- показатели эффективности: NPV, IRR, срок окупаемости (PBP), индекс прибыльности (PI);
- факт подтягивается кнопкой «Актуализировать показатели».

Отсюда берём саму модель: проект → план потока по периодам и статьям → показатели план/факт. Без сценариев, этапов, Ганта и многокритериального выбора.

## Решения пользователя (2026-10-24)

| Вопрос | Решение |

## Факт

Учитываются проведённые документы с датой ≥ `start_date`. Суммы берутся без НДС.

**Правило старшинства:**
- поле задано → весь документ идёт только в этот проект;
- поле пустое → в проект идут только строки или шапка со статьёй, закреплённой за проектом;
- документ, у которого поле указывает на другой проект, по статьям не учитывается.

| Документ | Направление | Сумма | Статья |
| --- | --- | --- | --- |
| `receipt` поступление | вложение | `net` строки | статья строки (у товаров — пусто) |
| `supplier_return` возврат поставщику | вложение со знаком − | `net` строки | статья строки |
| `other_costs` прочие затраты | вложение | `amount` строки | статья строки |
| `write_off` списание | вложение | себестоимость по `documentLineCosts` | статья шапки |
| `realization`, `act` | поступление | `net` строки | пусто («Выручка») |
| `customer_return` | поступление со знаком − | `net` строки | пусто |
| `stock_posting` оприходование | поступление | себестоимость | статья шапки |

- Закрытый проект: новые документы к нему не привязываются, привязанные черновики не проводятся, а по статьям учитываются только документы, проведённые до `closed_at`.
- Строка без статьи относится к статье проекта того же направления, если такая статья одна.
- По статьям (запасной путь) ловятся строки и шапки, у которых есть статья: поступления и возвраты поставщику по строкам, прочие затраты, списания и оприходования.
- Факт раскладывается по периодам проекта. Дата позже горизонта попадает в последний период, и карточка показывает предупреждение.
- Поле копируется при «На основании» (заказ поставщику → поступление и т. п.).

## Расчёты (`packages/shared/src/investments.ts`, чистые функции)

- `periodStart(date, kind)`, `periodIndexOf(start, kind, date)`, `periodLabel(start, kind, i)`.
- `periodRate(annualPct, kind)`: `(1+r)^(1/k) − 1`, где k = 12 / 4 / 1.
- `cashflow(lines)`: поток по периодам. Поступления идут с плюсом, вложения с минусом. Суммы — на `decimal.ts`.
- `npv(flows, rate)`: `Σ CFᵢ / (1+r)ⁱ`. **Поток периода 0 не дисконтируется** (в Excel `NPV()` дисконтирует и первый член).
- `irr(flows)`: ставка за период — бисекция с уточнением Ньютоном, затем перевод в годовую `(1+irr)^k − 1`. Если знак потока не меняется или корня нет — `null`.
- `payback(flows)` и `discountedPayback(flows, rate)` — в периодах, дробные, с линейной интерполяцией внутри периода. Если проект не окупается — `null`.
- `profitabilityIndex`: PV поступлений / PV вложений. Если вложений нет — `null`.
- `investmentMetrics(flows, rate, kind)` собирает всё вместе.
- Дисконтирование считается во float, потому что BigInt не умеет дробные степени. Результат округляется до копеек, IRR — до 0,01 процентного пункта.
- Сверочный пример: `[-1000, 300, 400, 500]` при 10%: NPV = −21,04, IRR ≈ 8,90%, простая окупаемость — 2,6 периода.

Показатели считаются трижды:
- **План** — по плану;
- **Факт** — по фактическому потоку;
- **Прогноз** — факт за прошедшие периоды и план за будущие.

## Права

- **Суммы и все производные показатели** (NPV, IRR, PI, окупаемость) видят только admin и owner. Сервер маскирует их через `maskCost` в каждом ответе: список, карточка, план-факт, ответы на действия.
- Member видит список проектов, статусы, сроки, статьи и ссылки на документы, но без сумм.
- В payload событий outbox сумм нет.
- Создавать проект, править его и менять статус могут admin и owner. Member не видит сумм, поэтому и плана править не может.
- Поле «Инвестпроект» в документе ставит member и выше: это ссылка, а не сумма. Варианты для выбора отдаёт `GET /investments/options`.

## API `/investments`

| Метод и путь | Что делает |
| --- | --- |
| `GET /` | список: статус, поиск, архив. Итоги плана и факта, NPV, IRR |
| `GET /options` | неархивные и незакрытые проекты для поля документа |
| `GET /:id` | карточка: план, статьи, ссылка на проект задач, поток по периодам, показатели «план, факт, прогноз» |
| `GET /:id/plan-fact` | статья × период: план, факт, отклонение. Плюс документы факта |
| `POST /`, `PATCH /:id` | создание и правка (только черновик); строки плана и статьи заменяются списком |
| `POST /:id/status { action }` | смена статуса: `approve`, `unapprove`, `close`, `reopen` |
| `DELETE /:id`, `POST /:id/restore` | архивирование и возврат |

События outbox: `investment.created|updated|status_changed|archived|restored`.

Сводный план-факт по всем проектам строится из `GET /` (там уже есть итоги плана, факта и прогноза), отдельного маршрута нет.

## Интерфейс

- Раздел **«Финансы»** (`NAV_GROUPS.finance`):
  - `/investments` — список проектов;
  - `/investments/plan-fact` — сводный план-факт.
- **Карточка `/investments/:id`** — как форма 1С:
  - шапка: название, статус, шаг, начало, горизонт, ставка, организация, ответственный, проект задач;
  - панель показателей «План / Факт / Прогноз»;
  - вкладки `DocTabs`:
    - «План» — строки «период × статья × сумма»;
    - «Денежный поток» — по периодам: вложения, поступления, чистый поток, накопленный, дисконтированный накопленный;
    - «План-факт» — по статьям и периодам, отклонение, документы факта;
    - «Статьи проекта» — запасной путь факта;
  - комментарий внизу.
  - Числа вводятся через `inputMode="decimal"`, поэтому стрелки ↑↓ меняют значение.
- Поле **«Инвестпроект»** в шапке документов из таблицы факта (`DocumentPage`) и в «Прочих затратах».
- Тексты — неймспейс `finance` (`en/finance.ts` + `ru/finance.ts`).
