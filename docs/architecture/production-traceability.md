# Прослеживаемость партий (traceability)

Реализовано поверх партионного учёта (задача 1187, раздел [«Склад»](./stock.md#партионный-учёт-задача-1187)).
Задача 1253. Партия — `stock_batches` (склад, товар, номер); остаток партии — производная сумма
движений `stock_moves` по `batch_id`. Здесь — **связи партий** и двусторонняя трассировка.

Не путать с серийными номерами (`serial_numbers`, задача 1099): серийный номер — это экземпляр товара,
прослеживаемость партий — граф «из какого сырья сделана партия» / «куда ушло сырьё партии». Это отдельная
сущность `stock_batch_links`, серийные номера не переиспользуются.

## Таблица связей: `stock_batch_links`

Одно ребро — пара «вход → выход» по документу. Связь **не двигает остатки и себестоимость** — только граф.

| Поле | Смысл |
|---|---|
| `document_id` | Документ, породивший связь: выпуск продукции, перемещение, отчёт о переработке |
| `kind` | `production` — выпуск/разборка; `transfer` — перемещение; `processing` — давальческое сырьё |
| `input_batch_id` / `output_batch_id` | Партия-источник и партия-результат своего склада (у переработки могут быть `null`) |
| `input_line_id` / `output_line_id` | Строки документа связи |
| `input_product_id` / `output_product_id` | Товары входа/выхода (узлы дерева без партии) |
| `owner_kind` / `owner_company_id` | Собственный материал (`own`) или давальца (`customer`) |
| `processing_order_id` | Заказ на переработку (для `processing`) |
| `qty` | Количество по связи |

Новые таблицы арендатора защищены `app_secure_tenant_table` (RLS по `workspace_id`). Миграция —
`packages/db/drizzle/0150_batch_traceability.sql` (журнал `idx: 145`).

### Кто и когда пишет связи

`recordStockBatchLinks` (packages/db/src/traceability.ts) вызывается из `postDocument` после проведения
движений склада для документов `production`, `stock_transfer`, `tolling_receipt`, `tolling_report`,
`tolling_return`. Связи читаются **из уже записанных движений**, поэтому совпадают с реальным
проведением и не дублируют логику FEFO/средней:

- **production**: каждая израсходованная партия сырья (`qty < 0`, `batch_id`) → каждая выпущенная партия
  продукции (`qty > 0`, `batch_id`). Заодно работает для **разборки**: исходный товар → выходные продукты.
- **transfer**: партия склада-источника → партия склада-получателя, попарно по товару (приёмка наследует
  номер и даты партии отправки).
- **processing** (давальческое сырьё): у своего склада партий нет, движения живут в
  `customer_stock_moves`. Связь держится за заказ на переработку: материалы давальца → продукция
  давальца; партии своего склада в таком ребре могут отсутствовать.

Запись **идемпотентна**: перед вставкой связи документа удаляются. Отмена проведения
(`unpostDocument`) вызывает `removeStockBatchLinks`, а удаление партии каскадно убирает её рёбра
(`ON DELETE cascade`). Восстановление черновика и повторное проведение пересоздают связи.

## Два направления трассировки

API (монтируется в `/stock`, чтение — любой участник):

- `GET /stock/batches/:id/from` — **назад, «из чего сделана партия X»**;
- `GET /stock/batches/:id/where-used` — **вперёд, «куда ушло сырьё партии Y»**.

Параметр `?depth=N` (1..50) ограничивает глубину разворота. Ответ — `{ direction, root }`, где `root` —
вложенное дерево (см. ниже). Если партии нет (или она чужого арендатора — RLS) — `404`.

### Назад (`from`)

```
партия X
  └ документ, создавший партию (выпуск / перемещение / поступление)
      ├ израсходованные партии сырья (по stock_batch_links, рекурсивно)
      └ для поступления — поставщик, дата и номер партии
```

Узел-партия берёт дату выработки и «годен до» из `stock_batches`; документ-поступление несёт
контрагента (`documents.counterparty_id → companies`), поэтому цепочка доходит до поставщика.
Полуфабрикаты раскрываются рекурсивно: партия полуфабриката — тоже выход какого-то выпуска.

### Вперёд (`where-used`)

```
партия Y
  └ документы, где партия израсходована (отрицательные stock_moves)
      ├ production  → выпущенные партии продукции (рекурсивно вперёд)
      │              + продукция и заказ давальца для переработки
      ├ stock_transfer → партия на складе-получателе (рекурсивно)
      ├ realization / work_order → заказ покупателя (по цепочке based_on)
      └ write_off / supplier_return → лист
```

Отгрузки и заказы находятся по движениям (`stock_moves.batch_id`) и цепочке «на основании»
(`documents.based_on_id`) — от реализации к заказу покупателя. Перемещения дают выход на партию
склада-получателя, откуда трассировка продолжается.

## Построение дерева и защита от циклов

Чистый построитель — `buildTraceTree` в `packages/shared/src/traceability.ts` (тесты —
`packages/shared/test/traceability.test.ts`). Ему дают плоские узлы (`TraceNodeSeed`) и рёбра
«родитель → потомки»; он собирает вложенное дерево:

- **циклы** обрываются по множеству предков текущей ветви (A → B → A не разворачивается бесконечно);
- **«ромб»** (узел достижим двумя путями) циклом не считается — узел законно появляется в двух ветвях;
- дубли рёбер у одного родителя отбрасываются;
- ограничены **глубина** (`maxDepth`) и **число узлов** (`maxNodes`) — предохранитель от взрыва дерева.

Узел дерева (`TraceNode`): `id`, `kind` (`batch | document | movement | order | supplier | processing`),
`title`, `subtitle`, `batchId`, `documentId`, `documentType`, `documentNumber`, `productId`, `productName`,
`warehouseId`, `number`, `qty`, `date`, `meta`, `children`.

## Интерфейс

Кнопка «Прослеживаемость» в строке партии на экране **Batches** (`/batches`) открывает диалог
(`apps/web/src/app/docs/batch-trace.tsx`) с переключателем «Из чего сделана / Куда ушло» и деревом.
Клик по партии углубляет трассировку в неё, клик по документу открывает карточку документа.
Тексты — через `t()`, ключи `batches.trace.*` в словарях `en`, `ru`, `es`.

## Ограничения

- **Давальческое сырьё** (`customer_stock_moves`) не имеет партийного измерения: у него нет номера
  партии и дат. Трассировка давальца ведётся на уровне заказа на переработку и товара, а не «партии
  давальца» в строгом смысле; связи `processing` это отражают.
- **Перемещение «в пути»**: прямая передача пишет связь «источник → получатель» тем же документом.
  Для приёмки «в пути» отдельным документом (фаза 2) партия-источник берётся из оприходованных
  ранее порций; связь строится по совпадению товара и номера партии в документе приёмки.
- Связи хранят количество по списанной партии; распределение стоимости/количества между несколькими
  выходами одного выпуска не детализируется — граф показывает факт «эта партия ушла в этот выпуск».
