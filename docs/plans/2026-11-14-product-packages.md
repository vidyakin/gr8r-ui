# Упаковки товара (единицы с коэффициентом), как упаковки номенклатуры в 1С

Задача: учёт в упаковках — поставщик продаёт ящиками по 100 шт, списание в штуках; в документах можно выбрать любую единицу товара;
прайсы поставщиков с колонкой единицы и/или кратности.

## Решения

### Схема
- `product_units` (миграция 0121): `id`, `workspace_id`, `product_id`, `unit_code`, `factor numeric(18,6) > 0`, `created_at`.
  Уникально `(workspace_id, product_id, unit_code)`; составные FK на `products` (cascade) и `units`; RLS — `app_secure_tenant_table`.
  Базовая единица — `products.unit_code`, в `product_units` её нет (сервис не даёт завести упаковку с базовой единицей и коэффициентом ≠ 1).
- `document_lines.unit_factor numeric(18,6) not null default 1` — коэффициент единицы строки на момент ввода.
- `product_prices.unit_code text null` + `unit_factor numeric(18,6) not null default 1` — цена записана за эту единицу.
- `supplier_price_profiles.factor_col int null` — колонка кратности; `supplier_price_lines.unit_factor numeric(18,6) null` — кратность из файла.

### Количество и пересчёт в строках документа
- **`document_lines.qty` всегда в базовых единицах.** Поэтому остатки, движения, резервы, остаток к отгрузке по цепочке
  (`originLineId`), серийные номера, партии, инвентаризация, перемещение «в пути» и все 49 сервисов, читающих `documentLines.qty`,
  работают без изменений: 2 ящика по 100 — это `qty = 200`, со склада уходит 200 шт.
- `price` — цена за единицу строки (за ящик). Суммы: `qty / unit_factor × price`, одно округление до копейки
  (`computeLine` получил необязательный `unitFactor`; строки из БД передают его сами). Места, считающие суммы вручную
  (`recalcLines`, лояльность, калькуляции, автоскидки), идут через `computeLine` со строкой — проверены.
- Себестоимость прихода = `net / qty` — уже за базовую единицу. Оприходование (`stock_posting`, `opening_stock`) берёт `price / unit_factor`.
- API строки документа: вход — `qty` (базовые единицы, как раньше) **или** `unitQty` (в единице строки, так шлёт форма):
  при `unitQty` сервер считает `qty = unitQty × factor` (больше 3 знаков — 422 `invalid_qty`). Выход — `qty`, `unitFactor`, `unitQty`.
  Внутренние копии строк («на основании», рейсы, производство) передают `qty` из БД и `unitCode` строки — пересчёт не нужен.
- Коэффициент строки: базовая единица товара — 1; та же единица, что у сохранённой строки, — прежний коэффициент; упаковка товара —
  её коэффициент; неизвестная единица — 1 (старое поведение: единица — подпись).
- Печать: количество в единице строки (`qty / factor`), цена за единицу строки.

### Цена в прайсах
- Строка прайса: единица файла (колонка единицы) и кратность (колонка кратности). Единица строки прайса определяется так:
  есть кратность > 1 и нет единицы — «упак» (778); единица = базовая и кратности нет — коэффициент 1; иначе упаковка товара с этой единицей;
  кратность из файла важнее коэффициента упаковки.
- При привязке строки или создании товара по строке, если у товара нет упаковки с этой единицей и коэффициент известен, упаковка заводится.
  Коэффициент неизвестен (единица не базовая, кратности нет, упаковки нет) — при применении строка пропускается с причиной `unit_unknown`.
- Применение пишет в `product_prices` цену **за единицу прайса** с `unit_code`/`unit_factor`. `resolvePrices` отдаёт цену за базовую
  единицу (`price / unit_factor`, до копеек) — производные виды цен, подстановка цены в документ и сравнение «было → стало» работают в базовой единице.
- Сводка «Применить» и блок поставщиков в карточке: цена за единицу прайса и справочно за базовую (1500 ₽/ящ → 15 ₽/шт).

### UI
- Карточка товара: блок «Единицы» — базовая единица и список упаковок (единица, коэффициент), добавление/удаление.
- Строка документа: выбор единицы из базовой и упаковок товара; при смене единицы цена пересчитывается из цены за базовую × коэффициент.
- Профиль прайса: колонка кратности; таблица строк прайса показывает единицу и кратность.

## Порядок работ
db (миграция, сервис упаковок, строки документов, цены) → shared (схемы, `computeLine`) → api (маршруты, тесты) → web.

## Тесты
- Приход 2 ящика по 100 → остаток 200 шт, себестоимость за штуку; реализация 1 ящика → остаток 100; реализация 50 шт на основании
  заказа в ящиках — остаток к отгрузке в штуках; отмена проводки возвращает остаток.
- Загрузка прайса с колонками единицы и кратности: упаковка заводится при создании товара, цена пишется за ящик, сводка показывает цену за штуку.

## Фактическая реализация
- db: `product_units` (0121, RLS, составные FK), `document_lines.unit_factor`, `product_prices.unit_code/unit_factor`, `supplier_price_profiles.factor_col`,
  `supplier_price_lines.unit_factor`; `product-units.ts`; пересчёт — `resolveLines` (`documents.ts`), `computeLine` (shared), оприходование, калькуляции,
  варианты КП (`VariantLine.unitFactor`), печать (`qty` в единице строки).
- Прайс: `supplierLineUnit` и `ensureLinePacks` (`supplier-prices.ts`); при кратности > 1 без колонки единицы — «упак» (778); единица = базовая — коэффициент 1
  (кратность в штуках — минимальная партия); неизвестная кратность — пропуск `unit_unknown`.
- web: блок «Единицы и упаковки» (`catalog/product-units.tsx`), единица строки (`docs/line-unit.tsx`: смена единицы сохраняет сумму и количество в базовых),
  колонка «Кратность» в формате прайса, «За базовую ед.» в сводке «Применить», обе цены в «Номенклатуре контрагента» и истории цен.
- Тесты: `apps/api/test/product-units.test.ts` (приход/расход в упаковках, отгрузка частями, фиксация коэффициента, оприходование, печать, прайс с единицей и кратностью).
- Не сделано: выбор упаковки в инвентаризации, перемещении «в пути» и выпуске (там единица строки — базовая); штрихкод упаковки.
