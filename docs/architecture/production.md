# Производство: спецификации и себестоимость

Реализовано на этапе 4. Код: схема `packages/db/src/schema/production.ts`, расчёт `packages/shared/src/bom.ts` (+ `decimal.ts`), схемы API
`schemas/production.ts`, API `apps/api/src/routes/production.ts`, клиент `apps/web/src/app/production/*`.
Чтение — любой участник; участки и настройки меняет admin и выше, продукцию и спецификации — member и выше.

- `manufactured_items` — справочник продукции (изделия и полуфабрикаты): код, название, `kind` (`product` — изделие, `semi` — полуфабрикат; на уровне
  данных разницы нет: любую продукцию можно включить в другую), единица, ссылка на товар каталога для продажи/склада (`product_id`, необязательно),
  выход на партию (`batch_qty`), процент накладных (`overhead_pct`) и **дней на изготовление** (`lead_days`, рабочих, по умолчанию 0 —
  дата запуска минус этот срок по календарю воркспейса, см. «План производства и пополнение»). Архивируется; продукцию,
  которая входит в чужие спецификации, убрать нельзя.
- `bom_lines (item_id, kind: material|semi|work, sort_order, …)` — спецификация на `batch_qty` единиц (форма строки по типу проверяется `CHECK` в БД):
  - material — `product_id` из каталога (только товары: услуга материалом быть не может, её место — работа), `qty`, `scrap_pct` (отход);
  - semi — `child_item_id` (другая продукция со своей спецификацией), `qty`, **режим полуфабриката `semi_mode`** (`stock` — полуфабрикат выпускается
    отдельно и списывается со склада, `explode` — «фантом», разворачивается до материалов и работ в том же выпуске; по умолчанию `stock`,
    `CHECK` в БД: значение задано только у строк `semi`; миграция `0007_bom_semi_mode.sql`); дерево любой глубины, **циклы запрещены**: при записи строки сервер
    проверяет, достижимо ли изделие из включаемого полуфабриката (`wouldCreateCycle`), под рекомендательной блокировкой воркспейса, чтобы параллельные
    правки разных изделий не замкнули цикл (422 `bom_cycle`); интерфейс не предлагает полуфабрикаты, которые замкнули бы цикл;
  - work — `operation` (название), `work_center_id` (участок, необязательно), `hours`, `rate` за час (пусто — ставка участка) и `fixed_cost`;
    стоимость работы = hours × ставка + fixed_cost; `product_id` — **операция** из каталога (вид номенклатуры «операция»),
    если она есть: работа без операции остаётся текстовой, её стоимость по-прежнему оценивается по норме (этап 4в);
  - `unit_code` строки заполняет сервер из единицы товара / продукции (преобразования единиц нет: строка в единице своего товара).
- `work_centers` — участки со ставкой за час по умолчанию; `warehouse_id` — склад-цех участка (составной FK на `warehouses`, вид `workshop`; проверяется в сервисе).
- Настройка воркспейса `workspaces.settings.materialPriceSource` (`GET/PATCH /production/settings`, меняет admin; интерфейс — Settings → Production) задаёт
  **источник цены материала**: `purchase` (закупочная, по умолчанию), `price` (цена продажи) или `avg_cost` (средняя себестоимость склада, этап 5: взвешенная остатком
  по складам; товар без остатка оценивается закупочной ценой). Нулевая цена считается незаданной: материал оценивается в 0, строка помечается «No price».
- **Себестоимость единицы** считает чистая функция `computeBomCost` в `packages/shared` — одна и та же на сервере (`GET /manufactured-items/:id/cost`, тесты)
  и в интерфейсе (мгновенный пересчёт при правке строки, без ожидания сервера). Арифметика десятичная на BigInt (`decimal.ts`, масштаб 10^-6), без float;
  результат — строки с 4 знаками. Правила: стоимость партии / `batch_qty` = себестоимость единицы; material = цена × qty × (1 + отход%/100);
  semi = qty × себестоимость единицы полуфабриката (его спецификация считается рекурсивно, со своими накладными); **накладные узла = overhead_pct от
  прямых затрат его собственных строк (материалы + работы)** — полуфабрикат уже включает свои накладные, поэтому на него накладные родителя не начисляются
  (нет двойного счёта). Результат — дерево с разбивкой «материалы / работы / накладные / итого» по каждому узлу (партия и единица); затраты полуфабриката
  входят в разбивку родителя по своим статьям. Цикл — `BomCycleError` с цепочкой id.
- **Развёртка и потребность** считают чистые функции `packages/shared/src/bom.ts` — одна и та же на сервере и в тестах. `explodeBom(items, rootId, qty)`:
  спецификация задана на партию, поэтому нормы пропорциональны `qty / batch_qty` (кратности партиям нет, как в УНФ); материал — с отходом, работа — часами,
  полуфабрикат по `semi_mode` строки: `stock` — строка на списание, `explode` — его материалы и работы рекурсивно; цикл — `BomCycleError`.
  `computeNeeds(explosion, availability)` — потребность с учётом остатков: нужно / доступно / дефицит по каждому товару. **Дефицит полуфабриката в режиме
  `stock` разворачивается дальше**: на недостающее количество считаются его материалы и работы (строка «выпустить ПФ × N»). Требования одного товара с разных
  уровней агрегируются и сравниваются с остатком один раз — остаток не списывается дважды. Количества — 3 знака.
- `GET /production/snapshot` отдаёт одним запросом всё для клиентского расчёта: продукцию со строками, участки, материалы из спецификаций (цены) и настройки.
  Клиент кэширует снимок, правит его оптимистично, realtime по событиям `manufactured_item` / `bom_line` / `work_center` / `product` / `workspace`
  перечитывает его. API: `/work-centers`, `/manufactured-items` (+ `/:id/lines`, `/:id/lines/reorder`, `/:id/cost`, `/:id/explode`), `/bom-lines/:id`, `/production/*`.
- `GET /manufactured-items/:id/explode?qty=&warehouseId=` — развёртка спецификации на количество и потребность: остаток склада минус резерв (по складу
  или по всем складам воркспейса), дефицит и строки «выпустить ПФ». Стоимость в ответе не отдаётся: маскирование себестоимости по роли приходит с этапом 0а.
- Интерфейс: `/production` — список продукции с себестоимостью единицы; `/production/:id` — шапка (тип, код, единица, партия, накладные), дерево спецификации
  (иконки по типу строки, количество и стоимость строки, количество правится на месте, перестановка перетаскиванием или «Move up/down», полуфабрикат раскрывается
  в своё дерево — только чтение, строки приведены к вкладу в партию родителя, накладные полуфабриката — отдельной строкой — и открывается переходом) и итог внизу
  (материалы / работы / накладные для партии и для единицы, себестоимость единицы); переключатель **Needs** с полем «Need for» показывает потребность
  (нужно / доступно / дефицит, у полуфабриката — пометка «Produce N»), режим полуфабриката выбирается в форме строки; `/work-centers` — справочник участков; Settings → Production — источник цены.
