# Распределение материалов по итогам смены

Реализовано по задаче 1135 (сессия «УНФ: Производство»), решения пользователя от 2026-10-26 — в
`docs/plans/2026-10-21-unf-production.md`, раздел «Задача 1135». Код: сервис — `packages/db/src/shift-allocation.ts`, выпуск —
`packages/db/src/production.ts`, цепочка себестоимости — `recomputeStockCosts` в `packages/db/src/stock.ts`, чистый расчёт —
`packages/shared/src/shift-allocation.ts`, схема — `packages/db/src/schema/production.ts` (миграция `0031_shift_allocation.sql`, `0032_shift_allocation_items.sql`),
API — `apps/api/src/routes/production-closing.ts` (`/material-allocations`), тесты — `apps/api/test/production-allocation.test.ts`,
`packages/shared/test/shift-allocation.test.ts`, клиент — `apps/web/src/app/production/MaterialAllocationPage.tsx`.

- **Режим.** `work_centers.material_mode` (`on_release` по умолчанию | `shift`) и `production_headers.material_mode` (берётся у участка при
  создании выпуска, правится в черновике: `PATCH /production-orders/:id/accounting`, поле `materialMode`). Режим смены — только сборка,
  включая этапы; разборка и давальческое сырьё всегда «при выпуске» (выпуск создаётся с `on_release`, перевод в смену — 422
  `shift_mode_unsupported`).
- **Выпуск в режиме смены** при проведении не списывает материалы и полуфабрикаты, строки состава остаются нормами (факт `actual_*` пуст,
  резерв заказа не уменьшается); отходы и брак работают как обычно. В форме выпуска строки материалов только для чтения с пометкой «норма».
- **Документ `material_allocation`** («Распределение материалов», префикс РМ, группа production) по модели справки УНФ 8.6.2 «Распределение
  затрат». Шапка — дата (она же **окончание периода**), «Начало периода» (`material_allocations.period_from`, по умолчанию равно дате;
  `period_to` всегда равен дате документа, начало позже даты — 422 `invalid_period`; в форме начало идёт за датой, пока его не изменили
  руками), участок (`documents.work_center_id`), склад списания (по умолчанию склад-цех участка). Вкладки:
  - «Материалы» — обычные строки списания (`document_lines`, роль `out`): факт смены; «Заполнить по нормам» (сумма норм позиций вкладки
    «Продукция») и «Заполнить по остатку цеха» (остаток склада списания на дату документа по материалам норм);
  - «Продукция» — хранимая таблица `material_allocation_items` (позиции выпусков). «Заполнить по выпуску» берёт проведённые выпуски
    участка в режиме смены за период, ещё не вошедшие в другое **проведённое** распределение; строки можно удалить (выпуск остаётся
    свободным для другого документа), удаление позиции убирает и её строки распределения;
  - «Распределение» — хранимая редактируемая таблица `material_allocation_rows` (позиция × материал × количество, до 6 знаков);
    команды «Распределить по нормативам» и «Распределить по количеству» (пропорционально количеству выпуска) заменяют её целиком,
    количества и состав строк правятся вручную (`PATCH`: `items`, `rows`; команды — `POST /:id/fill-items`, `/:id/distribute`
    `{method: norms|qty}`, `/:id/fill-by-norms`, `/:id/fill-by-stock`). Стоимость строки пустая до проведения.
  Создаётся только своим API (общий `POST /documents` — `production_api_only`).
- **Проверки при проведении.** Каждая позиция «Продукции» — позиция проведённого выпуска режима смены того же участка с датой в периоде,
  не вошедшая в другое проведённое распределение (иначе 422 `release_not_allocatable`); строки только по позициям вкладки
  (422 `allocation_row_invalid`); пустое распределение заполняется по нормативам; сумма по каждому материалу равна факту смены
  (иначе 422 `allocation_mismatch`, в `details.products` — материал, распределено и факт). Стоимость — по средней списания,
  пропорционально количеству строк материала. Нематериальные затраты этим документом не распределяются — их распределяет закрытие месяца.
- **Алгоритм** (`allocateShiftMaterials`, `costShares`): материал делится между позициями пропорционально нормативному количеству
  (норма × количество выпуска); материал без норм у всех позиций — пропорционально плановой стоимости материалов позиции, без
  стоимости — по количеству выпуска. Остаток округления — на последнюю строку, сумма долей равна факту; стоимость материала делится по
  долям количества так же.
- **Проведение.** Расход со склада списания по средней (недостаток — обычная ошибка остатков), строки результата, затем
  `production_items.alloc_cost` и `stage_cost` позиции растут на стоимость долей плюс накладные % спецификации. До продукции стоимость
  доходит не записью цены, а прибавкой к цене прихода в `recomputeStockCosts` (отдельная часть, не `own_delta` закрытия):
  `loadAllocationChain` считает её живьём из `alloc_cost`, поэтому остаток дорожает, а уже отгруженное, перемещённое и израсходованное
  получает корректировку по цепочке (себестоимость продаж). `hasCostAdjustments` считает такой воркспейс «с корректировками».
- **Этапы.** Промежуточный этап: `alloc_cost` копится в `stage_cost` (НЗП) своей позиции, а НЗП следующего этапа (`stageTotals`) берёт
  `stage_cost − alloc_cost` — распределённое доходит до продукции финального этапа той же прибавкой (на единицу — `alloc_cost` этапа /
  годное количество, как у обычного НЗП). Если финальный этап уже выпущен — его приход получает корректировку при проведении
  распределения; если выпускается позже — при его проведении (`refreshStageAllocations` в `afterPost`).
- **Отмена проведения** (`beforeUnpost` + `afterUnpost`) возвращает расход, снимает долю из `alloc_cost`/`stage_cost`, обнуляет стоимость строк
  (строки и вкладка «Продукция» остаются в черновике) и пересчитывает цепочку. Отмена выпуска, вошедшего в проведённое распределение — 409 `has_posted_children`; такой выпуск
  не дополняется документом дня (достаточно проведённого распределения). Пересчёт стоимости по нарядам (`recalcReleaseCost`) сохраняет `alloc_cost` в `stage_cost`.
- **Закрытие месяца.** Выпуски режима смены, не вошедшие ни в одно проведённое распределение, дают предупреждение со списком (`totals.warnings`), закрытие идёт.
  Распределённые материалы входят в прямые затраты выпуска для баз распределения: `loadReleaseTargets` берёт
  `stage_cost − alloc_cost` плюс удорожание по цепочке (в нём уже сидит доля распределения), поэтому она считается один раз.
- **Ограничения.** Удорожание самих материалов распределения (корректировки закрытия на расход распределения) до продукции не доходит:
  расход распределения идёт в `seq` после прихода продукции, а проход цепочки односторонний. Резерв материалов заказа на
  производство в режиме смены не уменьшается — выпуск ничего не списывает.
- **Права.** Документ создают и проводят member и выше; стоимость строк результата видят admin и owner (`maskAllocation`).
- **Интерфейс.** Настройка участка — Production → Work centers (поле «Материалы выпусков»), режим выпуска — в шапке выпуска (Segmented),
  документ — Production → Material allocation (`/material-allocations`).
