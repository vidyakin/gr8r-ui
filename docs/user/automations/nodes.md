# Шаги автоматизаций

## Для чего раздел

Справочник по шагам, из которых собирается [автоматизация](automations.md): что запускает сценарий (триггеры), как он выбирает путь (условия и логика) и что делает (действия).

В палитре редактора шаги сгруппированы по категориям «Триггер», «Условие», «Логика», «Действие». Часть шагов пока показывается на английском языке — они перечислены ниже в скобках так, как подписаны на экране.

## Что на экране

### Триггеры (запускают сценарий)

У сценария должен быть ровно один триггер.

| Шаг | Когда срабатывает |
|---|---|
| «Создана запись» | создана запись выбранной сущности |
| «Изменена запись» | изменено любое поле записи |
| «Изменено поле» | изменено поле; можно указать «Было» и «Стало» (необязательно) |
| «По расписанию» | по расписанию в формате cron (например, «По будням в 09:00», «Каждый час», «Каждые 15 мин») |
| «Ручной запуск» | сценарий запускают кнопкой «Запустить», при желании на выбранной записи |
| «Лид создан», «Статус лида изменён» | создан лид; лид перешёл в статус (можно выбрать конкретный) |
| «Deal won», «Deal lost» | сделка перешла в этап категории «выиграна» или «проиграна» (воронку можно уточнить) |
| «Deal moved to a stage» | сделка перешла на другой этап или в другую воронку |
| «Deal exceeded the stage time limit» | сделка задержалась на этапе дольше его лимита времени |
| «Payment posted» | проведён кассовый или банковский документ оплаты |
| «Document paid» | к документу применена оплата; флажок «Only when fully paid» (только при полной оплате) |
| «Vehicle or driver document expires» | подходит или истёк срок документа автомобиля или водителя |
| «Trip sent or completed» | рейс отправлен или завершён |

Сущности для записей: задача, проект, сделка, компания, контакт, товар, документ и ваши собственные сущности из конструктора.

### Условие и логика

- **«Условие»** — сравнивает значение с другим («равно», «не равно», «больше», «меньше», «содержит», «пусто», «не пусто» и т. п.; числа сравниваются как числа). Идёт дальше по выходу «да» или «нет».
- **«Пауза»** — ждёт указанное время (до 30 суток), потом продолжает.
- **«Ветвление»** — выбирает один из нескольких путей по значению; варианты вводятся по одному на строку.

### Действия

| Шаг | Что делает |
|---|---|
| «Изменить поле» | задаёт значение поля записи; значение проверяется так же, как при ручном вводе |
| «Создать задачу» | создаёт задачу в проекте: название, описание, исполнитель, приоритет, статус, срок |
| «Уведомить участника» | отправляет уведомление в приложении |
| «Добавить комментарий» | пишет комментарий к задаче или заметку к сделке |
| «Создать лид» | создаёт лид в первом статусе «новый» |
| «Назначить ответственного за лид» | вручную или по кругу среди менеджеров продаж |
| «Move deal to a stage» | переносит сделку на этап (или на первый этап другой воронки) |
| «HTTP-запрос» | вызывает внешний адрес: метод, URL, заголовки (по одному на строку «Имя: значение»), тело |

## Подстановка значений

В любом текстовом параметре можно использовать значения вида `{{путь}}`:

- `{{trigger.record.title}}` — поле записи, запустившей сценарий; `{{trigger.record.custom.название}}` — пользовательское поле;
- `{{trigger.changes.поле.from}}` и `.to` — что было и что стало;
- `{{trigger.project.leadId}}` — руководитель проекта;
- `{{steps.идентификатор_шага.результат}}` — результат предыдущего шага;
- `{{flow.name}}`, `{{run.id}}`, `{{now}}`.

Проще всего вставить переменную через меню «Вставить переменную» рядом с параметром. Отсутствующее значение подставляется как пустой текст.

## Типовые действия

### Уведомить руководителя, когда задача ушла на проверку

1. Триггер «Изменено поле»: сущность «Задача», поле «Статус», «Стало» = нужный статус.
2. Шаг «Уведомить участника»: получатель «Руководитель проекта (триггер задачи)», сообщение, например «Задача {{trigger.record.title}} ждёт проверки».
3. Опубликуйте.

### Создать задачу, когда сделка выиграна

Триггер «Deal won» → «Создать задачу» с проектом и названием, например «Запуск: {{trigger.record.title}}».

### Отправить данные во внешнюю систему

«HTTP-запрос»: метод `POST`, URL внешней системы, в заголовок добавьте `Content-Type: application/json`, в тело — JSON с подстановками. См. [Секреты, вебхуки и интеграции](integrations.md).

### Реагировать на оплату

Триггер «Document paid» с флажком «Only when fully paid» → шаг «Уведомить участника» (например, ответственного менеджера). Остаток по документу доступен как `{{trigger.changes.remaining}}`; чтобы реагировать на остаток, добавьте «Условие».

## Права

Шаги редактируют владелец и администраторы. Шаги конкретных разделов доступны, только если подключён их модуль (например, «Payment posted» — «Деньги», шаги сделок и лидов — «CRM»); если модуль выключили, запуск такого сценария будет пропущен.

## Частые ошибки

- **Нет такого шага в палитре.** Модуль, к которому он относится, не подключён: [Нужно больше?](../general/upgrade.md).
- **Подстановка не сработала, поле пустое.** Проверьте путь в `{{…}}` и что предыдущий шаг действительно вернул это значение (в запуске посмотрите его «Выход»).
- **«У сценария может быть только один триггер» и «К шагу может вести только одна связь».** Уберите лишний триггер или объедините ветви иначе — слияние путей в один шаг не поддерживается.
- **Изменение поля не проходит проверку.** Значение должно соответствовать типу поля (текст, число, дата, выбор, ссылка).
