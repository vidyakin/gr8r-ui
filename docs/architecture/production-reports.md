# Отчёты производства

Задача 1091, часть 1 (справка УНФ 8.9). Код: сервисы — `packages/db/src/production-reports.ts`, запросы — `packages/shared/src/schemas/production-reports.ts`,
маршруты — `apps/api/src/routes/production-reports.ts` (`GET /production/reports/<имя>`), экран — `apps/web/src/app/production/reports/`.

- **Экран** `/production/reports`: вкладка в адресе (`?tab=`), реестр вкладок `REPORT_TABS` в `ProductionReportsPage.tsx` — новый отчёт добавляется
  вкладкой (файл `*Tab.tsx` + строка реестра + маршрут и хук в `reports-data.ts`). Общие отборы: период, участок, изделие (вкладка сама решает, какие нужны).
- **Общие компоненты:** `ReportTable` — сворачиваемые группировки (уровни `GroupLevel`), итоги в строке группы и общий итог (суммы — `decimal`),
  клик по строке открывает документ-источник (`href`), выгрузка CSV того, что на экране; `BarChart` — SVG-столбцы без зависимостей, цвета — токены темы.
  Ответы кэшируются под `['ws', id, 'production', 'reports', …]` и обновляются событиями документов.
- **Отчёты и правила:**
  - `release` — выпуск продукции: проведённые выпуски периода, приём финальным этапом (как `producedQty`), годное = количество минус брак; изделие → документ.
  - `orders` — заказы на производство по позиции: остаток на начало = заказано до периода минус выпущено до него; заказано и выпущено — внутри периода;
    остаток на конец сходится с «остаток к выпуску» карточки заказа. Срок — `due_date` документа, иначе плановый финиш; просрочка = дней от срока до даты отчёта
    при невыпущенном остатке. Заказ без движения и остатка не попадает.
  - `plan-fact` — строки планов производства (не архивных) с началом периода внутри отбора против годного выпуска изделия за период строки
    (от начала до дня перед следующим периодом плана); строки разных планов на тот же период складываются.
  - `bom` — `explodeBom` на количество: этапы → материалы, расходы, полуфабрикаты (состав полуфабриката справочно, в итог не входит), операции с нормативным временем.
    Цена: «по виду цен» (`purchase | price | avg_cost`, как `resolveMaterialPrice`) или «по последней закупке» (`resolveCostPrice`); накладные и округление — отдельная строка,
    сумма строк равна плановой себестоимости (`computeBomCost`) на количество.
  - `load` — по участкам и дням: мощность и запланировано — расчёт планировщика (`workspaceLoad`, тот же, что `GET /production/load`), факт — нормочасы проведённых
    сдельных нарядов участка по дате наряда; перегрузка — день, где запланировано (или выполнено) больше мощности.
- **Права:** количества — любой участник; стоимость нормативного состава (цены, суммы, накладные, итог) — только admin и owner, остальным `null` (`maskBomReport`,
  по образцу `maskWipBalance`). Период отчёта — не больше года, иначе 422 `report_period_invalid`.
- **Параметрическая спецификация (нормативный состав).** Запрос `bom` принимает `params` — JSON-объект значений параметров изделия; они подставляются в
  `items[root].params` перед `explodeBom`/`computeBomCost`. Экран строит поля по `SpecParamDef` (число — `inputMode="decimal"`, вариант, флажок); по умолчанию выбирается первое
  изделие без параметров. Ошибка формулы — 422 с кодом `formula_param` (не заданы значения) или `formula_error`, текст без идентификатора строки; перевод — `errors.*`
  (коды в `ALWAYS_TRANSLATE`, чтобы и английский показывал перевод).

## Часть 2 (задача 1091)

Сервисы — в том же `packages/db/src/production-reports.ts`, маршруты `GET /production/reports/release-cost | cost-plan-fact | wip-movement`.

- **`release-cost` — себестоимость выпуска** (период, участок, изделие; изделие → документ выпуска). Берутся проведённые выпуски финального этапа с приходом продукции на наш склад;
  выпуски из давальческого сырья (прихода со стоимостью нет) и разборка не входят. Себестоимость прихода = Σ по приходным движениям строки продукции `qty × (цена + корректировка
  stock_cost_adjustments.delta_cost)`. Виды затрат (колонки): `materials` и `semi` — `actual_cost` строк состава (свои, не давальческие); `alloc` — `production_items.alloc_cost`;
  `work` — сумма проведённых сдельных нарядов по строке состава (нет наряда — оценка нормы, как `itemCost`); `services` — расход подрядчику (`expense`);
  `indirect` — своя часть закрытия месяца `own_delta × qty`; `other` — остаток до себестоимости прихода: плановые накладные % спецификации (своего и принятых этапов), вычет возвратных отходов, округление.
  Затраты промежуточных этапов того же заказа (`source_item_id` / `customer_order_line_id`) финальный выпуск принимает через НЗП, поэтому они разнесены по тем же видам:
  доля этапа = min(количество позиции, выполнено этапом) / выполнено этапом (годное), как финальный этап забирает НЗП в `production-wip.ts`; к долям добавляются материалы, полуфабрикаты,
  работы, услуги, `alloc_cost` и `closing_cost` этапа (косвенные этапа — с расшифровкой по статьям из `byRelease[].byCostItem` позиции этапа, одинаковые статьи складываются). Сумма видов равна приходу по построению. Расшифровка косвенных по статьям `cost_items` — из `byRelease[].byCostItem`
  результата закрытия месяца (`production_cost_closings.totals`; для этого `planOverhead` теперь отдаёт `byTargetItem`), делится пропорционально долям, остаток округления — на последнюю статью;
  закрытие, выполненное до этой версии, расшифровки не имеет (одна строка «без расшифровки» до перезакрытия). Отчёт целиком стоимостной: роль ниже admin получает **403 `cost_access_required`**.
- **`cost-plan-fact` — план-факт себестоимости** (период, участок, изделие; изделие → материал → документ). По материалам выпусков всех этапов (`kind = material`, свои): план — `production_components.qty`
  (снимок норм выпуска; брак уже внутри количества выпуска) × фактическая средняя цена списания строки (`actual_cost / actual_qty`; нет списания — средняя по материалу в отчёте); факт — списанное
  (`actual_*`). Выпуск режима смены берёт факт из строк проведённых распределений (`material_allocation_rows`), без проведённого распределения он в отчёт не попадает.
  Отклонение = факт − план (плюс — перерасход) в количестве и сумме. Возвратные отходы материалы не меняют. Суммы — `maskCostPlanFact` (admin/owner), количества видят все.
- **`wip-movement` — НЗП с движением** (период, участок; завершающий участок → заказ → изделие). Остаток на начало и на конец — `wipBalance` на день до начала и на конец (с `includeEmpty`, чтобы
  позиция, прошедшая НЗП внутри периода, не терялась); приход — `stage_cost + closing_cost` выпусков промежуточных этапов периода, количество — по самому широкому этапу, как остаток;
  расход = начало + приход − конец (то, что финальный этап принял в продукцию). Остаток на конец совпадает с `GET /production/wip` на дату конца (в ответе `closingTotal`).
  Суммы — `maskWipMovement` (как `maskWipBalance`).
- **Экран:** вкладки `release-cost`, `cost-plan-fact`, `wip-movement` (`ReleaseCostTab`, `CostPlanFactTab`, `WipMovementTab`); графики — по видам затрат, план/факт материалов, у участника без
  доступа к стоимости график план-факта строится по количествам, колонки сумм скрыты, вкладка себестоимости показывает пояснение вместо 403.
- **Тесты:** `apps/api/test/production-reports.test.ts` — сверка себестоимости выпуска с приходом (обычные выпуски; режим смены с `alloc_cost` и закрытием месяца с `closing`-долей),
  план-факт на перерасходе, НЗП на конец = `/production/wip`, маскирование для member, параметрический нормативный состав.
