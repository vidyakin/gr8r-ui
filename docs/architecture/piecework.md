# Операции, исполнители и сдельный наряд

Реализовано на этапе 4в (сессия «УНФ: Производство»). Код: сервис — `packages/db/src/piecework.ts`, схема — `packages/db/src/schema/production.ts`
(миграция `0014_piecework.sql`), API — `apps/api/src/routes/piecework.ts`, клиент — `apps/web/src/app/production/PieceworkPage.tsx`.

- **Операция — вид номенклатуры.** `products.kind` знает `goods | service | work | operation`. Операция не продаётся и склад не двигает;
  её данные — `operations (workspace_id, product_id, norm_hours, work_center_id)` (норма времени на единицу и участок по умолчанию)
  и `operation_rates (workspace_id, product_id, valid_from, rate, unit)` — **история расценок** с датой начала действия.
  Способ расчёта: `per_unit` (за единицу продукции) или `per_hour` (по норме времени). В наряд идёт расценка, действующая
  **на дату наряда**; сумма строки правится вручную до проведения.
- **Работа спецификации может ссылаться на операцию:** у строки `bom_lines.kind = 'work'` поле `product_id` — операция
  (текстовые работы без операции работают как раньше, оценка `hours × rate` сохраняется). Та же ссылка попадает в снимок
  состава (`production_components.product_id`).
- **Назначение операции исполнителю** — `production_operations (workspace_id, document_id, item_id, component_id, operation_id,
  member_id, task_id, stage_id, work_center_id, planned_qty, planned_hours, done_qty)`. Правила: сумма назначений по операции
  не больше количества позиции заказа (иначе 422 `operation_over_assigned`); без исполнителя задачи нет; у каждого назначения
  есть **задача модуля production** (системный проект `Production`), снятие назначения архивирует задачу. Одна операция
  делится между несколькими исполнителями по количеству.
- **Сдельный наряд** — тип документа `piecework_order` (СН) группы `production`, без контрагента, номер выдаётся при проведении.
  Свои строки лежат в `piecework_lines` (операция, продукция, заказ и выпуск, назначение, **план** и **факт** количества,
  нормочасы, расценка, сумма), шапка — `piecework_headers` (исполнитель и участок): **один наряд на (исполнитель, дата)**,
  повторная отметка дописывает строку. Ввод на основании — `POST /production/piecework/from-document` (заказ на производство,
  выпуск или заказ покупателя): остаток работы каждого исполнителя попадает в наряд за день.
- **Выполнение отмечают оба.** Мастер — в рабочем месте «Выпуск продукции» (отметка строки: `assignments: [{ assignmentId, qty }]`),
  исполнитель — в своей задаче (блок «Production operation» в карточке задачи). Оба пути пишут в наряд исполнителя за день.
- **Проведение наряда** закрепляет выполненное количество за назначением (`done_qty`), закрывает задачу исполнителя, когда
  выполнено всё назначенное, и **пересчитывает себестоимость выпуска**: фактическая стоимость работ (сумма проведённых нарядов)
  заменяет оценку `hours × rate`, цена прихода продукции и средняя склада пересчитываются в той же транзакции
  (`revalueMove` в `packages/db/src/stock.ts`). Если продукцию уже отгрузили — 422 `cost_locked` (корректировка — этап 6).
  До проведения наряда выпуск считает работы по норме — оценка не ломается.
- **Права.** Суммы и расценки видят admin и owner и **сам исполнитель — только свои**; остальным участникам в ответах API
  они приходят пустыми (`maskCost`). Отчёт выработки участнику отдаёт только его строки. Назначать и проводить наряды — member и выше.
- **API:** `GET/PUT /production/operations`, `GET/POST /production/operation-rates`, `GET /production/operations/:id`,
  `POST /production/operations/:id/done`, `GET/POST/PATCH /production/piecework`, `GET /production/piecework/report`,
  `POST /production/piecework/from-document`, `GET/POST /production-orders/:id/operations`.
- **Интерфейс:** `/production/piecework` — журнал нарядов, отчёт выработки и расценки операций; в карточке заказа на производство —
  раздел «Operations» с назначением исполнителей; в строке спецификации — выбор операции из каталога; в карточке задачи операции —
  отметка выполненного количества.
- **Печать:** форма «Сдельный наряд» (`PRINT_FORMS.piecework`): исполнитель, участок, план и факт по каждой операции, расценка и сумма.
