# Каталог: товары и услуги

Реализовано на этапе 4. Код: схема `packages/db/src/schema/catalog.ts` (миграция `0004_catalog.sql`), схемы API
`packages/shared/src/schemas/catalog.ts`, API `apps/api/src/routes/catalog.ts` и `catalog/service.ts`, клиент `apps/web/src/app/catalog/*`.
Чтение — любой участник; единицы, категории и характеристики меняет admin и выше, товары — member и выше.

- `units (workspace_id, code, name, symbol, is_base)` — справочник единиц ОКЕИ **в каждом воркспейсе**: базовый набор (`OKEI_UNITS` в
  `packages/shared/src/constants.ts`: шт 796, кг 166, ч 356, усл. ед 876 …) воркспейс получает при создании (`registerBaseUnits`; для существующих —
  миграция), свои единицы добавляются рядом (код 3–4 цифры, не меняется). Базовые не удаляются; единица, на которую ссылаются товары и
  спецификации, не удаляется (составной внешний ключ). Единица товара — составной FK `(workspace_id, unit_code)`.
- `product_categories` — дерево: `parent_id` + материализованный `path` (id предков и самой категории через «/»), выборка поддерева по префиксу
  (`path = X or path like X/%`, индекс `text_pattern_ops`). Перенос ветки пересчитывает `path` всего поддерева; в себя и в потомков перенести нельзя.
  Удалить можно только пустую категорию (без подкатегорий и товаров).
- `attribute_defs (category_id, key, name, type, required, unit, options, sort_order)` — характеристики категории. Типы — как у полей
  конструктора, кроме ссылок (`user`/`ref`/`refs`) и `datetime`; `options` те же (варианты select, min/max, maxLength). **Наследование:** действующий набор
  категории = характеристики всех предков (от корня) + свои (`GET /product-categories/:id/attributes` отдаёт их с признаком `inherited` и названием
  категории-источника). Ключ уникален вдоль всей ветки: нельзя завести ключ, который уже есть у предка, самой категории или потомка
  (409), и перенести ветку к родителю с таким же ключом. Ключ и тип не меняются. Удаление характеристики — с подтверждением (`?confirm=<ключ>`) и
  необратимо: значения стираются у товаров всей ветки (`attrs - ключ`).
- `products (kind: goods|service|work|operation, sku, name, description, barcode, unit_code, vat_rate, price, purchase_price, category_id, default_supplier_id, attrs jsonb, is_active,
  custom jsonb)`. `vat_rate` — `none|0|5|7|10|20`; `price` — цена продажи, `purchase_price` — закупочная (`numeric(18,2)`, строками). `default_supplier_id` — поставщик по умолчанию
  (составной FK на `companies`): заказы поставщикам по потребности производства создаются на него. `lead_days` —
  срок поставки в днях (для закупки): им считается потребность на обеспечение в расчёте потребностей и заказы
  поставщикам. Нормы запаса товара — `stock_levels`, см. раздел «План производства и пополнение». `sku` и
  `barcode` уникальны в воркспейсе (частичные уникальные индексы по непустым; sku — без учёта регистра), штрихкод — 8–14 цифр. Мягкое удаление — `archived_at`.
  Варианты товара (размер/цвет) — позже, отдельной таблицей. `product` — системная сущность конструктора: пользовательские поля товара лежат
  в `custom` (индексы по ним строит воркер, `SYSTEM_TABLES.product = products`).
- **Проверка `attrs` — тем же механизмом, что поля конструктора:** характеристики категории (с унаследованными) превращаются в `FieldDef`, значения проверяет
  `buildRecordSchema` (`packages/shared/src/fields.ts`) — на сервере (`validateAttrs`) и в формах клиента (`validateRecord`, те же `FieldInput` / `FieldValue`).
  Создание — обязательные заполнены, лишние ключи (в том числе характеристики соседней категории) отклоняются; без категории характеристик нет,
  любые `attrs` — ошибка. PATCH той же категории проверяет только изменённые ключи (как `custom`), `null` убирает ключ. Смена категории проверяет
  итоговый набор целиком по новой схеме, как создание: значения, которых в новой схеме нет, нужно убрать явно (`null`). Перенос категории с товарами,
  у которых есть значения унаследованных характеристик, пропадающих из цепочки, запрещён (422).
- API: `/units`, `/product-categories` (+ `/:id/attributes`), `/attribute-defs/:id`, `/products` (список: `categoryId` с подкатегориями — `subtree=false` отключает,
  `kind`, `active`, `q` по названию / sku / штрихкоду, `sort`). События outbox: `unit.*`, `product_category.*`, `attribute_def.*`, `product.*`.
- Интерфейс (маршрут `/catalog/:productId?`, группа «Catalog» в сайдбаре): дерево категорий слева (счётчики с подкатегориями, меню категории — подкатегория,
  характеристики, переименование и перенос, удаление), таблица товаров справа на `DataTable` + `FilterBar` (категория — из дерева, `?category=` в адресе;
  фильтры тип / активность, поиск), карточка товара на `EntityDrawer` (поля по типам, характеристики категории теми же `FieldInput`, пользовательские поля
  конструктора), форма создания с характеристиками выбранной категории. Редактор характеристик категории показывает унаследованные (только чтение, с
  пометкой «from …») и свои. Палитра команд находит товары и продукцию (`useCatalogHits`).
