# Обмен с 1С — план и решения (опрос 2026-11-02)

Опрос пользователя (2026-11-02):

- **Конфигурации:** 1С:Бухгалтерия 3.0 и 1С:Управление торговлей. Регламентированный учёт — в Бухгалтерии.
- **Формат:** EnterpriseData (универсальный формат обмена 1С, XML). Транспорт — файлы; позже HTTP-сервис (задача 1229).
- **Приоритет:** **1С — главный**. При конфликте данных при загрузке выигрывает значение из 1С; наши данные, не подтверждённые обменом, не считаются эталоном.
- **Режим:** выгрузка обмена — и ручная (кнопкой), и по расписанию.

Направления:

1. **Выгрузка в 1С** (наши справочники и документы → EnterpriseData): нужна прежде всего для Бухгалтерии — туда уходит то, что нельзя вести в ней самой (реализация, поступление, банк, касса). Задача 1227.
2. **Загрузка из 1С при переходе** (УНФ/УТ/Бухгалтерия → мы): справочники, остатки. Задача 1228.
3. **Двусторонний обмен по расписанию** — после того как работают 1 и 2. Задача 1229.

Пока так, модуль лицензий — `integrations`.

## Задача 1226 — таблица соответствий объектов с 1С (основа всех обменов)

1. **Таблица `integrations_1c_links`** (одна на все виды объектов): воркспейс, тип объекта (`entity_type`: organization, company, product, bank_account, document), наш id (`entity_id`, полиморфная привязка как у вложений — составного FK нет, допустимые типы в реестре `packages/shared`), GUID 1С (`ref_uuid`), имя объекта 1С на момент сопоставления (`ref_name`, чтобы показывать в интерфейсе без загрузки данных 1С), конфигурация-источник (`source`: `buh3`, `ut` — у пользователя обе, GUID из разных баз не совпадают), кем и когда сопоставлено (руками или автоматически). Уникальность: (воркспейс, source, entity_type, entity_id) и (воркспейс, source, entity_type, ref_uuid) — один наш объект ↔ один GUID и наоборот; уникальный индекс на ref_uuid по воркспейсу и типу (GUID глобально уникален, но тип страхует от коллизий между базами).
2. **Правила поиска (автосопоставление)** при загрузке из 1С, в порядке убывания точности:
   - организация и контрагент: **ИНН + КПП** (для юрлиц), ИНН без КПП (ИП/физлица), затем ОГРН; несколько кандидатов — не сопоставлять, отдать на ручное;
   - номенклатура: **артикул** (`products.sku` = артикул 1С), затем штрихкод, затем точное имя с одинаковым видом (товар/услуга) — только при единственном совпадении;
   - банковский счёт: БИК + номер счёта;
   - документ: номер + дата (номер без префиксов, дата ±1 день) — только при единственном совпадении.
3. **Сервис `packages/db/src/integrations-1c.ts`**: поиск по правилам, автосопоставление пакета (возвращает «сопоставлено / кандидат ы / не найдено»), запись и разрыв связи, ручное переопределение (ручная связь перезаписывает автоматическую; автопоиск ручные связи не трогает), чтение GUID по нашему объекту (для выгрузки: у какого объекта 1С-ссылка уже есть).
4. **API `/integrations/1c/links`**: список несопоставленных и сопоставленных по типу с фильтром, автопоиск (dry-run: для списка объектов из 1С показать кандидатов), ручное сопоставление (POST: наш id + GUID + имя), разрыв (DELETE). Права — admin+ (интеграция настраивает администратор). Раздел доступен при подключённом модуле `integrations`.
5. **Интерфейс:** «Настройки → Интеграции → 1С»: сводка (сколько сопоставлено/несопоставленных по типам), вкладка-таблица по типу объекта (наш объект, GUID 1С, имя 1С, источник, как сопоставлено), кнопка «Автопоиск» для загруженного из 1С списка, ручное связывание выбором из справочника, разрыв связи. Тексты через `t()`.
6. **Готово, когда:** таблица и миграция; автосопоставление по ИНН/КПП, артикулу и номеру счёта покрыто тестами; ручное сопоставление работает в интерфейсе; RLS-тест новой таблицы; раздел в `docs/architecture/` (создаётся задачей 1227 вместе с форматом EnterpriseData, здесь — заметка в плане).

Зависимости: не зависит ни от чего. От неё зависят 1227 (выгрузка: писать GUID в пакет), 1228 (загрузка: сопоставление справочников), 1229 (обмен: обе стороны).

## Задача 1227 — выгрузка в 1С:Бухгалтерию 3.0 (EnterpriseData)

Справочники (организации, контрагенты, договоры, номенклатура, склады, счета) и документы (реализация, поступление, банк, касса, авансовые отчёты) за период; GUID из `integrations_1c_links` (новые объекты выгружаются с новым GUID, который 1С вернёт при загрузке — или генерируем сами и храним). Файл и по расписанию.

## Задача 1228 — загрузка из 1С при переходе (УНФ, УТ, Бухгалтерия)

Справочники из EnterpriseData/XML, остатки товаров, денег и взаиморасчётов на дату через ввод начальных остатков; предпросмотр и отчёт о несопоставленном. Сопоставление — задачей 1226.

## Задача 1229 — двусторонний обмен по расписанию

HTTP-сервис 1С, регистрация изменений, квитирование пакетов, приоритет 1С при конфликте, журнал обменов.

## Задача 1230 — сверка с 1С

Отчёт расхождений по документам, суммам, оплатам и остаткам между нашими данными и выгрузкой 1С за период.
