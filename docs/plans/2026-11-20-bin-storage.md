# Адресное хранение (ячейки склада) — задача TaskFlow 1460

Источник идеи — разбор RBS ERP (сессия TaskFlow 67). ГТД и страна происхождения — отдельной задачей, не здесь.
Основа — `docs/architecture/stock.md` (движения, остатки, партии FEFO), чек-лист — `docs/lessons.md`.

## Решения (согласованы с пользователем 2026-11-20)
- Справочник ячеек — **плоский список** у склада: код («A-01-03», уникален в складе), необязательная зона (текст), порядок обхода (число), архив.
- Ячейки включаются **флагом склада** `warehouses.use_bins`. Склад без флага работает ровно как сейчас (bin_id всегда null).
  Служебные склады «в пути» и склады контрагентов ячеек не имеют.
- **Ячейка указывается в строке документа**, ордерной схемы и заданий на размещение нет (отдельная задача позже).
- **Расход — автоподбор с ручной правкой:** если в строке ячейка не указана, система раскладывает расход по ячейкам с остатком
  в порядке обхода (`sort_order`, затем код), «без ячейки» — последней. Указанная ячейка списывается только из неё.
- Себестоимость остаётся **средней по (склад, товар)** — ячейка влияет только на место хранения, как партия на порядок списания.

## Модель данных (packages/db)
- `storage_bins (id, workspace_id, warehouse_id, code, zone, sort_order int default 0, archived_at, created_at, updated_at)`;
  уникальность `(workspace_id, warehouse_id, lower(code))` среди неархивных; составные FK `(workspace_id, warehouse_id)`;
  `app_secure_tenant_table`.
- `warehouses.use_bins boolean not null default false`, `warehouses.receipt_bin_id uuid null` — ячейка приёмки по умолчанию
  (составной FK на storage_bins, `ON DELETE SET NULL`).
- `document_lines.bin_id` (откуда — для расхода; куда — для прихода) и `document_lines.target_bin_id` (куда — у перемещений,
  где у строки есть и расход, и приход). Составные FK на storage_bins, `ON DELETE SET NULL`.
- `stock_moves.bin_id uuid null` + составной FK + индекс `(workspace_id, warehouse_id, product_id, bin_id)`.
- Остаток ячейки — **производное от движений** (сумма `qty` по `warehouse, product, batch, bin`), отдельной таблицы нет.
- Миграции `drizzle/0132_*.sql` (и дальше по номеру) — **вручную** вместе с записью в `drizzle/meta/_journal.json`
  (снимки в meta после 0088 не ведутся, см. CLAUDE.md).

## Проведение (ядро — `packages/db/src/bins.ts`, `assignBins`)
Вызывается из `applyStockMoves` **после `assignBatches` и под теми же блокировками остатков** (lockBalances уже взят), до записи движений.
Ячейки строк `assignBins` читает сам из `document_lines` по `lineId` — поэтому все вызывающие (`documents.applyDocumentMoves`,
`internal-ops` перемещения «в пути», `production` выпуск и разборка, `work-orders`) получают ячейки без изменения сигнатуры.
- Склад движения без `use_bins` → `binId = null`, ничего не делаем.
- **Приход:** ячейка = `target_bin_id` строки, если у той же строки в этом наборе есть расход (перемещение), иначе `bin_id` строки;
  нет — `warehouses.receipt_bin_id`; нет — null («без ячейки»). Ячейка должна принадлежать складу движения и быть не в архиве — иначе 422 `invalid_bin`.
- **Расход:** строка с `bin_id` → вся порция из этой ячейки (с учётом партии порции, если она есть); не хватает и минус запрещён → 422
  `insufficient_bin_stock` (`details`: товар, ячейка, доступно, нужно). Без `bin_id` → раскладка по ячейкам с положительным остатком
  (для партионного товара — внутри партии порции) в порядке `sort_order, code`, «без ячейки» — последней; остаток, который не
  разложился (минус разрешён), уходит в «без ячейки». Каждая порция — отдельный MoveRequest со своим `binId` (как порции FEFO).
- Цена расхода не меняется (средняя склада); средневзвешенная цена строки в `applyStockMoves` уже считается по порциям.
- Перемещение «в пути»: отправка — расход из `bin_id`, приход на склад «в пути» без ячейки; приёмка (фаза 2) — приход в `target_bin_id`
  склада-получателя (или ячейку приёмки).
- Отмена проведения ничего нового не требует: движения удаляются, остаток ячеек производный.

## Перемещение между ячейками
Новый тип документа `bin_transfer` («Перемещение между ячейками», группа stock, префикс «ПЯ»): один склад (шапка), в строке
`bin_id` → `target_bin_id`, обе обязательны и различны, склад с `use_bins`. Движения: расход из `bin_id` и приход в `target_bin_id`
по цене расхода (`costFromLine`) — средняя склада не меняется. В `stockPlan` роль `transfer` для этого типа берёт склад-получатель = склад шапки.
Печатной формы нет. Права — как у `stock_transfer`.

## API (apps/api)
- `GET/POST /warehouses/:id/bins`, `PATCH/DELETE /storage-bins/:id` (DELETE — архив; запрещён, если в ячейке остаток: 422 `bin_not_empty`);
  `POST /warehouses/:id/bins/import` — список кодов текстом (по строке, «код;зона;порядок»). Запись — admin.
- `PATCH /warehouses/:id` принимает `useBins`, `receiptBinId`. Выключить `useBins` при остатке в ячейках — 422 `bins_in_use`.
- Строки документов принимают и отдают `binId`, `targetBinId` (+ `binCode`, `targetBinCode` для отображения). `undefined` — не трогать, `null` — очистить.
- `GET /stock/bin-balances?warehouseId&productId&binId&q&nonZero` — остаток по (ячейка, товар, партия), «без ячейки» отдельной строкой.
- Коды ошибок (`invalid_bin`, `insufficient_bin_stock`, `bin_not_empty`, `bins_in_use`) — в словари ошибок фронтенда en/ru.

## Интерфейс (apps/web)
- Карточка склада: переключатель «Адресное хранение», ячейка приёмки, таблица ячеек (код, зона, порядок, остаток позиций), добавление, импорт списком, архив.
- Строки складских документов (поступление, реализация, возвраты, списание, оприходование, перемещение, выпуск, `bin_transfer`):
  колонка «Ячейка» (и «В ячейку» у перемещений) — только если склад документа с `use_bins`; выбор из ячеек склада, пусто = автоподбор / ячейка приёмки.
- Отчёт «Остатки по ячейкам» (раздел меню «Склад»): фильтры склад/ячейка/товар, группировка по ячейке. В карточке товара (Inventory) — остаток по ячейкам.
- Кнопка «Движения» документа показывает ячейку движения.
- Тексты — `t()`, en + ru; статья пользователя `docs/user/` (склад) + `bun run docs:verify`.

## Инкременты (каждый — свой коммит и тесты)
1. **Схема и справочник:** миграция, Drizzle, сервис ячеек, API справочника и флага склада, поля строк документов (сохранение/чтение), тест RLS-покрытия.
2. **Проведение:** `assignBins` в `applyStockMoves`, `bin_transfer`, `GET /stock/bin-balances`, ячейка в `stock-preview`. Тесты:
   приход в ячейку и в ячейку приёмки; автоподбор по порядку обхода; явная ячейка и нехватка в ней; партионный товар (FEFO × ячейки);
   перемещение между складами (обычное и «в пути» с частичной приёмкой); выпуск продукции и материалы; отмена проведения;
   склад без флага не меняется (существующие тесты склада зелёные); **конкурентность**: два параллельных расхода из одной ячейки 7+7 при остатке 10 → один проходит.
3. **Интерфейс и документация:** карточка склада, колонки в строках, отчёт, i18n, статья, `docs/architecture/stock.md` (раздел «Адресное хранение»).
