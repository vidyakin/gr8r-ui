# Лендинг FutureERP

## Решения (интервью с пользователем, 2026-10-29)
- **Где живёт:** отдельный пакет `apps/landing` (Vite + React, как `apps/web`), отдаётся с того же домена, что и приложение.
- **Язык:** русский. Тексты через локальный `t()` и словарь `apps/landing/src/i18n/ru.ts`; английский словарь добавится позже
  и обязан повторять форму русского (тип `Dict`). Отступление от правила приложения «en — источник ключей»: у лендинга
  первая и пока единственная версия русская. Данные внутри «записей» (задачи, клиенты, суммы) — демо-данные, по-русски без перевода.
- **Модули-«записи»:** задачи и проекты, CRM (сделки и окупаемость), документы и КП, автоматизации.
  Порядок на странице — предположение, подтвердить у пользователя: задачи → CRM → документы → автоматизации.
  В первой версии — три записи (задачи, CRM, документы), автоматизации — место под запись.
- **Тон:** сухой, деловой. Только факты из `docs/architecture/*.md`: без придуманных цифр, логотипов клиентов и отзывов.
- **Форма заявки:** есть. Шлёт `POST /api/hooks/leads/<токен>` (публичный вебхук форм лидов, `docs/architecture/leads.md`)
  с полями `name`, `company`, `phone`, `email`, `comment` и `utm_source=landing`. Токен — формы лидов арендатора оператора, задаётся при сборке
  `VITE_LEAD_FORM_TOKEN`. Без токена форма показывает почту для связи вместо отправки. `OPERATOR_LEAD_HOOK_URL` воркера — другое, не путать.

## «Записи» модулей
Не видео: React-сцены из разметки и CSS-классов настоящего интерфейса (`.side`, `.board`, `.bcol`, `.kcard`, `.doc-head`, `.dtbl`…),
стили берутся из `apps/web/src/styles` напрямую. Компоненты приложения не импортируются (тянут i18n, Radix, контексты).
- Сценарий — список шагов `{ at, do }` (`src/demo/player.ts`): курсор едет к элементу `data-demo="…"`, кликает, печатает, состояние сцены меняется.
- Кадр рисуется в фиксированной ширине и масштабируется под контейнер; координаты курсора считаются в системе кадра (делим на масштаб).
- Играет только в зоне видимости и при видимой вкладке; кнопка «пауза» у каждой записи (WCAG 2.2.2); кадр `inert` + `aria-hidden`, рядом текстовая подпись.
- `prefers-reduced-motion`: сразу конечное состояние, без курсора и без автопроигрывания.

## Отдача с одного домена (открытый вопрос — решить до деплоя)
Приложение работает на HashRouter (`/#/tasks`), поэтому перенос на подпуть не трогает маршруты:
1. **Вариант А (рекомендуется):** лендинг на `/`, приложение на `/app/` (Vite `base: '/app/'`, nginx `location /app/`). Ссылки «Войти» → `/app/#/signin`.
   Нужно проверить абсолютные пути в приложении (`/api` остаётся, ассеты уходят под `/app/assets`).
2. **Вариант Б:** лендинг только для `location = /` без cookie сессии, иначе отдаётся приложение. Без переноса, но логика на nginx.
Пока лендинг живёт отдельно (`bun run --cwd apps/landing dev`), nginx и Dockerfile приложения не меняются,
кроме строки `COPY apps/landing/package.json` в Dockerfile — без неё `bun install --frozen-lockfile` падает.

## Правка 1 (2026-10-29): вкладки вместо ленты секций
- Убраны нумерация 01–04 и индекс в первом экране, таймкод и «REC» у записей.
- Модули — крупные вкладки (tablist, стрелки переключают). Вкладка — «страница» модуля: слева заголовок, одна фраза и список возможностей (название + пояснение, `modules.<id>.features`), справа запись. На узком экране запись над списком.
- Кадр рисуется в ширину контейнера, текст 1:1; узкий режим (без боковой панели) — уже 960px, масштабирование только уже 560px (телефон ≈0,6).
- Текст страницы крупнее: абзацы 17px, пункты 16–17px.

## Правка 2 (2026-10-29): вкладки «Услуги» и «Производство»
- Порядок вкладок: задачи → CRM → документы → услуги → производство → автоматизации. Из «Что ещё есть» эти два пункта убраны.
- «Услуги» (`ServicesScene.tsx`): день записи к мастерам (`.appt-grid` из appointments.css) — запись клиента на свободный слот через диалог, затем «Пришёл» в карточке записи.
- «Производство» (`ProductionScene.tsx`): рабочее место «Выпуск продукции» — отметка этапов заказа, «Выпустить (6)», уведомление о документе выпуска, заказ становится «Выполнен».
- Диалог и уведомление в кадре — `.d-modal`, `.d-toast` (у приложения они fixed к окну).

## Правка 3 (2026-10-29): цепочка в первом экране
- Первый экран в две колонки: слева заголовок и кнопки, справа `HeroFlow.tsx` — один заказ проходит Звонок → Заявка → Сделка → Производство → Продажа → Деньги → Аналитика.
- Шаги загораются по одному (1,1 с), линия между значками заливается, пройденные получают галочку; после полной цепочки — пауза 2,6 с и сначала.
- Играет только в зоне видимости и при видимой вкладке; при reduced motion все шаги сразу пройдены. Тексты — `hero.flow.*`, данные те же, что в записях (кухня Петрова, 318 000 ₽, ROMI 243 → 508 %).
