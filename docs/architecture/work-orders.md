# Заказ-наряд: работы, материалы и состояния

Реализовано на этапе 1 (сессия «УНФ: Услуги»). Код: сервис — `packages/db/src/work-orders.ts`, схема — `packages/db/src/schema/services.ts`
(состояния, материалы, назначения) и `schema/documents.ts` (виды заказ-нарядов), метаданные и правила категорий — `packages/shared/src/documents.ts`,
API — `apps/api/src/routes/work-orders.ts`, клиент — `apps/web/src/app/docs/work-orders.tsx`.

- **Заказ-наряд сам является продажей** (`work_order`, группа `sales`, префикс `ЗН`, контрагент — покупатель). При входе в состояние категории
  `done` документ проводится целиком: выручка и долг клиента по строкам, расход товаров со склада, списание материалов — движениями самого заказ-наряда
  (отдельный `write_off` не создаётся). Частичной отгрузки нет. Выход из `done` в рабочую категорию снимает проведение (товар возвращается, выручка уходит).
  Проводить и отменять проведение вручную нельзя (`422 work_order_state_only`) — это делает состояние. Счёт на основании заказ-наряда выставляют
  до выполнения (предоплата), поэтому заказ-наряд — единственный тип, счёт по которому можно провести, не проводя основание.
- **Состояния задаёт воркспейс.** `work_order_kinds (workspace_id, name, sort_order, is_default)` — виды заказ-нарядов (вид по умолчанию один на воркспейс),
  `document_states (workspace_id, document_type, kind_id, key, label, color, category, sort_order)` — состояния: у каждого вида свой упорядоченный набор.
  Логика привязана к **категории** состояния (`new | scheduled | in_progress | done | delivered | cancelled`), а не к ключу: воркспейс переименовывает
  состояния и добавляет свои, но «выполнен» всегда узнаётся по категории. Вид по умолчанию с состояниями (по одному на категорию) создаёт код при
  создании воркспейса (`ensureWorkOrderKind`), для существующих воркспейсов — миграцией. Состояние, на котором есть заказ-наряды, удалить нельзя (409
  `state_in_use`), последнее состояние категории — тоже (409 `last_state_in_category`).
- **Динамические состояния.** У заказ-наряда состояний нет в метаданных типа, поэтому их отдаёт провайдер типа (`STATE_PROVIDERS` в
  `packages/db/src/document-hooks.ts`), а побочные действия (проведение и его отмена) делает хук смены состояния (`STATE_HOOKS`). Всё в одной транзакции
  запроса: нехватка товара даёт `422 insufficient_stock`, и состояние не меняется. Из завершённых категорий (`delivered`, `cancelled`) выходят только
  admin и выше. Отмена (категория `cancelled`) требует причину (`cancelReason` в теле смены состояния) и снимает проведение выполненного заказа.
- **Материалы** — `work_order_materials (workspace_id, document_id, product_id, qty, unit_code, warehouse_id)`: израсходованы на работу, только товары
  (`products.kind = 'goods'`), склад списания — свой или склад документа. Списываются при выполнении (движения заказ-наряда, `document_line_id` пуст).
- **Исполнители** — `work_order_assignments (workspace_id, document_id, task_id, line_id, work_center_id, planned_hours)`: исполнитель это задача модуля
  `services` в системном проекте `Services` (время пишется на неё, `time_logs` не меняется). Чужой участник отклоняется: составной внешний ключ
  `(workspace_id, assignee_id)` и проверка в сервисе (`422 invalid_reference`).
- **Вид номенклатуры `work`** (`products.kind`) — работы заказ-наряда: к ним относятся материалы и исполнители; услуги остаются `service`.
  Список видов расширяют вместе с CHECK в БД (`products_kind_chk`).
- **Печатные формы** заказ-наряда: бланк приёма заказа (`work_order`), акт, УПД, ТОРГ-12 и счёт — те же шаблоны, что и у актов и реализаций.
- **API:** `/work-orders` (журнал с состояниями, карточка с материалами и назначениями, `POST /:id/materials`, `POST /:id/assignments`),
  `/work-order-assignments/:taskId` (правка и удаление), `/work-order-kinds` и `/document-states` (справочники, admin и выше).
- **Интерфейс:** журнал **Work orders** (`/work-orders`) с фильтром по состояниям; в карточке документа — блок состояния и вида, таблицы материалов
  и исполнителей; настройка видов и состояний — Settings → Work order kinds.

## Себестоимость работ (задача 1096)

Код: расчёт — `packages/shared/src/work-orders.ts` (`computeWorkOrderCost`, тесты `packages/shared/test/work-orders.test.ts`), сбор данных — `packages/db/src/work-order-cost.ts`,
API — `GET /work-orders/:id/cost`, экран — `apps/web/src/app/docs/work-order-cost.tsx`, отчёт — `apps/web/src/app/production/reports/WorkOrderCostTab.tsx`. Справка УНФ 7.1.

- **Живая себестоимость.** В документ ничего не пишется: сервер собирает данные и считает при каждом запросе. У строк «Услуга» затрат нет — их выручка целиком в марже.
- **Труд** = часы × `work_centers.hourly_rate`. Участок — `work_order_assignments.work_center_id`, а если пуст — участок нормы работы строки (`operations.work_center_id`). Личных ставок нет.
  Без участка труд не оценивается (0), часы попадают в предупреждение `no_work_center`, в карточке показывается плашка. Факт часов — все `time_logs` задач-назначений, без ограничения по датам.
- **План:** плановые часы × ставка + материалы заказ-наряда и товары его строк × текущая средняя себестоимость (склад строки или документа, иначе средняя по складам) + прочие затраты.
  **Факт:** часы × ставка + материалы и товары по себестоимости списания (`stock_moves.cost` проведённого заказ-наряда: строка товара — товары, без строки — материалы) + прочие + косвенные.
  Пока заказ-наряд не выполнен, факт материалов и товаров — оценка по средней (`estimated`, пометка «оценка»).
- **Выручка** = `documents.amount_net` (без НДС: работы, услуги, товары). **Маржа** = выручка − себестоимость, процент — от выручки (`null` при нулевой выручке). Плановая маржа — до выполнения.
- **Прочие затраты:** у `other_cost_lines` есть необязательный `work_order_id` (составной FK на `documents`, миграция 0034). Такие строки — прямые затраты заказ-наряда (проведённые документы),
  в пул косвенных закрытия месяца (`period_costs`) не попадают. Ввод на основании: `POST /documents/:id/based-on {type:'other_costs'}` создаёт черновик с `based_on_id` = заказ-наряд
  (строки пользователь добавляет), в форме «Прочие затраты» есть поле «Заказ-наряд» (шапка действует на все строки без своего).
- **Косвенные** — из итогов закрытия месяца (`production_cost_closings.totals.byWorkOrder`, статус `done`), см. `month-closing.md`.
- **Права:** `GET /work-orders/:id/cost` — admin и owner (иначе 403 `cost_access_required`). В журнале `/work-orders` поля `cost`, `margin`, `marginPct`, `costBasis` у остальных `null`;
  `costBasis` — `fact` у выполненного, иначе `plan`. Вкладка «Себестоимость» и колонки журнала скрыты для member и guest.
- **Отчёт** `GET /production/reports/work-order-cost?from&to` — см. `production-reports.md`.
