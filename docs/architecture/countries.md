# Страновые пакеты

Страна организации определяет валюту по умолчанию, допустимые ставки НДС, налоговые режимы, реквизиты и доступные печатные формы. Страна контрагента определяет его собственные реквизиты. Организация и контрагент могут быть из разных стран.

| Код | Валюта | НДС | Ставка по умолчанию | Налоговые режимы |
| --- | --- | --- | --- | --- |
| RU | RUB (₽) | Без НДС, 0%, 5%, 7%, 10%, 20%, 22% | 20% | `osn`, `usn` |
| KZ | KZT (₸) | Без НДС, 0%, 16% | 16% | `our`, `simplified` |
| AE | AED | Exempt, 0%, 5% | 5% | `standard`, `exempt` |

## Реестр

`getCountryPack` из `@erp/shared` возвращает пакет по коду. Для пустого или неизвестного кода используется RU. Входные схемы API принимают только зарегистрированные коды.

Каждый пакет в `packages/shared/src/countries/<код>/` задаёт валюту и символ, ставки и подписи НДС, сумму прописью, поля реквизитов с масками и проверками, режимы налогообложения и идентификаторы печатных форм. RU переиспользует функции из `ru.ts`, сохраняет существующий список `VAT_RATES` для совместимости и публикует все существующие формы. Пакеты RU и KZ указывают формат банковской выписки. У AE в базовом пакете реестр форм пуст.

Чтобы добавить страну, добавьте код в `COUNTRY_CODES`, пакет в реестр, переводы для `en`, `ru`, `es` и миграцию для списка стран и налоговых режимов. Общие схемы принимают объединение ставок зарегистрированных пакетов.

## Хранение и проверка

Миграция `0146_country_pack.sql` задаёт `country = 'RU'` и `requisites = {}` для существующих организаций и контрагентов. Российские формы и интеграции по-прежнему читают колонки `inn`, `kpp` и `ogrn`. В API поле `requisites` при передаче заменяет JSON-объект целиком. При смене страны форма сохраняет реквизиты выбранной страны. Российские колонки сохраняются.

| Страна | Ключи в `requisites` | Проверки |
| --- | --- | --- |
| KZ | `binIin`, `iik`, `bik`, `kbe`, `knp` | БИН/ИИН — 12 цифр с двухпроходной проверкой mod 11. ИИК — IBAN длиной 20 символов с префиксом `KZ` и проверкой mod 97. БИК — SWIFT/BIC, КБе — 2 цифры, КНП — 3 цифры. |
| AE | `trn`, `iban`, `bic` | TRN — 15 цифр. IBAN — префикс `AE` и 21 цифра с проверкой mod 97. BIC — SWIFT/BIC. |

Алгоритмы сверены с правилами формирования [ИИН](https://old.adilet.zan.kz/rus/docs/V2300032942), [БИН](https://adilet.zan.kz/rus/docs/V2300032918) и [реестром IBAN Swift](https://www.swift.com/standards/data-standards/iban-international-bank-account-number).

База проверяет формат НДС в пяти колонках. Допустимые значения имеют вид `none` или `^[0-9]+(\.[0-9]+)?$`. Приложение проверяет конкретную ставку по пакету организации документа. Каталог и сметы используют пакет основной организации воркспейса. Если ставка товара недоступна для организации документа, для новой строки подставляется ставка организации. Исторические ставки видны в сохранённых документах.

Новый документ берёт валюту организации, если в запросе создания торгового документа не передана `currency`. При создании торгового документа на основании валюта наследуется. Суммы строк считаются десятичной арифметикой с округлением до двух знаков. `computeTotals` суммирует уже округлённые строки и группирует их по ставкам.


## Формы KZ

`printFormsFor` выбирает формы по типу документа и стране его организации. `formAllowedFor` использует тот же список в API предпросмотра, PDF и отправки по почте. Общий `PRINT_FORMS` содержит 24 российских и 7 казахстанских идентификаторов.

| Документ | Формы KZ |
| --- | --- |
| КП, заказ покупателя, счёт | Счёт на оплату (`kz_invoice`) |
| Реализация | Накладная на отпуск запасов на сторону (`kz_z2`), счёт-фактура (`kz_tax_invoice`) |
| Акт | Акт выполненных работ (`kz_r1`), счёт-фактура (`kz_tax_invoice`) |
| Заказ-наряд | Счёт на оплату, накладная З-2, акт Р-1, счёт-фактура |
| Отчёт переработки | Акт Р-1 |
| Приход / расход по кассе | КО-1 (`kz_pko`) / КО-2 (`kz_rko`) |
| Списание со счёта | Платёжное поручение (`kz_payment_order`) |

Формы выводят реквизиты сторон, сумму в тенге и тиынах прописью и ставки НДС из строк документа. Поручение использует указанный в платеже счёт организации. Печатные шаблоны опираются на структуру первичных документов и платёжного поручения. Счёт-фактура формируется из данных реализации или акта для печати. Обмен с ИС ЭСФ и СНТ за пределами пакета. [Формы первичных документов РК](https://old.adilet.zan.kz/rus/docs/V1200008265), [Форма счёта-фактуры](https://old.adilet.zan.kz/rus/docs/V2500037241), [Платёжные поручения](https://adilet.zan.kz/rus/docs/V1600013275)

## Выписки KZ

`parseBankStatement` использует общий разбор секций `1CClientBankExchange` и модуль `countries/kz/bank-statement.ts` для локальных полей. Формат определяется по ИИК, валюте, полям идентификаторов и кодов или заголовку Halyk, Kaspi, Jusan / Alatau City Bank либо BCC. Операции в KZT попадают в предпросмотр с ИИК, SWIFT/БИК, БИН/ИИН, КБе и КНП. У операций в иной валюте выводится предупреждение.

Импорт сопоставляет счёт организации и строит ключ дубля по полному ИИК, включая буквы. Для контрагентов ищет БИН/ИИН в `requisites.binIin`, в старых ключах `bin` / `iin` и в колонке `inn`. При нескольких совпадениях помогает ИИК из `requisites.iik` или отдельного банковского счёта. ИИК также используется для поиска операций без совпадения по идентификатору. Для записи денег банковский счёт организации должен быть заведён во вкладке «Счета».
