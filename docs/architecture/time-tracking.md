# Учёт времени и нормы работ

Реализовано на этапе 2 (сессия «УНФ: Услуги»). Код: сервис — `packages/db/src/services.ts`, схема — `packages/db/src/schema/services.ts`
(строки работ заказ-наряда) и `schema/work.ts` (заказчик задачи), API — `apps/api/src/routes/services.ts` и `apps/api/src/routes/work-orders.ts`,
клиент — `apps/web/src/app/docs/timesheet.tsx`, `apps/web/src/app/docs/work-orders.tsx` и `apps/web/src/app/catalog/product-ui.tsx`.

- **Время пишется на задачи модуля `services`** — `time_logs` не меняется: у назначения заказ-наряда уже есть задача.
  Недельный табель сотрудника — **отчёт** по этим записям (`GET /services/timesheet`), отдельного документа-табеля нет.
  Строки табеля: дата, сотрудник, заказчик (контрагент заказ-наряда или заказчик задачи), вид работ (товар строки заказ-наряда), задача, часы.
  Admin и owner видят табель любого сотрудника, участник — только свой.
- **Заказчик у задачи** — `tasks.company_id` (необязательный, составной внешний ключ на `companies`): так пишут время по заказчику
  без заказ-наряда (консультация по договору). В БД — CHECK: заказчик бывает только у задач модуля `services`.
  Назначение заказ-наряда получает заказчика из контрагента заказ-наряда автоматически.
  В вебе поле **Customer** есть только у задач модуля `services` — в панели задачи (`task-drawer`) это выбор компании
  из справочника с поиском и очисткой (`CounterpartyPicker`, тот же выбор, что в документах), в списках и таблицах
  задач модуля `services` — колонка **Customer**. Локальное поле `tasks.company` ↔ API `companyId`
  (`apps/web/src/app/data/specs.ts`); ошибки `company_not_allowed` и `invalid_reference` показываются понятным текстом
  (`apps/web/src/app/data/api.ts`).
- **Норма времени и участок** живут в таблице `operations` (1:1 к товару каталога) — как у операций производства; вид товара задаёт смысл записи:
  `operation` — производство, `work` — услуги. Норма применяется к новому назначению заказ-наряда: плановые часы = количество строки × норма,
  участок — по умолчанию из нормы (если не указан). Норма задаётся у работы в карточке каталога (`PUT /services/work-norms/:productId`).
- **Выставление клиенту выбирается в строке работы заказ-наряда**: `work_order_lines (workspace_id, line_id, document_id, billing)`,
  `billing = norm | hours`. `norm` — количество × цена (как раньше), `hours` — фактические часы задач-назначений строки × цена.
  Перед проведением заказ-наряда (вход в состояние категории `done`) количество таких строк пересчитывается по фактическим часам
  в той же транзакции; записанных часов нет — `422 no_hours_billed`, заказ-наряд не проводится.
- **API:** `/services/work-norms` (нормы работ), `/services/timesheet` (табель), `GET /work-orders/:id/time` (план и факт по назначениям,
  сводка по исполнителям и строкам работ), `POST /work-orders/:id/billing` (способ выставления строк работ).
- **Интерфейс:** в карточке заказ-наряда — блок **Works** (способ выставления строки, фактические часы) и план/факт по исполнителям;
  в карточке работы в каталоге — норма времени и участок по умолчанию; экран **Timesheet** (`/services/timesheet`) — недельный табель;
  на странице участника — фильтр часов по модулю.
