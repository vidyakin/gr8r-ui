# Внутренние складские документы

Реализовано на этапе 0а (сессия «УНФ: Производство»). Код: метаданные типов и чистая функция `stockPlan` — `packages/shared/src/documents.ts`,
сервисы — `packages/db/src/documents.ts` и `packages/db/src/stock.ts`, справочник статей — `cost_items` (миграция `0007_stock_docs.sql`),
API — `apps/api/src/routes/documents.ts`, клиент — `apps/web/src/app/docs/*`.

- **Внутренний документ — документ без контрагента.** У типа в `DOCUMENT_META` поле `party: null`; контрагент не нужен и не хранится,
  НДС у строк — `none`, продажной цены нет. Направление движения задаёт **роль строки** (`document_lines.stock_role`: `in` | `out`), а не тип документа:
  сервер проставляет её сам (`lineRole`), клиент её не присылает. План движений — чистая функция `stockPlan(doc, lines) → PlannedMove[]`
  (тесты — `packages/shared/test/documents.test.ts`): у продаж и закупок направление задаёт тип, у внутренних — роль строки и шапки.
- **Типы:** `stock_transfer` (ПМ, перемещение между складами: расход со склада шапки и приход на `target_warehouse_id` по каждой строке),
  `write_off` (СП, списание: расход, статья затрат обязательна), `stock_posting` (ОП, оприходование: приход, статья доходов обязательна),
  `opening_stock` (НОТ, начальные остатки товаров: приход по себестоимости строки без статьи, не входит в факт инвестпроектов; миграция 0073),
  `inventory_count` (ИНВ, инвентаризация: остатки не двигает, результат сверки оформляется списанием и оприходованием на основании).
  Вид операции — `documents.operation` (`transfer`; `in_transit`, `to_operation`, `from_operation` — этап 0б). Перемещение требует склад-получатель,
  отличный от склада-источника (иначе 422 `target_warehouse_required`; в БД — CHECK `documents_transfer_chk`).
- **Статьи затрат и доходов** — `cost_items (workspace_id, name, kind: expense|income, system_key, archived_at)`, арендаторская таблица
  (`app_secure_tenant_table`), имя уникально среди неархивных. `documents.cost_item_id` — составной FK. Вид статьи должен совпадать с типом документа
  (списание — расходная, оприходование — доходная): иначе 422 `cost_item_kind_mismatch`; статья обязательна при проведении — `cost_item_required`.
  Системные статьи («Брак», «Порча», «Недостача», «Отходы», «Передача в эксплуатацию», «Излишки») заводит код при создании воркспейса (`ensureCostItems`).
  Справочник — Settings → Cost items (меняет admin и выше).
- **Цена оприходования** — себестоимость единицы прихода: по умолчанию текущая средняя (склад, товар), иначе цена последнего проведённого поступления,
  иначе закупочная цена товара (`GET /stock/default-cost?warehouseId=&productId=`; `defaultPostingCost`). Задать цену вправе admin и owner;
  member'у сервер подставляет среднюю, а присланную цену игнорирует.
- **Состояние документа отдельно от проведения** — `documents.state` (NULL у типов без состояний), допустимые значения и переходы — в метаданных типа
  (`DOCUMENT_META[type].states`, чистые правила — `stateTransitions` / `canChangeState` в `shared`). Действие `POST /documents/:id/state { state }`
  пишет событие `document.updated` с `changes.state {from, to}` — автоматизация «поле изменилось» срабатывает без нового триггера
  (`state` добавлен в `BUILTIN_FIELDS.document`). Хук типа на смену состояния живёт в слое БД (`STATE_HOOKS` в `packages/db/src/document-hooks.ts`):
  им пользуются перемещение «в пути» (этап 0б), заказ на производство (этап 2) и заказ-наряд (план услуг). Первый тип с состояниями — перемещение «в пути»
  (`shipped` → `received`, обратный переход отменяет приёмку).
- **Инвентаризация (ИНВ).** Остатки не двигают: у строки документа `qty` — **фактическое** количество, `document_lines.book_qty` — **учётное**
  (по остаткам склада на момент заполнения), разница — недостача или излишек. Строки заполняются кнопкой «Fill by stock»
  (`POST /documents/:id/fill-count-sheet`, опись — `GET /stock/count-sheet?warehouseId=`). По проведённой инвентаризации создаются
  **списание** (недостача, статья «Недостача») и **оприходование** (излишек, статья «Излишки», цена — по умолчанию) — строго по разнице:
  сколько уже оформлено, столько ещё можно (своя проверка в `packages/db/src/inventory.ts`). Снять инвентаризацию с проведения нельзя,
  если по ней есть проведённые документы (общее правило `has_posted_children`).
- **Перемещение «в пути»** (`stock_transfer` с `operation = 'in_transit'`) — одно состояние документа вместо двух документов:
  при проведении товар уходит со склада отправителя и приходит на **служебный склад вида `transit`** (один на воркспейс, создаётся лениво),
  документ получает состояние `shipped`. Переход в `received` (хук `STATE_HOOKS`) — расход с `transit` и приход получателю по **принятому количеству**
  (`document_lines.received_qty`, не больше отправленного); непринятое остаётся на `transit`. Возврат `received → shipped` отменяет вторую партию
  движений. Движения помечены **фазой** (`stock_moves.phase`: 1 — отправка, 2 — приёмка), поэтому отмена идёт по фазам.
- **Передача в эксплуатацию** (`operation = 'to_operation'`) — расход со склада (себестоимость — на статью затрат, например «Передача в эксплуатацию»)
  и количественный учёт «у кого»: `in_use_balances (workspace_id, product_id, member_id?, work_center_id?, qty)` и движения `in_use_moves`
  (получатель ровно один — сотрудник или участок; CHECK). Возврат из эксплуатации (`from_operation`) уменьшает остаток у получателя
  (без прихода на склад). Остаток пересчитывается по движениям, поэтому отмена одного документа не ломает остаток; если после отмены остаток
  ушёл бы в минус — 422 `in_use_conflict`. Экран «In use» (`/stock/in-use`, `GET /stock/in-use`).
- **Стоимость видят только admin и owner** (`canSeeCost` / `maskCost` в `packages/db/src/cost.ts`): `stock_moves.cost`, средняя и стоимость остатка
  (`/stock/balances`), `/stock/avg-costs`, цена оприходования в строке документа и «стоимость по себестоимости» в журнале. Member и guest видят количество,
  но не стоимость (в ответах — `null`). Количество участник видит всегда.
- **Журнал** — `group=stock` (`/stock-docs`): вкладки по типам, колонка «Cost» — сумма `qty × cost` по движениям документа (у перемещения берётся расходная
  сторона, иначе приход и расход сократились бы). Внутренние документы не входят в суммы продаж и закупок.
- **Печатные формы внутренних документов:** **ИНВ-3** (инвентаризационная опись: учётное, фактическое и разница по каждой позиции),
  **ТОРГ-16** (акт о списании: количество и себестоимость по средней, статья затрат), **ТОРГ-13** (накладная на внутреннее перемещение:
  склад-отправитель, склад-получатель, получатель в эксплуатацию). Себестоимость строк берётся из движений документа (`documentLineCosts`),
  она видна только admin и owner.
- **Обобщение логики заказов:** проверки по именам типов заменены чтением метаданных — `isOrder` (строки заказа — источник `origin_line_id`),
  `reservedUntil` (типы-исполнители, снимающие резерв), `isReturn`, `fulfils`, `reserves`. Поведение продаж и закупок не изменилось.
