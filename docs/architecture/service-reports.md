# Контроль и отчёты услуг

Задача 1097. Код: правила без БД — `packages/shared/src/service-reports.ts` (`orderOverdue`, `spreadPlan`), схемы запросов — `schemas/service-reports.ts`,
сервис — `packages/db/src/service-reports.ts`, API — `apps/api/src/routes/service-reports.ts` (`/services/reports/*`),
экран — `apps/web/src/app/services/reports/` (`/services/reports`, группа «Услуги»), вкладка компании — `apps/web/src/app/docs/CompanyDocuments.tsx`.
Тесты — `apps/api/test/service-reports.test.ts`.

- **Запросы.** `GET /services/reports/{states|schedule|load|clients}?from&to[&counterpartyId&assigneeId&kindId&today]` — период (не длиннее года, иначе `422 report_period_invalid`),
  клиент, исполнитель (участник), вид заказ-наряда; `today` — «сегодня» для просрочки (по умолчанию дата сервера). Читает любой участник.
- **Состояние (`states`).** Заказ-наряды с датой документа в периоде. Строки по заказ-нарядам и сводка по видам и состояниям (число, сумма без НДС и с НДС, просроченные, часы, % выполнения),
  по категориям и итоги. % выполнения — факт/план часов назначений (`work_order_assignments.planned_hours`, время всех `time_logs` задач-назначений). Оплат в системе нет — колонок оплаты нет.
- **Просрочка** (`orderOverdue`). Заказ-наряд не в категории `done | delivered | cancelled` и `due_date < today`, **или** есть незакрытое назначение (задача не в статусе `done`),
  конец которого раньше `today` (локальная дата `end_at` в поясе воркспейса, иначе срок задачи). У отменённого заказ-наряда назначения не проверяются. Срок документа и назначения
  показываются как причины `due` / `assignment`, дни — наибольшая просрочка.
- **Отклонения (`schedule`).** По назначениям: плановые и фактические часы, плановый конец (`end_at`, иначе срок задачи), закрытие (`tasks.completed_at` у задачи в `done`),
  отклонение в часах и днях (у незакрытой просроченной — до `today`); итоги по заказ-наряду и исполнителю. В период назначение попадает по плановому концу, без дат — по дате документа.
- **Загрузка (`load`).** По исполнителям и дням: доступное время — график участника (`members.calendar_id`, иначе график воркспейса; праздники и исключения), плановые часы, факт — `time_logs`
  задач модуля `services`, % загрузки, перегрузка (план или факт больше доступного). План раскладывается `spreadPlan` в поясе воркспейса: интервал `start_at..end_at` — пропорционально
  длительности в каждом локальном дне (в том числе через полночь), без интервала — в день срока задачи, затем срока документа, без дат — строка «без даты» (берётся по дате документа,
  в проценты не входит). Отменённые заказ-наряды в план не входят. Отбор клиента или вида ограничивает и факт задачами этих заказ-нарядов.
- **Клиенты (`clients`).** Выручка без НДС за период = заказ-наряды, выполненные в периоде (вход в «выполнен», как в отчёте себестоимости 1096), + проведённые акты и реализации
  (по дате документа) − возвраты покупателей; разбивка «работы и услуги / товары» по виду номенклатуры строки. Себестоимость = `computeWorkOrderCost.cost.fact` заказ-нарядов
  + себестоимость движений актов, реализаций и возвратов (у возврата отрицательна). Отборы вида и исполнителя относятся к заказ-нарядам: с ними акты, реализации и возвраты не учитываются.
- **Права.** Себестоимость, маржа и процент клиентов — только admin и owner: API отдаёт `null` (`maskClientsReport`), интерфейс скрывает колонки.
- **Интерфейс.** Вкладки в адресе (`?tab=`), общие отборы, таблицы и графики — каркас отчётов производства (`production/reports`: `ReportTable`, `BarChart`, `ReportState`), импортируется оттуда без копирования.
  Вкладка «Документы» карточки компании использует журнал `GET /documents?counterpartyId=&type=` (итоги выборки возвращает сервер).
