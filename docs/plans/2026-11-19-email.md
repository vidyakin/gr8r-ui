# Почта: отправка и входящие (задача 1092, часть «почта»), 2026-11-19

Повод: главный пробел CRM по сравнению с EspoCRM (`2026-11-19-espocrm-gap.md`). Без почты нет переписки в истории клиента,
отправки счетов и КП, писем из автоматизаций, подтверждения заявок, будущих рассылок и обработки ответов (`2026-11-16-ai-lead-intake.md`).

## Решения пользователя (2026-11-19)

- Первый этап — **отправка и входящие**, двумя инкрементами подряд. Полный почтовый клиент (папки, фильтры, групповые ящики) — не сейчас.
- Ящики — **общий ящик воркспейса** (автоматизации, системные письма) **и личные ящики** сотрудников (письма из карточек уходят от имени менеджера).
- Подключение — **обычный SMTP/IMAP** (Яндекс 360, Mail.ru, Gmail, свой сервер; пароль приложения). Сервисы рассылок по API — позже.
- SMS — отдельной задачей на том же каркасе исходящих сообщений.

## Инкремент А — отправка

### Данные (db)
- `mailboxes`: `id`, `workspace_id`, `kind` (`shared` | `personal`), `member_id` (у личного; у общего null, общий — один на воркспейс),
  `email`, `display_name`, `smtp_host`, `smtp_port`, `smtp_secure` (`ssl` | `starttls` | `none`), `smtp_user`,
  `imap_host`, `imap_port`, `imap_secure`, `imap_user` (заполняются для инкремента Б), `signature` (текст), `status`
  (`ok` | `error` | `unchecked`), `last_error`, `checked_at`, `created_at`, `updated_at`. RLS — как у прочих таблиц арендатора.
  Пароль — в хранилище секретов (`docs/architecture/secrets.md`) под ключом `mailbox.<id>.password`, в таблице его нет.
- `email_messages`: `id`, `workspace_id`, `mailbox_id`, `direction` (`out` | `in`), `status` (`queued` | `sending` | `sent` | `failed` | `received`),
  `from_email`, `from_name`, `to` (массив адресов), `cc`, `subject`, `body_text`, `body_html` (очищенный), `message_id`, `in_reply_to`,
  `references`, `attempts`, `last_error`, `sent_at`, `received_at`, `created_by`, связи `lead_id`, `contact_id`, `company_id`, `deal_id`,
  `document_id` (все nullable), `created_at`. Вложения — через существующие вложения (`docs/architecture/attachments.md`).
- Письмо в истории: при отправке и приёме создаётся касание `crm_activities` типа `email` со ссылкой на письмо (`email_message_id`),
  чтобы письмо было в ленте лида, контакта, контрагента и сделки без отдельного экрана.

### Отправка (worker)
- Задача воркера `email.send`: берёт письмо `queued`, читает пароль через `readSecret`, отправляет через `nodemailer`, ставит `sent`
  или повторяет при временной ошибке (как flow: экспоненциально, до 5 попыток), затем `failed` с причиной. Заголовок `Message-ID`
  генерируем сами и храним — по нему инкремент Б свяжет ответы.
- Защита: адреса SMTP-серверов — через `net.ts` (SSRF: без локальных адресов в проде), таймауты, лимит писем на воркспейс в сутки.
- Выбор ящика: явный `mailboxId`; иначе личный ящик автора; иначе общий; нет ни одного — понятная ошибка `mailbox_required`.

### API
- `GET/POST/PATCH/DELETE /mailboxes` — общий ящик правит admin+, личный — его владелец; ответ без пароля, с фактом наличия.
- `POST /mailboxes/:id/check` — проверка SMTP (и IMAP, если заполнен) подключением, статус в ящик.
- `POST /emails` — поставить письмо в очередь: получатели, тема, текст, вложения (id существующих), привязки, `documentId` +
  `printForm` для PDF документа (печать уже есть у воркера). `GET /emails?leadId=…|contactId=…|companyId=…|dealId=…` — переписка.
- Realtime-событие на смену статуса письма.

### Интерфейс (web)
- «Настройки» → «Почта»: общий ящик (форма с пресетами Яндекс 360 / Mail.ru / Gmail, кнопка «Проверить»). «Профиль» → «Мой почтовый ящик».
- Окно «Новое письмо» (кому, копия, тема, текст, подпись ящика, вложения, выбор ящика «от кого») — из вкладки «Дела» лида, контакта,
  контрагента, сделки (рядом с «Записать звонок»), и кнопка «Отправить по почте» в документе (счёт, КП, заказ, реализация) с PDF.
- В ленте касаний письмо показывается со статусом (в очереди, отправлено, ошибка — с причиной и «Повторить»).

### Автоматизации
- Узел `action.email_send` (`packages/shared/src/automations/nodes/`, как `action-telegram-send`): ящик (общий по умолчанию или ответственного),
  кому (подстановки `{{…}}`), тема, текст, привязка к записи триггера. Порт `rt.sendEmail` в рантайме воркера.

### Тесты (инкремент А)
- Ящики: права (чужой личный ящик не виден и не правится), пароль не уходит в ответы, RLS между воркспейсами.
- Очередь: письмо → `sent` (фейковый SMTP-транспорт), временная ошибка → повтор, постоянная → `failed`; касание создаётся.
- Узел автоматизации отправляет письмо с подстановками.

## Инкремент Б — входящие

- Задача воркера `email.sync` по расписанию (раз в 2–5 минут) и вручную: для каждого ящика с IMAP — `imapflow`, новые письма из INBOX
  (по `UIDVALIDITY` + последнему `UID`, курсор в ящике), разбор `mailparser`, HTML — через ту же очистку, что в комментариях.
- Сопоставление: `In-Reply-To`/`References` → наше отправленное письмо → его привязки; иначе адрес отправителя → контакт → контрагент,
  иначе лид по email. Не нашлось — письмо хранится без привязки (виден в ящике), лид не создаётся (настройка «создавать лид из
  писем без привязки» — флажок общего ящика, по умолчанию выключен).
- Касание `email` направления «входящее», уведомление ответственному, триггер автоматизаций «Получено письмо» (запись, ящик, отправитель).
- Вложения входящих — в хранилище вложений с лимитом размера.
- Экран «Почта» (минимальный): входящие ящиков, доступных пользователю, «без привязки» — с действием «Привязать к контакту/лиду».
- Тесты: разбор письма, сопоставление по In-Reply-To и по адресу, повторная синхронизация не дублирует, RLS.
