# Параметрические спецификации, варианты и калькуляция заказа (этап 7)

Код: язык выражений и параметры — `packages/shared/src/expr.ts` и `parameters.ts`, схема — `packages/db/src/schema/production.ts`
и `schema/calculations.ts` (миграция `0023_stage7_parametric_specs.sql`), сервисы — `packages/db/src/specs.ts`, `variants.ts`,
`calculations.ts`, API — `apps/api/src/routes/production.ts`, `production-orders.ts`, `calculations.ts`, `catalog.ts`,
клиент — `apps/web/src/app/production/*` и `apps/web/src/app/docs/calculation.tsx`.

- **Параметры спецификации** — `manufactured_items.params jsonb`: список описаний (`FieldDef`: `number`, `select`, `boolean`,
  ключ, название, обязательность, варианты) и у каждого флажок **«разрез склада»** (`stockDimension`). К параметрам
  спецификации добавляются характеристики категории её товара (с унаследованными); ключ параметра не может совпадать с
  ключом характеристики (422). Значения параметров хранятся в строке заказа (`document_lines.params`) и в позиции заказа
  на производство (`production_items.params`) и проверяются той же схемой значений, что и характеристики категории
  (`checkParamValues` в `specs.ts`: тип, варианты select, лишние ключи — 422 `invalid_params`; обязательность — при расчёте
  состава, незаполненный параметр формулы даёт 422).
- **Формулы строк** — `bom_lines.qty_expr` (количество) и `bom_lines.condition` (условие включения строки в состав);
  длина до 500 символов (`CHECK` в БД). Выражения считает **безопасный вычислитель** `packages/shared/src/expr.ts`:
  свой токенизатор и парсер (без `eval` и `Function`), числа десятичные (BigInt, `decimal.ts`), строки в кавычках,
  параметры-идентификаторы, `+ − * /`, скобки, унарный минус, сравнения `= <> != < <= > >=`, логика `and/or/not`,
  функции `if`, `round`, `ceil`, `floor`, `min`, `max`, `abs`; пределы: длина 500, вложенность 16, аргументов 8;
  зарезервированные имена (`__proto__`, `constructor`, `prototype`) запрещены. При сохранении строки спецификации
  выражение разбирается и сверяется со списком параметров (неизвестный параметр — 422 с текстом ошибки); при вычислении
  понятные ошибки: незаполненный параметр, деление на ноль, несовпадение типов, отрицательное количество.
  Вложенной продукции значения передаются **по совпадающим ключам**; без параметров поведение строго прежнее.
- **Несколько спецификаций на товар** (`resolveSpecForProduct` в `specs.ts`): у обычного товара — спецификация по
  умолчанию (`product_manufacturing.default_item_id`), без неё — самая ранняя своя (`manufactured_items.product_id`);
  у варианта — своя спецификация варианта, иначе спецификация по умолчанию родителя. Параметры товара (проверка
  значений, варианты) берутся из той же спецификации. Флажок `is_invalid` («Недействительна»): такая спецификация не предлагается в новых документах и не
  выбирается по умолчанию, старые документы не ломаются.
- **Варианты товара** (`products.parent_product_id` + `variant_values`): комбинация значений параметров с флажком «разрез
  склада» даёт отдельную складскую позицию. Вариант создаётся **лениво** при первом заказе комбинации (строка заказа
  покупателя ссылается уже на вариант; при смене значений строка, уже ссылающаяся на вариант, переходит на вариант той
  же основы; позиция заказа на производство без строки заказа покупателя получает вариант по своим значениям) или заранее кнопкой «Create all combinations» по select-параметрам с флажком
  (лимит 200 комбинаций, сверх — 422). Гонка двух одновременных созданий одной комбинации даёт одну строку
  (уникальный индекс + `ON CONFLICT DO NOTHING` по нему). Артикул варианта — артикул родителя и значения через «-»;
  занятый артикул — вариант без артикула. Выпуск по строке с параметрами приходует вариант; остаток родителя
  не меняется.
- **Строка «Расход»** (`bom_lines.kind = 'expense'`): услуга подрядчика. Входит в плановую себестоимость и калькуляцию,
  но со склада не списывается и в потребности, резервы и заказы поставщику не попадает (`CHECK` на `kind` пересозданы
  в миграции 0023 — и в `bom_lines`, и в `production_components`).
- **Снимок под заказ:** состав по параметрам считается при создании заказа на производство и при выпуске, а кнопка
  «Recalculate composition» (`POST /production-orders/:id/fill-from-bom`) пересчитывает снимок в черновике; в проведённом
  заказе — 422 (сначала отмена проведения). Ручная правка снимка остаётся.
- **Калькуляция заказа покупателя** — `order_calculations` (документ, источник цены `avg|last_purchase|purchase_price`,
  наценка, итоги) и `order_calculation_lines` (строка заказа, тип `material|semi|work|expense|extra`, товар, количество,
  цена, сумма; `extra` — разовые расходы, например доставка). Источник цены: выбранный, при отсутствии цены — следующий
  по порядку `avg → last_purchase → purchase_price`. Себестоимость единицы — та же, что плановая (`computeBomCost`:
  материалы, работы с фиксированными затратами, полуфабрикаты по своим спецификациям, накладные %), только с ценами по
  источнику калькуляции; строки состава — расшифровка развёртки, фиксированные затраты и накладные — отдельная строка
  «Fixed costs and overhead». Итог цены — сумма «цена единицы × количество». «Apply price to lines» переносит в строки
  заказа цену себестоимости единицы × (1 + наценка) — **только в черновике** (в проведённом заказе 422 `not_draft`). Себестоимость видят только admin и owner: у member суммы скрыты, пересчёт и
  применение цены — 403.
- **Печать спецификации:** «кратко» (только эта спецификация) и «развёрнуто» (все переделы до исходных материалов) —
  `GET /manufactured-items/:id/print/short|expanded`, шаблон `packages/shared/src/print/bom.ts`. Фильтр списка
  спецификаций «Contains material/operation» — по конкретному товару (материал, расход) или операции:
  `GET /manufactured-items?contains=<productId>`.
- **Ограничения:** строки плана производства и расчёта потребностей не несут значений параметров — изделие с формулами,
  которые требуют значений, в потребности по плану не попадает (строка пропускается, как при цикле); изделие без своих
  параметров с параметрическим полуфабрикатом не разворачивается (значения взять неоткуда); полуфабрикат в режиме
  `stock` по параметрам не делится на варианты; «Расход» входит в фактическую себестоимость выпуска по плановой цене
  (поступление той же услуги со статьёй и участком закрытие месяца распределит ещё раз).
