# Разборка (вид операции «Разборка»)

Реализовано в задаче #1134 (сессия «УНФ: Производство»). Код: сервис — `packages/db/src/production.ts` (`disassemblySplit`, ветки проведения и
пересчёта выпуска), схема — `packages/db/src/schema/production.ts` (миграция `0024_disassembly.sql`), чистые функции — `packages/shared/src/bom.ts`
(`allocateDisassembly`, `outputBases`, `checkCostShares`), API — `apps/api/src/routes/production.ts` и `routes/production-orders.ts`,
клиент — `apps/web/src/app/production/ItemPage.tsx`, `line-dialog.tsx`, `ProductionOrderPage.tsx`, `apps/web/src/app/docs/DocumentPage.tsx`.

- **Вид операции документа** — `documents.operation`: у заказа на производство и выпуска `assembly` (сборка, по умолчанию) или `disassembly`
  (разборка). Выбор вида — в шапке заказа; выпуск наследует вид операции заказа (у выпуска он только показывается). Вид операции заказа должен
  совпадать с видом спецификации каждой позиции, иначе 422 `operation_mismatch`. Существующие документы не меняются: вид операции по умолчанию — сборка.
- **Спецификация разборки** — у `manufactured_items` поле `mode` (`assembly | disassembly`, по умолчанию `assembly`). У разборки товар спецификации —
  **исходный** (что разбирают), а строки спецификации — только `output` (выходной продукт: товар, количество на партию, **доля стоимости** `cost_share`)
  и `work` (операции). Строки `material` / `semi` / `expense` в спецификации разборки запрещены, а `output` — в спецификации сборки (422
  `spec_kind_forbidden`). Формулы этапа 7 (`qty_expr`, `condition`) у выходов разрешены — они считаются так же, как у материалов.
- **Доли стоимости.** Если доля задана хоть у одной строки, заданы все, и сумма ровно 100 %; иначе 422 (`share_incomplete` / `share_sum`).
  Проверка — при сохранении спецификации и при проведении выпуска (строки добавляются по одной, поэтому проверка суммы не висит на каждой строке).
- **Заказ на производство с видом «разборка».** В «Продукции» — исходный товар и количество (что разбирают); снимок `production_components` содержит
  строку `material` с исходным товаром (он списывается со склада и обеспечивается как материал — резерв, потребности и заказы поставщику),
  строки `output` (выходные продукты) и `work`. «Fill from BOM» собирает снимок по спецификации разборки. Выходные продукты в потребности
  не попадают: они не расходуются, а ожидаются поступлением.
- **Выпуск с видом «разборка».** Списывает исходный товар по средней склада и приходует выходные продукты. Себестоимость разборки — списанное
  + работы + накладные (`overhead_pct` спецификации) — делится между выходами: по долям стоимости, иначе по цене продажи × количество, иначе по
  количеству; остаток округления — на последней строке, сумма приходов равна распределяемой стоимости. Чистая функция `allocateDisassembly`
  (`packages/shared/src/bom.ts`) — та же логика на сервере и в тестах. Поэтапный выпуск и сдельный наряд работают как при сборке: работы разборки
  оцениваются нормой, фактическая стоимость нарядов пересчитывает распределение (`recalcReleaseCost`).
- **Пересчёты стоимости.** `recomputeStockCosts` (`packages/db/src/stock.ts`) переносит удорожание исходного товара на выходные продукты
  в обратную сторону, чем при сборке: удорожание списанного исходного товара (с накладными) делится между приходами выходов пропорционально
  их стоимости при проведении (`production_components.actual_cost`; без стоимости — по количеству), а не по текущим ценам продажи.
  Закрытие месяца распределяет косвенные затраты участка на выходные продукты разборки (`loadReleaseTargets`); часы работ позиции
  разборки делятся между выходами по их стоимости, чтобы база «по часам работ» не считала их по разу на каждый выход.
- **Разборка — в один этап:** вид производства у спецификации разборки запрещён (422 `disassembly_stages`). Спецификация разборки не
  может быть спецификацией по умолчанию товара (`product-settings`: только сборка этого же товара), а выбор спецификации товара
  (`resolveSpecForProduct`) берёт только сборки.
- **Ограничения:** база «по объёму выпуска» у разборки — количество выходов; потребности плана производства по спецификации разборки не
  показывают исходный товар.
- **Интерфейс:** переключатель **Assembly / Disassembly** в шапке спецификации, строки «Output» с полем **Cost share, %**, вид операции в шапке
  заказа на производство, подписи по виду («What we disassemble» вместо продуктов, «Outputs» вместо состава), роль строки выпуска
  («To disassemble» / «Output»), печать спецификации с колонкой доли и подписью «Исходный товар».
- **Не сделано (по решению пользователя):** складской документ «Комплектация запасов», возвратные отходы при разборке (задача 1136),
  разборка давальческого сырья, распределение по итогам смены.
