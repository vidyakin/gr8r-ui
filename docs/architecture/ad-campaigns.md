## Данные (миграция 0053)
Таблицы арендатора: `workspace_id`, `unique(workspace_id, id)`, составные FK, `app_secure_tenant_table`.
- `lead_sources` — источник: название (уникально по `lower(name)`), цвет (палитра статусов лидов), **тип** `kind` (как в 1С:ERP: `channel` — канал, `partner` — партнёр, `contact` — контактное лицо; миграция 0054), порядок, архив.
- `ad_campaigns` — кампания: название, источник (обязателен), код `utm_campaign` (необязателен, уникален без регистра среди непустых), период, бюджет, комментарий, ответственный, архив.
- `ad_campaign_expenses` — расход кампании: дата, сумма `numeric(18,2)`, комментарий. Вводится вручную; удаление кампании каскадом удаляет расходы.
- `source_id` / `campaign_id` у `leads`, `lead_forms`, `companies`, `deals`; **кто привёл** — `referrer_company_id` / `referrer_contact_id` у `leads`, `companies`, `deals` (миграция 0054, составные FK `ON DELETE SET NULL (колонка)`; в схеме Drizzle FK нет — цикл типов companies ↔ contacts). У лида и формы текст `source` — **кэш названия источника** (подстановки `{{trigger.record.source}}`, фильтр `?source=`); пишет его только сервер.
- Миграция создала источники из непустых `leads.source` и `lead_forms.source` каждого воркспейса (без учёта регистра) и проставила ссылки.

## Атрибуция (`resolveAttribution`)
- **Кампания задаёт источник:** при выборе кампании источник ставится её; явно переданный другой источник — 422 `campaign_source_mismatch`. Смена источника сбрасывает кампанию другого источника. Ссылка на чужую/несуществующую кампанию или источник — 422 `invalid_reference`.
- **Текст** `source` (API лидов, узел «Создать лид», вебхук без источника формы) ищет источник по названию без учёта регистра и создаёт его, если нет (`findOrCreateSource`; сравнение в JS — `lower()` в БД с локалью C не меняет регистр кириллицы).
- **Вебхук формы:** кампания по `utm_campaign` (код кампании, архивные не сопоставляются) → кампания формы → источник формы → источник с названием `source`/названия формы.
- **Конвертация лида:** источник и кампания переносятся в новые контрагента и сделку; существующему контрагенту — только если у него источника нет (первое касание важнее).
- **Сделка** без явного источника при создании получает источник и кампанию контрагента.
- Переименование источника обновляет кэш `source` у лидов и форм; смена источника кампании переносит `source_id` у её лидов, форм, контрагентов и сделок.
- Встроенное поле `source` у узла «Обновить поле» лида убрано.
- **Кто привёл** зависит от типа источника: у партнёра сохраняется только контрагент, у контактного лица — только контакт, у канала — ничего (лишнее молча отбрасывается, чужая запись — 422). Конвертация лида и сделка от контрагента переносят ссылку вместе с источником; смена типа источника снимает неподходящие ссылки у его лидов, клиентов и сделок. У формы сайта рекомендателя нет.

## Отчёт по каналам `GET /ad-report?from&to&groupBy=source|campaign`
Даты включительно. Строка на источник (кампанию) плюс «без источника» (`key: null`, в конце):
- `leads` — лиды по `created_at` (без архивных), `converted` — сколько из них сконвертировано;
- `newClients` — контрагенты по `created_at`;
- `wonDeals`, `revenue` — сделки этапа `won` по `closed_at` (после воронок 1176 — категория этапа), сумма `amount`;
- `expense` — расходы по дате (для разреза по источникам — через источник кампании);
- `conversion` = converted / leads × 100 %, `cpl` = expense / leads, `cac` = expense / newClients, `romi` = (revenue − expense) / expense × 100 %; при нулевом делителе — `null`. Итог (`total`) считается от сумм.
- `currencies` — валюты выигранных сделок: валюты воркспейса нет, суммы складываются как есть; интерфейс предупреждает, если валют больше одной.
Разрез `groupBy=referrer` — по тем, кто привёл (контрагент или контакт, `refKind`): только записи с рекомендателем, без расходов и строки «без источника». Отчёт видят все участники.

## API и права
`/lead-sources` (CRUD, архив, 409 `lead_source_in_use`, если есть активные кампании), `/ad-campaigns` (CRUD, `spent` — потрачено за всё время, 422 `campaign_period_invalid`), `/ad-expenses` (фильтры `campaignId`, `from`, `to`) — запись admin+. Фильтры `sourceId` / `campaignId` у `/leads`, `/companies`, `/deals`. События `lead_source.*`, `ad_campaign.*`, `ad_expense.*`; клиент обновляет ключ `['ws', id, 'ad', …]`.

## Интерфейс
CRM → «Реклама» (`/crm/ads`): вкладка «Отчёт по каналам» (период, разрез, итог, ROMI цветом) и «Кампании» (создание и правка, расходы по нажатию на название). Settings → «Источники привлечения» (название, тип, цвет, порядок, архив). Поля «Источник», «Кампания» и «Кто привёл» (для партнёра и контактного лица) — в карточке лида, форме сайта, карточке контрагента и сделки. Тексты — `ads.*`.
