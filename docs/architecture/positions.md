# Должности сотрудников и виды номенклатуры (задача 1172)

Код: `packages/db/src/positions.ts`, `packages/shared/src/positions.ts`, `apps/api/src/routes/positions.ts`, `apps/web/src/app/positions/`, `settings/positions.tsx`.

## Данные (миграция 0039)
- `positions` — название (уникально без учёта регистра), `functions text[]`, `sections text[]` (пусто = все разделы).
- `member_positions` — должности участника (одна или несколько), `position_product_kinds` — виды номенклатуры, которые оказывает должность.
- `product_kinds` — вид номенклатуры: название и тип `goods | service | work`; `products.product_kind_id` (необязательно).
- Все четыре таблицы под RLS (`app_secure_tenant_table`), ссылки составные `(workspace_id, id)`.
- `members.is_courier` удалён: миграция создаёт в воркспейсах с курьерами должность «Курьер» (`courier`, все разделы) и назначает её отмеченным.

## Функции и списки выбора
Функции: `appointments_specialist`, `courier`, `production_worker`, `work_order_executor`, `sales_manager`.
`membersWithFunction` (shared): участники с функцией; если ни у одной должности воркспейса её нет — все участники.
Применено: специалисты записи (`GET /appointments/specialists`, график), курьеры (`GET /deliveries/couriers`, вкладка доставки), исполнители
заказ-нарядов и производства (в списке остаются уже назначенные), ответственные сделок и менеджеры плана продаж.
Ограничение курьера своими доставками (`courierScope`) действует только при наличии у участника должности с функцией `courier`.

## Разделы меню
Разделы: `crm, trade, stock, services, deliveries, production, finance, projects, catalog, automations` (соответствие пунктов меню — `POSITION_SECTION_OF` в `apps/web/src/app/routes.ts`).
`visibleSections(role, positions)`: admin/owner — все; без должностей — все; иначе объединение (должность с пустым набором открывает все).
`GET /positions/me` отдаёт должности, функции и видимые разделы (отдельный запрос воркспейса, а не `/auth/me`: сессия не привязана к воркспейсу).
Интерфейс скрывает пункты меню, группы, команды и поиск палитры; прямой переход на скрытый раздел показывает «Нет доступа к разделу» (`SectionGuard`).
Это видимость интерфейса: права API (роли) не менялись.

## Виды номенклатуры
- Справочник правят admin и owner, читают все. Тип вида должен совпадать с `products.kind` (422 `product_kind_mismatch`); вид, используемый товарами, не удаляется (409 `product_kind_in_use`), его тип не меняется под товарами другого типа.
- Фильтр по виду в каталоге (`GET /products?productKindId=`), поле в карточке товара.
- У должности со специалистом записи — оказываемые виды. `specialistProductKindIds`: объединение видов его должностей; нет видов — любые услуги.
  Запись и перенос к другому специалисту проверяют услугу (422 `service_not_provided`), поиск свободного времени пропускает неподходящих специалистов.
  Форма записи фильтрует услуги и специалистов друг по другу; в документе «Оказанные услуги за день» услуги — по видам специалиста, товары — кнопкой «Добавить товар».

## API
`/product-kinds` и `/positions` (GET — все; POST/PATCH/DELETE — admin), `PUT /positions/by-member/:memberId` (admin), `GET /positions/me`.

## Фактическая реализация (задача 1172)
Реализовано по решениям плана целиком; демо: виды «Массаж / Мебель / Монтаж», должности «Массажист», «Рабочий цеха», «Курьер», «Менеджер» назначены шести участникам (кроме автора).
Отклонения: видимые разделы отдаёт `/positions/me`, а не `/auth/me`; серверной проверки функций при назначении курьера/исполнителя нет (фильтруют списки); строки услуг документа дня на сервере по видам не проверяются.
