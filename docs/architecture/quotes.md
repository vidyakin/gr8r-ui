## Варианты КП (КП и заказ покупателя)
- **Строки документа — всегда основной вариант.** Резервы, исполнение (`origin_line_id`), калькуляция, производство,
  пополнение и «на основании» читают `document_lines` и о вариантах не знают. Остальные варианты — `document_variants`
  (название, порядок, снимок строк `lines jsonb` с id строк, группой, параметрами и ссылками `source/origin`, итоги).
  Название основного — `documents.variant_name` (`null` — вариантов нет). `hasQuoteVariants(type)` в `shared`.
- Операции только в черновике (409 `not_draft`; у других типов — 422 `variants_not_available`):
  `POST /documents/:id/variants { name?, copy }` — прежний основной уходит в список, новый (копия с новыми id строк или
  пустой) становится основным; `POST …/variants/:vid/activate` — меняет местами основной и выбранный (id строк и ссылки
  сохраняются); `PATCH …/variants/:vid { name }`; `DELETE …/variants/:vid` (последний удалённый — `variant_name = null`);
  имя основного — `PATCH /documents/:id { variantName }`. Событие — `document.updated` (`changes: ['variants']`).
- Итоги вариантов в карточке (`variants[].totals`) и печати считаются на лету по текущему «НДС в т.ч./сверху».
  Смена вида цен пересчитывает только основной вариант.
- **Отличия от 1С:** вариант, открытый в форме, — основной (переключение в форме = «Сделать основным»), поэтому состояния
  «основной не выбран» и запретов проведения/печати нет; настройки CRM «Несколько вариантов КП» нет.

## Группы строк
`document_lines.group_name` (пусто — без группы), колонка «Группа» в КП, заказе и счёте, итоги «По группам» под таблицей.
Клиент, не приславший `groupName`, группу строки не сбрасывает. «На основании» копирует группу. Печать — подзаголовок
группы с суммой (`groupedRows` в `print/templates.ts`) в счёте на оплату (он же заказ) и в КП; УПД, ТОРГ-12, акт — без групп.

## Шаблоны КП
- `doc_templates`: название, `purpose` (в БД перечень 1С: `quote`, `contract`, `contract_order`, `contract_invoice`,
  `contract_work_order`; API принимает только `quote`), `body`, `is_used` («Используется» — в меню «Печать»),
  `only_author` (видит и печатает только автор — даже admin), `author_id`, архив вместо удаления.
- API `/doc-templates`: список (`purpose`, `used`, `archived`), карточка, создание — member+, правка и удаление — автор или
  admin+ (403 `forbidden`). Событие `doc_template.*`, кэш фронтенда `['ws', id, 'doc-templates']`.
- **Текст шаблона** (`print/quote.ts`): `# ` и `## ` — заголовки, пустая строка — абзац, `**жирный**`, параметры
  `{{Контрагент}}`, `{{Номер}}`, `{{Сумма прописью}}`… (`QUOTE_TEMPLATE_PARAMS`), блоки отдельной строкой — `{{Товары}}`
  (основной вариант по группам), `{{Варианты}}` (все варианты с итогами; без вариантов — как `{{Товары}}`), `{{Подписи}}`.
  Всё экранируется, значения не участвуют в разметке; незнакомый параметр остаётся текстом; строка, где все параметры
  пустые, не печатается. Стандартная форма — `DEFAULT_QUOTE_TEMPLATE`, с неё начинается новый шаблон.
- **Печать:** форма `quote` («Коммерческое предложение») у КП и заказа покупателя. `GET /documents/:id/print/quote?template=<id>`,
  PDF — `POST /documents/:id/pdf { form: 'quote', templateId }` (`document_files.template_id`, воркер печатает от имени
  `requested_by`). Меню «Печать»: стандартная форма, используемые шаблоны пользователя, «Все шаблоны КП…» → `/crm/quote-templates`.
- Не сделано: загрузка docx/odt и вкладка «Файлы», картинки товаров, отправка по почте (задача 1092), шаблоны договоров,
  связь КП со сделкой CRM.
