# Маркировка «Честный ЗНАК» для производства

План от 2026-11-07. TaskFlow — сессия 61, задачи 1376–1383 (номера — в «Порядке задач»).

## Рамки (решения 2026-11-07)

- **Товарные группы первой очереди:** молочная продукция и косметика с бытовой химией. Остальные группы — тем же
  механизмом позже (группа — настройка, а не код).
- **Только производство:** заказ кодов, печать этикеток, нанесение, ввод в оборот, вывод из оборота при списании.
- **Кассы не подключаем.** Розничную продажу гасит касса покупателя (ФФД 1.2 → ОФД → ГИС МТ). Мы только **каждую ночь
  подтягиваем статусы** своих кодов с сервера ЧЗ: кому передан, выведен ли из оборота, когда.
- **Портал ЧЗ остаётся для разовых дел:** регистрация участника, подключение товарных групп, договор с оператором и оплата
  кодов, карточки товаров в Национальном каталоге (на первом этапе — вручную на портале, у нас только GTIN).

## Как устроен ГИС МТ (кратко)

| Контур | Что берём |
|---|---|
| **СУЗ-Облако** (станция управления заказами) | заказ кодов, получение кодов блоками, отчёт о нанесении |
| **True API** | ввод в оборот, вывод из оборота, статус обработки документов, сведения о кодах (ночная синхронизация) |
| **Национальный каталог** | GTIN товара; карточки — пока на портале |
| **ЭДО** | передача кодов покупателю в УПД; оператор у нас отложен (1203), см. «Отгрузка» |

Документация закрыта: открывается после входа по УКЭП в разделе разработчика на честныйзнак.рф. Названия эндпоинтов и форматов
ниже — по открытым SDK и сообществу, **сверить в песочнице до реализации** (задача «Песочница», шаг 0).

## Особенности групп

| | Молочка | Косметика и бытовая химия |
|---|---|---|
| Учёт сейчас | поэкземплярный, разрешительный режим на кассах | объёмно-сортовой: в УПД — GTIN и количество, не коды (с 01.07.2026); поэкземплярный — с 2028–2030 (даты в источниках расходятся) |
| Ввод в оборот | нужен **идентификатор ВСД из «Меркурия»**: ЧЗ сверяет его с «Меркурием»; порядок — нанесение → ВСД → ввод в оборот | без ВСД |
| Даты | дата производства и срок годности — из нашей партии (`batch_produced_at`, `batch_expires_at`) | срок годности — если есть |
| Ночная синхронизация | видно, кому передан и когда продан | до поэкземплярного учёта статус «продан» может не обновляться — проверить в песочнице |

«Меркурий» не интегрируем: номер ВСД вводится в выпуске руками (или вставляется из буфера). Интеграция с ФГИС «ВетИС» —
отдельная задача, если попросят.

## Решения

1. **Модуль тарифа `marking`** (зависит от `production`; `docs/architecture/licensing.md`). Раздел меню «Маркировка»:
   заказы кодов, реестр кодов, документы ЧЗ, настройки подключения. Отраслевая опция `food` по-прежнему показывает партии —
   для молочки без партий маркировка не работает, проверка при включении товарной группы.

2. **Товар.** В карточке: «Маркируется», товарная группа ЧЗ (`milk` / косметика — код группы сверить), **GTIN** (отдельное поле,
   не `barcode`: у товара может быть свой штрихкод магазина), вид кода (единица / набор). Маркируемый товар требует партионный
   учёт (молочка) и целое количество в документах, как серийный (`docs/architecture/serials-repair.md`).

3. **Подпись УКЭП — в браузере пользователя** через КриптоПро ЭЦП Browser plug-in (`cadesplugin`). Сервер готовит данные
   (строку авторизации или тело документа в base64), браузер подписывает откреплённой подписью CAdES-BES, сервер отправляет
   в ЧЗ. **Ключи клиента на сервере не храним.** Облачная КЭП (КриптоПро DSS и подобные) и МЧД — позже, через тот же интерфейс
   «подписанта» (`Signer`: браузер / облако). Связь с задачей 1204 (КЭП) — общий подписант, но маркировка его не ждёт.

4. **Доступы ЧЗ — в хранилище секретов** (`docs/architecture/secrets.md`), ключи `crpt.*`: `crpt.oms_id`, `crpt.oms_connection`
   (идентификатор подключения СУЗ), `crpt.oms_token` (клиентский токен СУЗ), `crpt.api_key` (постоянный токен из ЛК, если подойдёт —
   см. п. 11), `crpt.true_token` + срок (токен True API после подписи, ~10 часов). Контур (прод / песочница) — настройка воркспейса.
   ИНН участника — из организации (`counterparties.md`); у арендатора с несколькими организациями — подключение на организацию.

5. **Адаптер ЧЗ** в `packages/shared` (типы, сборка тел документов, разбор кодов: GTIN, серийный номер, криптохвост по GS1)
   и в `apps/worker` (HTTP). Тесты и демо работают на `FakeCrpt` (как `MemoryFileStore`) — без сети.

6. **Реестр кодов `marking_codes`:** воркспейс, организация, товар, GTIN, полный код (GS1 с разделителями, как выдал СУЗ —
   нужен для печати), короткий код (01+21, для поиска и сверки), заказ кодов, партия, документ выпуска и строка, статус, владелец
   (ИНН) и дата смены, дата выбытия и причина, последняя сверка. Уникальность — (воркспейс, короткий код).
   Статусы у нас: `received` (получен из СУЗ) → `printed` → `applied` (отчёт о нанесении принят) → `introduced` (в обороте) →
   `transferred` (владелец сменился) → `retired` (выведен из оборота: продан в рознице, списан, экспорт) / `rejected` (ошибка ЧЗ).
   Журнал событий кода — как `serial_events`, чтобы отмена документа откатывала наши шаги до отправки в ЧЗ.

7. **Заказ кодов** — документ «Заказ кодов маркировки» (товар, количество, способ серийного номера — генерирует оператор).
   Проведение отправляет заказ в СУЗ; воркер опрашивает готовность и забирает коды блоками в реестр (`received`).
   Коды платные (списание с лицевого счёта в ЧЗ) — перед проведением предупреждение с количеством. Заказ из заказа на
   производство «на основании» — количество выпуска плюс запас в процентах (настройка).

8. **Печать этикеток.** DataMatrix генерируем сами (`bwip-js`, без сети) в PDF печатных форм: шаблоны 58×40 и 43×25 с названием,
   партией, сроком; лист A4 стикеров. Выгрузка CSV/TXT кодов для программ принтеров этикеток и линий (BarTender, нанесение
   на линии) — частый сценарий у производителей. Печать переводит коды в `printed`.

9. **Выпуск продукции → нанесение и ввод в оборот.** В документе выпуска (`production`, `production-orders.md`) у строки
   маркируемой продукции — коды по количеству: подобрать из напечатанных по товару, отсканировать сканером или загрузить файлом
   с линии. Для молочки — номер ВСД. После проведения выпуска кнопка «Отправить в ЧЗ» (подпись в браузере):
   отчёт о нанесении в СУЗ → после его обработки ввод в оборот через True API (даты производства и годности — из партии).
   Статус обработки документов ЧЗ опрашивает воркер, ошибки по кодам видны в выпуске. Проведение выпуска не ждёт ЧЗ:
   склад не должен зависеть от внешней системы; невведённая продукция видна отчётом «Не введено в оборот».

10. **Вывод из оборота при списании.** «Списание» маркируемого товара (брак, порча, образцы, собственные нужды) требует коды
    и после проведения отправляет документ вывода из оборота с причиной (подпись). Брак из ОТК (`quality.md`) — через то же списание.

11. **Ночная синхронизация — проход воркера** (как `runFleetOnce`, не строкой в `jobs`), раз в сутки ночью по воркспейсу:
    коды в статусах `introduced` и `transferred` пакетами отправляются в метод сведений о кодах True API (`cises/info`, размер
    пакета сверить), обновляются статус, владелец, дата выбытия; итог — событие для автоматизаций и строка в журнале синхронизации.
    **Проблема токена:** токен True API получается только подписью и живёт ~10 часов, а ночью пользователя нет. Порядок проверки
    в песочнице: (а) постоянный токен из ЛК (`X-Api-Key`) — по сообществу работает для проверки кодов; если подходит и для
    сведений о кодах, ночью подпись не нужна; (б) иначе — токен, подписанный днём, пока жив (напоминание «обновить доступ ЧЗ»
    в конце дня), а если истёк — синхронизация переносится на первый вход с подписью утром; (в) облачная КЭП — полное решение.
    Сведения доступны только по подключённым у участника товарным группам — учесть в ошибках.

12. **Отгрузка покупателю.** Без ЭДО коды остаются на балансе производителя, и в рознице молочка не продастся (разрешительный режим).
    Первый шаг — без оператора: выгрузка УПД XML (задача 1201) дополняется сведениями о маркировке — коды экземпляров (молочка)
    или GTIN и количество (косметика); клиент отправляет файл через своего оператора ЭДО. Переход кодов к покупателю мы видим
    ночной синхронизацией (`transferred`). В реализации маркируемого товара — подбор кодов по количеству, как серийных номеров.
    Отправка через оператора ЭДО — вместе с 1203.

13. **Экраны.** «Маркировка»: обзор (сколько получено, напечатано, в обороте, передано, выведено; ошибки), заказы кодов, реестр
    кодов с поиском по коду и фильтрами (товар, партия, статус, покупатель), документы ЧЗ со статусами и ошибками, журнал ночной
    синхронизации. Настройки → Интеграции: подключение ЧЗ (контур, СУЗ, проверка подписи и связи). Тексты — через `t()`,
    статья справки в `docs/user/`.

## Не делаем сейчас

Кассы и разрешительный режим на кассе, агрегация в короба и паллеты (нужна для линий с групповой упаковкой — следующая очередь),
Национальный каталог по API, импорт (таможня), перемаркировка, возвраты покупателей с повторным вводом в оборот, «Меркурий» по API,
оператор ЭДО (1203).

## Порядок задач

Задачи: 0 — 1376 (ждёт тестовую УКЭП), 1 — 1377, 2 — 1378, 3 — 1379, 4 — 1380, 5 — 1381 (списание) и 1382 (УПД), 6 — 1383.

0. **Песочница** (исследование, без кода в `main`): тестовая УКЭП, регистрация на тестовом контуре, сквозной прогон руками
   (скрипт в scratch): авторизация → заказ кодов → нанесение → ввод в оборот → сведения о кодах. Ответить на вопросы п. 11 (токен),
   коды товарных групп, размер пакета `cises/info`, поля ввода в оборот для молочки (ВСД, даты) и косметики, видны ли статусы
   кодов после передачи и продажи. Итог — дополнение этого плана.
1. **Основа** (db → shared → api): модуль `marking`, поля товара, `marking_codes` и журнал, секреты `crpt.*`, адаптер и `FakeCrpt`,
   подписант в браузере (`cadesplugin`), экран подключения.
2. **Заказ кодов и печать** (п. 7–8).
3. **Выпуск: нанесение и ввод в оборот** (п. 9) — зависит от 1–2.
4. **Ночная синхронизация и реестр** (п. 11, экраны п. 13) — зависит от 1; можно параллельно с 3.
5. **Списание** (п. 10) и **УПД с маркировкой** (п. 12) — после 3, параллельно друг с другом.
6. Демо (маркируемые молочка и крем, заказ, выпуск с кодами, синхронизация на `FakeCrpt`), справка, `changelog.md`.

Чек-лист `docs/lessons.md`: задача 3 и 5 меняют проведение (`applyStockMoves`, `saveLines`) — раздел «При планировании» до отдачи
субагенту.
