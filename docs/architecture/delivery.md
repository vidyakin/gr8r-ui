# Доставка

Задача 1100, часть 1 (без Яндекс.Доставки: её интеграция — позже, вместе с хранилищем секретов, задача 1092). Код: `packages/db/src/delivery.ts`,

## Данные
- `delivery_methods` — справочник способов: название (уникально среди неархивных), вид `own_courier | courier_service | third_party`, услуга каталога
  `product_id` (строка документа; обязательно услуга — 422 `delivery_product_not_service`), перевозчик (компания), тариф для клиента `client_rate`
  и тариф себестоимости `cost_rate` (jsonb `{ base, perKm, perKg, min }`), `free_from` — бесплатно для клиента от суммы документа без НДС.
- `deliveries` — одна доставка на документ (`document_id` уникален): заказ покупателя, реализация или заказ-наряд. Способ, адрес, контакт и телефон
  (по умолчанию из контрагента: фактический адрес, иначе юридический; первый контакт), дата и окно времени, расстояние, вес, `price` (клиенту) и
  `our_cost` (нам), курьер (`courier_member_id`) или перевозчик, статус `new | assigned | in_transit | delivered | failed`, комментарий, `line_id` —
  строка-услуга в документе, `origin_document_id` — заказ, из которого доставка перешла в реализацию.
- Расход в финансовый результат лежит в самой доставке: `expense_cost_item_id` (системная статья), `expense_amount`, `expensed_at`.
  Отдельного регистра финансового результата в проекте нет; расход читают отчёт по доставкам и (будущий) финансовый результат.
- `products.weight_kg` — вес товара, кг. `members.is_courier` — отметка «курьер» (правит admin и owner).
- Системная статья затрат `dostavka` («Доставка», расходная): миграция создаёт её существующим воркспейсам, `ensureCostItems` — новым;
  если название занято своей статьёй — «Доставка (системная)».

## Расчёт
`computeDeliveryCost(tariff, { distanceKm, weightKg, orderTotal })` (shared, decimal без float): цена = `base + perKm × км + perKg × кг`, не меньше `min`.
Для клиента: если `free_from > 0` и сумма документа без НДС достигла порога, цена 0; себестоимость остаётся (бесплатная доставка нам не бесплатна).
`deliveryWeight` — Σ количество × вес по строкам товаров (услуги и строки без веса дают 0). Сервер считает при создании доставки и при смене способа,
расстояния или веса, либо по `recalc`; явно присланные `price` / `ourCost` (себестоимость — только admin и owner) побеждают. Вес можно поправить
вручную или пересчитать по строкам (`recalcWeight`).

## Документ
- Вкладка «Доставка» у заказа покупателя, реализации и заказ-наряда: `GET/PUT /deliveries/by-document/:id`.
- «Добавить в документ» (`POST /deliveries/:id/add-to-document`) добавляет или обновляет строку-услугу «Доставка» (количество 1, цена доставки) —
  по `line_id`; у проведённого документа 409 `not_draft`. Строки читаются и сохраняются через `updateDocument`.
- **Наследование:** `createBasedOn(customer_order → realization)` вызывает `inheritDelivery`: доставка переходит к реализации (`document_id`), у заказа остаётся ссылка
  `origin_document_id` (ответ `by-document` заказа: `delivery: null`, `movedTo`). `line_id` перепривязывается по `source_line_id` скопированной строки.
  Завершённая (доставлена / не доставлена) доставка не переходит. Вторая реализация по тому же заказу доставку не получает.

## Статусы и расход
- Назначение курьера (`POST /deliveries/:id/assign`) двигает `new ↔ assigned`. `assigned`, а у своего курьера `in_transit` / `delivered` без курьера — 422 `courier_required`.
- «Доставлена» ставит `delivered_at`, пишет расход: `expense_amount = our_cost` на статью «Доставка» в день доставки; возврат из «доставлена» снимает расход
  (закрытый период — 422 `period_closed`). У **заказ-наряда** расход на статью не пишется: `loadWorkOrderCosts` добавляет себестоимость доставленной доставки в
  «прочие затраты» его себестоимости (`deliveredCostByWorkOrder`, задача 1096).
- Доставленную доставку нельзя удалить (409 `delivery_delivered`); завершённой нельзя сменить курьера (409 `delivery_closed`).

## Права
- Справочник способов: чтение — любой участник, правка — admin и owner. Доставки правит member и выше; guest читает.
- **Курьер** — участник с `members.is_courier`, чья роль ниже admin: видит в списках, карточке и «мои доставки» только свои, меняет только их статус на
  `in_transit | delivered | failed` (иначе 403 `delivery_not_yours` / `delivery_status_forbidden`); правка доставки, назначение, «Добавить в документ», удаление и отчёт ему закрыты (403).
  Admin и owner всегда видят всё. Себестоимость (`ourCost`, `expenseAmount`) и маржа приходят только admin и owner (иначе `null`).
- API: `GET /deliveries` (отборы `from`, `to`, `courierId`, `methodId`, `status`, `q`), `GET /deliveries/mine?date=`, `GET /deliveries/report?from&to&by=method|courier|day|month`,
  `GET /deliveries/route-sheet?courierId&date` (готовая HTML-страница), `GET /deliveries/couriers`, `PUT /deliveries/couriers/:memberId`, `/delivery-methods`.

## Отчёт и экраны
- Отчёт по доставкам (вкладка экрана «Доставки», группа «Услуги»): число, доставлено, не доставлено, доля недоставленных среди завершённых, выручка и себестоимость
  доставленных, маржа — по способам, курьерам, дням, месяцам; день — дата доставки, иначе день создания. Себестоимость и маржа только admin и owner; CSV.
- «Мои доставки» — телефонная ширина: доставки на день, адрес, контакт, телефон ссылкой `tel:`, сумма, «в пути / доставлена / не доставлена» (с комментарием), маршрутный лист.
- Печать «Маршрутный лист» курьера на день: адреса, окна, контакты, документы, суммы, подписи (без доставок «не доставлена»).
- Настройки → «Способы доставки»: справочник, тарифы и отметка «курьер» у участников.
