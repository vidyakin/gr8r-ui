# Обеспечение материалов заказа на производство

Реализовано на этапе 3 (сессия «УНФ: Производство»). Код: сервис — `packages/db/src/materials.ts` (резерв, размещение, покрытие) и
`packages/db/src/needs.ts` (сводная потребность), чистая функция покрытия — `packages/shared/src/supply.ts` (`materialCoverage`),
схема — `packages/db/src/schema/production.ts` (`production_placements`) и `schema/documents.ts` (`stock_reservations.production_component_id`),
API — `apps/api/src/routes/production-orders.ts` и `routes/production.ts`, клиент — `apps/web/src/app/production/material-stock.tsx` и `ProductionNeedsPage.tsx`.

- **Что обеспечивается.** Строки состава заказа на производство (`production_components`): материалы и полуфабрикаты. Покрытие строки считает чистая функция
  `materialCoverage` (нужно, списано, зарезервировано, размещено, не обеспечено, свободно, к поступлению, статус `full | partial | none`) — одна и та же на сервере и в интерфейсе.
- **Резерв автоматический.** При проведении заказа резервируется столько, сколько свободно на складе материалов (не больше «нужно − списано выпусками»):
  `stock_reservations.production_component_id` (строка состава) + склад + товар. Остатки блокируются — два заказа не займут одно и то же количество.
- **Резерв ручной.** В строке материала правятся «To reserve» и «Reserve warehouse»: уменьшить можно всегда, увеличить — в пределах свободного остатка склада
  (иначе 422 `insufficient_free`), смена склада переносит резерв. Резерв строки держится на одном складе.
- **Движение резерва.** Выпуск снимает резерв на списанное количество (`production_components.source_component_id` — строка состава заказа, из которой взята строка выпуска);
  отмена проведения выпуска возвращает его; отмена проведения заказа снимает весь резерв; закрытие заказа снимает остаток резерва.
- **Размещение.** Строка заказа поставщику может быть привязана к строке материала заказа на производство — `production_placements` (компонент, документ, строка документа, количество).
  Привязка делается при создании заказа поставщику на основании заказа на производство (`POST /production-orders/:id/supplier-orders`); поступление по такому заказу
  (строка поступления ссылается на строку заказа через `source_line_id`) при проведении сразу резервирует товар под заказ, отмена проведения поступления этот резерв
  снимает. Привязанное непоступившее количество — «Размещено» в карточке заказа. «К поступлению» — только **свободные** заказы поставщикам: строки, не привязанные
  ни к одному заказу на производство.
- **Дочерние заказы на полуфабрикаты.** Кнопка «Create semi-finished orders» (`POST /production-orders/:id/semi-orders`) по дефициту полуфабриката создаёт черновики
  `production_order` с `parent_document_id` и записью размещения у строки материала родителя. Выпуск дочернего заказа резервирует полуфабрикат под строку материала родителя.
- **Сводная потребность.** `GET /production/needs` — по материалам проведённых незакрытых заказов: нужно, в резерве, размещено, свободно, к поступлению, дефицит
  (дефицит = нужно − резерв − размещено − свободно; свободно не бывает меньше нуля — перерезерв заказов покупателей дефицит не раздувает; в карточке заказа «Не обеспечено» = нужно − резерв − размещено, без учёта свободного остатка — как в 1С).
  `POST /production/needs/supplier-orders` создаёт черновики заказов поставщику по поставщику товара: `products.default_supplier_id`, иначе — поставщик последнего
  проведённого поступления по товару; строки без поставщика возвращаются отдельной группой, заказ по ним не создаётся.
- **Интерфейс.** В карточке заказа — переключатель **Show stock** (колонки обеспечения с цветом и расшифровками: резервы по складам, размещение по документам,
  к поступлению по документам с датой), правка резерва и кнопки **Create semi-finished orders** / **Create supplier orders**. Отдельный экран **Needs**
  (`/production/needs`, вкладка **Production orders**) со сводным дефицитом и выбором строк; общий расчёт потребностей
  живёт на той же странице во вкладке **Stock needs** (см. «План производства и пополнение»). В карточке товара —
  поля **Default supplier** (`products.default_supplier_id`, составной FK на `companies`), **Lead days** и вкладка
  **Stock levels**.
- **Права.** Чтение — любой участник; резервирование, размещение и заказы — member и выше (как у соседних маршрутов производства).
