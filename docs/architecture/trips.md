## Данные (таблицы под RLS, ссылки составные `(workspace_id, id)`)
- `fleet_trips` — рейс: номер `РС-ГГГГ-NNNNN` (под advisory-блокировкой), вид `city | intercity`, статус `planned | in_transit | done | cancelled`, название, `date_from` / `date_to` (городской — одинаковые), время начала и конца (необязательно),
  машина, водитель, второй водитель, комментарий, `started_at` / `finished_at`.
- `fleet_trip_stops` — точка: `seq` (порядок объезда с 1 подряд), вид `load | unload | delivery`, **источник** `source_kind` (`manual | delivery | transport_order`) + `source_id`, `delivery_id` (внешний ключ на доставку, `ON DELETE SET NULL ("delivery_id")`),
  название, адрес, `lat` / `lon`, контакт, `day` (день рейса), окно `window_from` / `window_to`, вес, объём, паллеты, статус `planned | arrived | done | failed`, `arrived_at` / `done_at`.
- `fleet_waybills.trip_id` — внешний ключ на рейс, `ON DELETE SET NULL ("trip_id")` (форма с колонкой, иначе обнулится `workspace_id`).
- Настройка контроля вместимости — ключ `tripCapacityMode` в `workspaces.settings` (`warn` по умолчанию | `block`).

## Правила
- **Занятость.** Машина и водители (основной и второй) не могут быть в двух активных рейсах с пересекающимся временем: рейс без времени занимает весь день, со временем — интервал (`tripsOverlap`). 409 `trip_vehicle_busy` / `trip_driver_busy`. Машина — в работе и не в архиве (422 `vehicle_unavailable`, `vehicle_archived`).
- **Изменения.** Вид, даты, машину и водителей меняет только рейс в плане (409 `trip_not_planned`); смена водителя переносит курьера на доставки рейса. В пути можно менять название, время, комментарий и точки. Выполненный и отменённый — только чтение (409 `trip_closed`). Удаляется только рейс в плане.
- **Отправка** (`start`): нужна хотя бы одна точка (422 `trip_empty`), проверяется вместимость при режиме `block`; доставки точек становятся «в пути»; событие `fleet_trip.started`. **Завершение** (`complete`): каждая точка выполнена или не выполнена (422 `trip_stops_open`);
  событие `fleet_trip.completed`. **Отмена**: доставки без итога возвращаются в «новая» без курьера.
- **Вместимость** (`tripPeakLoad`, `tripOverloads`): груз точек «доставка» лежит в машине с начала рейса, «погрузка» добавляет, «выгрузка» и «доставка» снимают; пик сравнивается с грузоподъёмностью, объёмом и паллетами машины (пустой предел — не ограничен).
  Режим `block` — 422 `trip_overloaded` (`details.overloads`) при добавлении и правке точек, смене машины и отправке; режим `warn` — предупреждение в карточке (`warnings`) и подсветка загрузки в списке.
- **Окна времени.** Окно точки — `window_from`–`window_to` (конец не раньше начала); карточка предупреждает о точках, порядок которых противоречит окнам (`windowOrderConflicts`). Время в пути не считается — оно появится с картой (1213).
- **Расстояние по прямой** (`routeStraightKm`, гаверсинус) считается по точкам с координатами в порядке объезда: длина участков в карточке и общая по рейсу. Без координат — пусто.
- **Порядок точек** хранится в `seq`; `PUT /trips/:id/order` принимает все точки рейса ровно один раз (422 `trip_order_invalid`). Это же поле заполнит автоподбор (1213).

## Доставки в рейсе
- Точка из доставки (`POST /trips/:id/deliveries { deliveryId, index }`): адрес, контакт, окно и вес берутся из доставки, день — дата доставки в периоде рейса, иначе первый день. Доставка получает курьера = водителя рейса, статус «назначена»
  (в рейсе в пути — «в пути»). Доставка не может быть в двух активных рейсах (409 `delivery_in_trip`); завершённую в рейс не добавить (422 `delivery_finished`).
- **Синхронизация статусов.** Точка → доставка: «выполнена» → «доставлена» (пишется расход «Доставка», как обычно), «не выполнена» → «не доставлена», «в плане» / «прибыл» → «в пути». Доставка → точка: `changeDeliveryStatus` двигает точку («доставлена» → выполнена, «не доставлена» → не выполнена,
  возврат — в план), поэтому водитель может отметить доставку и из «Моих доставок». Курьера и статус «новая» вручную у доставки в активном рейсе менять нельзя (409 `delivery_in_trip`).
- Снятие точки, удаление и отмена рейса освобождают доставки (курьер снимается, статус «новая»). Доставки без рейса работают как прежде (`delivery.test.ts`).

## Путевой лист и печать
`POST /trips/:id/waybill` — `createWaybill(..., { tripId })` с машиной, водителем, датой начала и маршрутом из адресов точек; один неотменённый лист на рейс (409 `trip_waybill_exists`). Остальное — правила путевого листа ([fleet.md](fleet.md)).
`GET /trips/:id/print` — маршрутный лист рейса: форма маршрутного листа курьера (`renderRouteSheet`) с заголовком рейса, машиной, водителями, окнами и подписью водителя.

## События и автоматизации
`fleet_trip.created | updated | deleted | cancelled | stop_changed`, а также `fleet_trip.started` («Рейс отправлен») и `fleet_trip.completed` («Рейс выполнен», в payload — число выполненных и невыполненных точек). Узел **`trigger.trip_status`** («Рейс отправлен или выполнен», модуль `transport`)
запускается по выбранной ступени (`any | started | completed`). Изменения доставок пишут свои события (`delivery.updated`).

## API (`/trips`, модуль `transport`)
`GET /` (отборы `from`, `to`, `vehicleId`, `driverId`, `status`, `kind`, `q`), `POST /`, `GET|PATCH|DELETE /:id`, `POST /:id/start | complete | cancel | waybill`, `POST /:id/stops`, `POST /:id/deliveries`, `PUT /:id/order`,
`PATCH|DELETE /:id/stops/:stopId`, `POST /:id/stops/:stopId/status`, `GET /:id/print`, `GET /dispatch?date=`, `GET|PUT /settings` (запись — admin и owner). Читает любой участник, правит member и выше, guest — только чтение.

## Интерфейс
Группа «Транспорт»: «Диспетчер» (`/trips/dispatch`) и «Рейсы» (`/trips`) выше автопарка. **Диспетчер** — день с переключателем; слева нераспределённые доставки (на день и раньше, не в рейсе; перетаскиваются, есть запасной выбор «В рейс…»),
справа машины в работе с осью времени 06:00–22:00 и рейсами дня полосами (номер, статус, водитель, точки с окнами, загрузка / вместимость; красная рамка — перегруз). Бросок доставки на рейс добавляет точку, на свободную машину — создаёт городской рейс на день
(водитель — закреплённый за машиной). **Рейсы** — список с отбором по периоду, машине, статусу и виду; настройка вместимости (admin). **Карточка рейса** (`TripDialog`) — шапка, точки с порядком (стрелки), отметки «прибыл / выполнена / не выполнена» в пути,
предупреждения, путевые листы, действия «Отправить», «Завершить», «Отменить», «Создать путевой лист», «Печать маршрутного листа». Кэш `['ws', id, 'fleet', 'trips', …]`; события `fleet_trip` и `delivery` сбрасывают его (`app/data/realtime.ts`). Тексты — `trips.*` (en и ru), ошибки — `errors.*`.
