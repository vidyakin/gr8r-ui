# Зарплата (задача 1184, миграция `0050_payroll`)

Управленческий учёт как в 1С:УНФ: начисления, удержания, НДФЛ по ставке и страховые взносы процентом в затраты; регламентированной отчётности (6-НДФЛ, РСВ), больничных и отпускных по среднему нет. Решения интервью 2026-10-29 — в `docs/plans/2026-10-21-unf-production.md`, «Задача 1184».

**Где код:**
- схема — `packages/db/src/schema/payroll.ts` (+ `payment_lines.member_id`, `workspaces.payroll_insurance_rate`);
- сервис — `packages/db/src/payroll.ts` (справочники, кадровые данные, документы, заполнение, проведение, отчёты, печатные данные);
- выплата — общий код денег `packages/db/src/payments.ts` (операция `salary_payment`, `checkSalaryPayment`);
- общее — `packages/shared/src/payroll.ts` (чистые расчёты, константы), `schemas/payroll.ts`, `print/payroll.ts` (расчётный листок, Т-53); тесты `packages/shared/test/payroll.test.ts`;
- API — `apps/api/src/routes/payroll.ts` (`/payroll`), тест `apps/api/test/payroll.test.ts`;
- клиент — `apps/web/src/app/payroll/*` (`PayrollPages.tsx` — начисление и ведомости, `PayrollAdminPages.tsx` — сотрудники, отчёты, листок), словарь `payroll` (`en`/`ru`);
- демо — `packages/db/src/seed-payroll.ts`.

## Данные

- `employee_payroll (member_id)` — кадровые данные участника: приём и увольнение, организация, участок, способ отражения по умолчанию, ставка НДФЛ (13 %), счёт/карта для реестра (не секрет, только admin и owner), аванс суммой или % оклада.
- `employee_accruals` — плановые начисления с историей `valid_from`: оклад или премия (сумма), процент от продаж (`percent`, база `revenue | margin`). Действует последняя запись с датой не позже конца периода; смена в середине месяца действует с этого месяца целиком (решение исполнителя). Нулевое значение прекращает начисление.
- `payroll_kinds` — виды: системные (`salary`, `piecework`, `sales_percent`, `bonus`, `one_time`, `deduction`) создаются при первом обращении (`ensurePayrollKinds`), свои — с одной из баз; флажок «не облагается взносами» (`insurable = false`; у удержаний всегда выключен).
- `payroll_reflections` — способ отражения: статья затрат + участок.
- `payroll_headers` / `payroll_lines` — документ «Начисление зарплаты» (`payroll`, префикс НЗ, группа `payroll`): период (первый день месяца) и участок в шапке; строка — сотрудник, вид, база, ставка, дни (отработано/норма), сумма, НДФЛ, взносы, способ отражения.
- `payroll_statement_headers` / `payroll_statement_lines` — «Ведомость на выплату» (`payroll_statement`, ВЗ): вид `advance | settlement`, способ `cash | bank`.
- `payroll_moves (member_id, document_id, line_id, date, kind accrual|ndfl|deduction|payment, amount)` — регистр расчётов с персоналом, знак «долг перед сотрудником растёт» (+): начисление +, НДФЛ, удержание и выплата −.
- Ставка взносов — `workspaces.payroll_insurance_rate` (по умолчанию 30 %), `GET/PATCH /payroll/settings`.

Документы лежат в общей `documents`, `ownLines + section` — общий `POST/PATCH /documents` отвечает 422 `payments_api_only` (`isCashDocType` знает и типы зарплаты), создание и правка — только `/payroll`.

## Заполнение начисления (`fillPayroll`)

Строки автоматических видов (оклад, сдельная, процент, премия) пересчитываются, разовые начисления и удержания остаются. Берутся сотрудники с кадровыми данными, работавшие в периоде, подходящие по организации и участку шапки.
- **Оклад по табелю:** норма — рабочие дни месяца по графику сотрудника (`members.calendar_id`, иначе график воркспейса) с праздниками, без исключений; факт — те же дни с исключениями сотрудника (отпуск, больничный) и в пределах дат приёма и увольнения. Сумма = оклад × факт / норма (`salaryByDays`).
- **Сдельная:** сумма `pieceworkReport` за месяц по проведённым нарядам, поэтому совпадает с отчётом выработки. Выработка часов заказ-нарядов в сдельную не входит.
- **Процент от продаж:** по документам, где сотрудник — ответственный (`documents.responsible_id`): те же акты, реализации, возвраты и выполненные заказ-наряды, что в план-факте продаж (`postedSalesDocs`, `workOrdersFactDocs`). База `revenue` — выручка без НДС, `margin` — выручка минус себестоимость движений склада. Процент от услуг специалистов записи отдельно не считается.
- **Премия:** плановая сумма.
- НДФЛ = сумма × ставка сотрудника; взносы = сумма × ставка воркспейса (если вид облагается). Суммы правятся вручную: пустые НДФЛ и взносы при сохранении пересчитываются.

## Проведение и затраты

- Дата документа по умолчанию — конец месяца периода. Проверка закрытого периода: `assertPeriodOpen` по дате документа (общий код) и по концу месяца периода.
- Проведение пишет `payroll_moves` и затраты `period_costs` (источник `payroll`, период — месяц начисления, не дата документа). Строки группируются по статье и участку способа отражения (участок способа → участок шапки). Отмена проведения удаляет оба.
- **Без двойного счёта сдельщины:** сама сдельная в затраты не идёт — она уже в себестоимости выпуска (`piecework.md`), только долг перед сотрудником. Страховые взносы со сдельной идут в затраты (в себестоимости выпуска их нет). Удержания затрат не дают.
- Затраты распределяются при закрытии месяца по базе статьи (`month-closing.md`); для статьи в демо — «по нормочасам».
- Для каждой строки с затратой нужен способ отражения (422 `reflection_required`).

## Ведомость и выплата

- «Заполнить»: расчёт — долг перед сотрудником (>0) минус суммы в других непроведённых и проведённых ведомостях, ещё не оплаченные; аванс — сумма или % от оклада из кадровых данных, без тех, кому аванс за период уже оформлен проведённой ведомостью.
- Ведомость движений не пишет. `POST /payroll/statements/:id/pay {cashRegisterId | bankAccountId}` создаёт черновик **РКО** (способ «касса») или **списания со счёта** (способ «банк») с операцией `salary_payment`, `based_on_id` = ведомость, строка на сотрудника (`payment_lines.member_id`, статья ДДС «Оплата труда», расход) на остаток по нему. Банковская выплата — одно списание на всю ведомость.
- Проведение выплаты (общее `/documents/:id/post`) пишет `cash_moves` и `payroll_moves` (платёж −). Проверки: у каждой строки сотрудник (`member_required`), ведомость проведена (`statement_not_posted`), сумма проведённых выплат не больше суммы ведомости (`over_statement`). Отмена проведения ведомости с выплатами — 409 `statement_has_payments`.
- Состояние ведомости: `payState` `unpaid | partial | paid` по проведённым выплатам.
- **Зарплатный реестр:** `GET /payroll/statements/:id/registry` — CSV `ФИО;Счёт;Сумма` (UTF-8, разделитель `;`) по сотрудникам со счётом/картой; без счёта пропускаются (`X-Skipped-Count`). Общий простой формат — решение исполнителя, форматы конкретных банков (XML зарплатных проектов) не делались.
- **Печать:** `GET /payroll/statements/:id/print` — платёжная ведомость Т-53 (HTML, A4 альбом); `GET /payroll/payslip/print?period&memberId` — расчётный листок; КО-2 для выплаты зарплаты печатается как обычно.

## Отчёты и листок

- `GET /payroll/reports/settlements?from&to&memberId` — «Расчёты с персоналом»: долг на начало, начислено, удержано (НДФЛ и прочее), выплачено, долг на конец по сотрудникам.
- `GET /payroll/reports/summary?from&to` — начисления по видам и по участкам (по месяцу начисления проведённых документов), НДФЛ и взносы.
- `GET /payroll/payslip?period&memberId` — расчётный листок за месяц; сотрудник видит только свой.

## Права

Всё в `/payroll`, кроме листка, — admin и owner. Общие маршруты документов для типов зарплаты (карточка, проведение, отмена, удаление) — тоже только admin и owner (`payrollGuard`). Выплаты зарплаты скрыты от member в списке и карточке оплат, создавать их через `/payments` может только admin. Сотрудник видит свой расчётный листок. Тесты изоляции арендаторов — `apps/api/test/tenancy.test.ts` (RLS на всех новых таблицах) и `payroll.test.ts`.

## Интерфейс

Пункты группы «Финансы»: «Начисление зарплаты» (`/payroll`), «Ведомости на выплату» (`/payroll/statements`), «Сотрудники и ставки» (`/payroll/employees`: кадровые данные, плановые начисления, способы отражения, виды, ставка взносов), «Отчёты по зарплате», «Мой расчётный листок». Формы документов — шапка сверху, таблица ниже, комментарий внизу (как в 1С).

## Фактическая реализация

Реализовано по решениям плана (пп. 1–10) целиком, с отклонениями и ограничениями:
- сотрудники — участники воркспейса; кадровые данные в отдельной таблице `employee_payroll`, а не полями `members`;
- процент от услуг специалистов записи и выработка часов заказ-нарядов отдельными видами не считаются (процент идёт по документам продаж ответственного);
- смена оклада в середине месяца не делит месяц на отрезки;
- НДФЛ считается с точностью до копеек по строке, без округления до рублей и без нарастающего итога/вычетов;
- реестр на банк — простой CSV, не формат конкретного банка;
- начальных остатков долга перед сотрудниками нет (регистр начинается с первого начисления);
- переименование/архивирование способа отражения не пересчитывает проведённые документы.
