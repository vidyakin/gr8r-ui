# Пользовательская документация — TaskFlow, сессия 54

## Решения (опрос 2026-10-30)

1. **Где:** Markdown в репозитории `docs/user/` — один источник для справки в приложении и сайта документации.
   - В приложении: кнопка «?» в шапке каждого экрана открывает боковую панель со статьёй текущего раздела
     (по id из `SECTIONS` в `apps/web/src/app/routes.ts`), ссылки между статьями, поиск по справке. Статьи собираются в
     бандл при сборке (без сети), видны только разделы включённых модулей (`docs/architecture/licensing.md`).
   - Сайт: статическая сборка тех же файлов с поиском — рядом с лендингом (`apps/landing`), например `/docs`.
2. **Язык:** только русский. Справка — по-русски без перевода, как печатные формы; ключи `t()` только для кнопки и
   панели. Английский — позже переводом.
3. **Состав:** руководство по разделам (что на экране, поля, типовые действия, права, частые ошибки и коды
   `errors.*` по-человечески) и сценарии «как сделать» — сквозные цепочки (от лида до оплаты, от заказа до выпуска,
   от доставки до рейса, закрытие месяца, начальные остатки, зарплата).
4. **Структура:** `docs/user/<группа>/<раздел>.md`, `docs/user/howto/<сценарий>.md`, оглавление генерируется.
   Шапка статьи (frontmatter): `sections: [id, …]` — разделы из `SECTIONS`; `module` — модуль лицензий;
   `sources: [глобы файлов]` — экраны, API и сервисы, по которым написана статья; `verified: <коммит>` — на каком
   коммите статья сверена с кодом; `screenshots: [ключи]`.
5. **Актуальность:**
   - **Скрипт устаревания** `bun run docs:check`: статья устарела, если файлы из `sources` менялись после `verified`
     (git log); раздел без статьи; битые ссылки и ключи скриншотов. Выводит список и что поменялось (коммиты).
   - **Тест покрытия** (быстрый, без git): каждый id из `SECTIONS` есть хотя бы в одной статье — новый экран без
     справки роняет тест.
   - **Правило для агентов** в `CLAUDE.md` и `apps/web/AGENTS.md`: меняешь экран или поведение — обнови статью и
     `verified` в том же коммите; при сведении веток проверяю `docs:check` вместе с typecheck.
6. **Скриншоты автоматически:** скрипт Playwright поднимает приложение на демо-базе (отдельная БД `*_test`/своя, не
   рабочая), проходит по списку ключей (раздел + действие), снимает светлую тему в одном размере окна, кладёт в
   `docs/user/img/`. Запуск `bun run docs:shots`; снимки переиспользует лендинг.
7. **Генерация первой версии** — агентами по группам разделов, по коду экранов, `docs/architecture/*.md` и демо-данным,
   с проверкой в браузере. Писать для пользователя, без внутренних терминов (RLS, job, outbox).

## Фактическая реализация (задача 1236)

- `docs/user/README.md` — формат шапки, стиль, структура статьи раздела и сценария; шаблоны `_templates/section.md`, `howto.md`. Папки: ключи `NAV_GROUPS` (`production`, `trade`, `services`, `transport`, `finance`) плюс `general`, `crm`, `catalog`, `automations`; `howto/`, `img/`.
- `scripts/docs-lib.ts` (разбор шапок и `routes.ts` по тексту), `scripts/docs-check.ts` (`bun run docs:check [--strict]`), `scripts/docs-verify.ts` (`bun run docs:verify <файл…>`, `verified` = HEAD, 10 знаков).
- Устаревание: `git log verified..HEAD -- sources` (глобы как `:(glob)`); коммит, правивший и источник, и саму статью, считается сверенным (иначе `verified` нельзя поставить в том же коммите). Нет `verified` у статьи с `sources` — тоже «устарела». Ошибки: шапка, неизвестные id/`module`/папка, битые ссылки и картинки, `screenshots` без файла, глоб без файлов, неизвестный коммит `verified`. Предупреждения: устаревание, раздел без статьи вне pending, «уже описанный» id в pending.
- Тест `apps/web/src/i18n/docs-coverage.test.ts` + `docs/user/pending.json` (92 раздела; задачи 1239–1244 его опустошают). Корневой `bunfig` поднимает тестовую БД, поэтому тест запускают с `TEST_ADMIN_DATABASE_URL=postgres://postgres@127.0.0.1:5450/<имя>_test`.
- Образец — `docs/user/general/notifications.md`, сверен в браузере на отдельной БД на кластере 5450 (после проверки удалена).
- Правила добавлены в `CLAUDE.md`, `apps/web/AGENTS.md`, `docs/architecture.md`.
- Не сделано (сборка в приложение и сайт, оглавление — задача 1237, ниже): скриншоты (`docs:shots`). Замечено в приложении: бейдж непрочитанных в «Уведомлениях» в русском показывает «# непрочитанных» (плейсхолдер `#` не подставляется в `pages.notifications.unreadCount`), заголовки дней списка («Today», «Yesterday») не переведены.

## Фактическая реализация (задача 1237)

- Пакет `packages/docs` (`@gr8r/docs`, зависимость `marked`): `header.ts` (разбор шапки; им же пользуется `scripts/docs-lib.ts`), `catalog.ts` (каталог статей, оглавление по группам, поиск по заголовкам и тексту с грубым учётом окончаний, статьи раздела, адрес → раздел), `render.ts` (markdown → HTML). Без DOM и React, поэтому один код у приложения и сайта; дублирования нет.
- Санитизация: сырой HTML в статье экранируется; ссылки — только http(s)/mailto (в новой вкладке) и относительные `*.md` на существующие статьи (переходы внутри панели; битые — серый текст); картинки — только из `docs/user/img/` (нет файла — подпись курсивом).
- Сборка: `apps/web/src/app/help/bundle.ts` — `import.meta.glob(docs/user/**/*.md, ?raw, eager)` и картинки `img/*` (`?url`); файл грузится только динамическим `import()` (панель, палитра), поэтому тексты — отдельный чанк, не основной.
- Панель: `app/help/HelpPanel.tsx` (правая панель, `styles/help.css` на токенах темы), провайдер `app/overlays/help.tsx` (`useHelp()`), кнопка «?» в `layout/Topbar.tsx`. Клавиша F1 (`?` уже занят окном горячих клавиш). Раздел по адресу — `sectionOfPath(SECTIONS)`; одна статья открывается сразу, несколько — списком, нет — оглавление; кнопка «Оглавление», «Назад», поиск. Статьи выключенных модулей скрыты (`useSectionAccess().module`). Подписи — `help.*` (en+ru), статьи без перевода.
- Палитра: команда «Справка» (F1) и группа «Справка» с найденными статьями (каталог подгружается при вводе от 2 символов).
- Сайт: вторая страница сборки `apps/landing/docs/index.html` → `/docs/` (`vite.config.ts`, `src/docs/*`); адрес статьи в хеше `#/<id>`, серверу хватает статики; оглавление, поиск, адаптив, тёмная тема. В `Dockerfile` добавлен манифест нового пакета.
- Тест `apps/web/src/app/help/help.test.ts`: каждая статья рендерится, ссылки разрешаются, раздел → статья для всех `SECTIONS` кроме `system`, адрес → раздел, оглавление и поиск, санитизация.
- Проверено в браузере (отдельная БД на 5450, потом удалена): панель на «Главной», «Оплатах» и других разделах, переход по ссылке и «Назад», поиск, палитра, светлая и тёмная тема, `/docs`.
- Не сделано: якоря по заголовкам (ссылки `#…` внутри статьи отключены); хеш-адреса `/docs` не индексируются поисковиками; лендинг в Docker/деплой пока не собирается, `/docs` проверен только `vite build` и dev.
