# Платформа: тарифы и модули (TaskFlow, сессия 49)

Цель — продавать базовый функционал и полный помодульно: оператор установки (`users.is_operator`, `docs/architecture/deploy.md`,
`docs/architecture/tenancy.md`) включает арендатору модули через тарифы и докупленные модули.

## Решения (2026-10-29)

1. **Модули — крупные**, каталог в коде (`packages/shared`, без таблицы): id, название и описание (i18n), разделы навигации
   (`NAV_GROUPS`/`SECTIONS` в `apps/web/src/app/routes.ts`), корневые пути API (`TENANT_PATHS`), типы задач воркера и узлы
   автоматизаций, зависимости. Черновой состав: `core` (задачи, проекты, справочники, настройки — всегда включён), `crm`
   (лиды, сделки, воронки, реклама), `trade` (продажи, закупки, склад, цены, КП), `production` (требует `trade`), `services`
   (заказ-наряды, записи, доставка, договоры), `money` (касса, банк, онлайн-оплата, календарь), `payroll` (требует `money`),
   `automations`, `integrations` (банки, ЮКасса, вебхуки), `docflow` (сессия 48). Точное разбиение разделов — решение
   исполнителя, отметить в «Фактической реализации».
2. **Тариф + доп. модули.** Оператор ведёт справочник тарифов (`plans`: название, набор модулей, лимиты, срок пробного
   периода); арендатору назначается тариф и сверху — докупленные модули, у каждого свой срок. Включённые модули =
   `core` + модули тарифа + доп. модули с действующим сроком, плюс их зависимости. Таблицы — платформенные (не арендаторские,
   без RLS по workspace_id; правит только оператор через `SECURITY DEFINER`-функции, как `app_operator_tenants()`),
   арендатор читает только свой набор.
3. **Запрет везде:** интерфейс скрывает разделы и пункты палитры; API — middleware по корневому пути отвечает
   403 `module_disabled` (код в `errors.*`); воркер не запускает задачи, узлы и расписания отключённого модуля
   (автоматизация с узлом отключённого модуля — пропуск с понятной ошибкой в журнале запуска). Данные при отключении
   не удаляются.
4. **Срок действия и пробный период:** у тарифа и доп. модуля — дата окончания; пробный период N дней при создании
   арендатора. По истечении — режим «только чтение» на 14 дней (запись → 403 `module_expired`), затем модуль отключается.
   Баннер владельцу арендатора за 7 дней до окончания.
5. **Лимиты по тарифу:** пользователи (участники), организации, склады, объём файлов (после хранилища из сессии 48).
   Превышение — 403 `limit_exceeded` при создании; уже существующее не трогаем.
6. **«Нужно больше?»** — кнопка внизу левого меню; страница со всеми модулями: описание, возможности, отметка
   «подключён / пробный до … / не подключён», кнопка «Оставить заявку» (модули, комментарий, контакт). Заявки — в списке
   на экране оператора; если задан `OPERATOR_LEAD_HOOK_URL`, заявка дублируется лидом в вебхук лидов
   (`POST /hooks/leads/:token`, задача 1175) арендатора оператора.
7. **Журнал изменений:** кто из операторов и когда сменил тариф, модули, сроки, лимиты (старое → новое).
8. **Экран оператора:** тарифы (CRUD), у арендатора — тариф, доп. модули со сроками, лимиты и их использование, журнал,
   заявки. Демо-арендаторы и существующие — тариф «Полный» без срока (миграция), чтобы ничего не сломать.
9. **Готово, когда:** выключенный модуль не виден, его API отвечает 403, воркер его не исполняет; срок и «только чтение»
   работают; лимиты проверяются; страница «Нужно больше?» и заявки; тесты API (включая обход через прямой вызов API)
   и тест, что каждый путь из `TENANT_PATHS` принадлежит какому-то модулю; раздел `docs/architecture/licensing.md`.

### Фактическая реализация (задача 1205)

Сделаны решения 1–3, 8 и 9 (без режима «только чтение», лимитов, «Нужно больше?», журнала). Подробно — `docs/architecture/licensing.md`.

- **Состав модулей** (`packages/shared/src/licensing.ts`): `core`, `crm`, `trade`, `production` (→ trade), `services` (→ trade), `money` (→ trade),
  `payroll` (→ money), `automations`, `integrations` (→ money), `docflow` (пустой: пути, разделы и задачи добавит сессия 48).
  Решения исполнителя: справочники (`/companies`, `/contacts`, `/products`, `/organizations`, `/warehouses`, `/positions`, `/secrets`, конструктор `/entities` + `/data`)
  остались в ядре, чтобы выключенный модуль не ломал включённый; `/documents`, `/stock`, `/pricing`, `/doc-templates` (КП) — `trade`; записи на приём и доставка — `services`
  (как в плане, хотя пункт «Записи» в меню стоит в группе CRM); `/sales-plan` — `crm`; `/investments` и `/bank-import` — `money`; `/bank-connections` и ЮКасса — `integrations`;
  `action.http_request` — общий узел `automations`; узлы по лидам и сделкам — `crm`; `trigger.payment_posted` и `trigger.document_paid` — `money`.
  Зависимости `services` и `money` от `trade` добавлены потому, что их экраны работают с `/documents`.
- **Хранение.** Платформенные таблицы `license_plans`, `workspace_licenses`, `workspace_module_grants` (миграция `0057_licensing`). У двух последних есть колонка `workspace_id`,
  поэтому они подчиняются тесту покрытия RLS (ENABLE + FORCE, политика только SELECT для `app_user`, запись только `app_worker`); из выгрузки арендатора исключены (`SKIP_TABLES`).
  Справочник тарифов `app_user` не виден совсем. Запись и чтение оператора — `SECURITY DEFINER`-функции `app_operator_*`, арендатор читает только `app_workspace_license()`.
  Таблица названа `license_plans`, а не `plans`: рядом уже есть `tariff_plans` и `production_plans`.
- **Тарифы по умолчанию:** «Полный» (`all_modules`, включает и будущие модули, тариф по умолчанию) и «Базовый» (ядро + CRM + торговля, черновой состав). Арендатор без назначения
  получает тариф по умолчанию (новые регистрации, загруженные архивы), поэтому `initWorkspace` не менялся. Существующие арендаторы получили явные строки «Полный» без срока.
- **Запрет.** API: `requireModule` после `tenant()` по `MODULE_OF_PATH`, набор читается один раз на запрос; путь без модуля в `TENANT_PATHS` роняет сборку приложения.
  Публичные вебхуки (`/hooks/leads`, `/hooks/prices`, `/hooks/yookassa`) проверяют модуль сами. Воркер: задача выключенного модуля уходит в `failed` без повторов;
  расписания (биллинг, касания, просрочка сделок, записи, банки) пропускают арендаторов без модуля; flow с узлами выключенного модуля — `skipped` с причиной, без `automations`
  запусков нет, движок перепроверяет модуль на каждом шаге (модуль мог отключиться во время задержки). Интерфейс: `useSectionAccess` (меню, вторая панель, палитра, защита адреса) и пункты настроек.
- **Realtime.** Смена лицензии пишет событие `license.changed` (entity `license`) прямо из функции БД; фронтенд перечитывает весь кэш воркспейса.
- **Заложено для 1206–1209:** сроки тарифа (`workspace_licenses.plan_expires_at`) и доп. модулей (`expires_at`), пробный период тарифа (`trial_days`), лимиты тарифа и персональные
  (`limits`), авторы изменений (`updated_by`, `created_by`). Сейчас срок — жёсткая граница: по истечении модуль выключается сразу.

**Не сделано в 1205:** пункты 4–7 — см. ниже (задачи 1206–1209).

### Фактическая реализация (задачи 1206–1209)

Сделаны решения 4–7. Подробности — `docs/architecture/licensing.md`. Миграции: `0058_license_log` (1209), `0059_license_terms` (1206), `0060_license_limits` (1207), `0061_module_requests` (1208).

- **Журнал (1209).** Таблица `license_log` (одна запись — одно изменение одного поля: старое → новое, email оператора), пишут только `SECURITY DEFINER`-функции (`app_operator_set_license`,
  `app_operator_save_plan`, `app_license_start`) — поэтому журнал полон и для API, и для CLI. Правка тарифа пишется в журнал каждого арендатора на этом тарифе (`plan_edit`: модули, «все модули»,
  лимиты, пробные дни). RLS: ENABLE+FORCE, политика `USING (false)` — `app_user` не видит ни строки; таблица исключена из выгрузки арендатора. Экран: «Лицензия» арендатора → «Журнал изменений».
- **Сроки (1206).** Состояния модуля `active | readonly | off` (`moduleStates` в `@gr8r/shared`): источник — тариф и каждый доп. модуль, модуль действует, пока действует любой источник, в который он входит
  (с зависимостями). После срока 14 дней (`READONLY_DAYS`) «только чтение». `enabledModules` осталась «можно писать» (воркер, расписания, автоматизации, вебхуки лидов и ЮКассы — выключены сразу по сроку);
  `readableModules` — «можно читать» (API, меню, `/hooks/prices`). API: чтение → 200, запись (не GET/HEAD) → 403 `module_expired` с `readonlyUntil`; через 14 дней — `module_disabled`. Воркер: задачи только чтения
  (`document.pdf`, `settlement.act_pdf`, `billing.export_zip`) идут и в режиме «только чтение», остальные — как у выключенного модуля.
  Пробный период: `workspace_licenses.is_trial`; `createTenant` (CLI `--plan`, API `planId`) вызывает `app_license_start`: выбранный тариф (иначе по умолчанию) с `trial_days` → срок `now() + trial_days` и признак,
  запись `trial_started`. Тариф по умолчанию без `trial_days` и без явного `--plan` — как раньше, без строки лицензии. Самостоятельная регистрация (`/auth/signup`, `POST /workspaces`) пробный период **не** получает.
  Баннер `LicenseBanner` (owner/admin): за 7 дней до конца и в режиме «только чтение», со ссылкой «Нужно больше?». Оператор может снять признак пробного периода в диалоге лицензии.
- **Лимиты (1207).** Ключи `members`, `organizations`, `warehouses`, `storageMb` (`LIMIT_KEYS`); нет ключа — без ограничения, `0` — больше нельзя; лимит тарифа и персональный поверх него. Использование считает
  `app_usage_of(ws)` мимо RLS: участники без отключённых + неотвеченные неистёкшие приглашения; организации и склады не в архиве; объём = `files.size_bytes` (не в архиве) + `document_files.size` + `document_exports.size`.
  `assertLimit` → 403 `limit_exceeded` (`details: {limit, max, used}`) при создании приглашения, организации, склада и файла (`POST /files` по `sizeBytes`); существующее не трогается. Хранилища файлов S3 ещё нет,
  поэтому «объём» — по метаданным и PDF в БД; PDF, которые создаёт воркер, лимитом не блокируются (только учитываются). Исправлена ошибка 1205: диалог лицензии не отправлял лимиты и каждым сохранением стирал персональные.
  Экран оператора: лимиты тарифа и арендатора, использование.
- **«Нужно больше?» (1208).** Раздел `upgrade` (`/upgrade`, ядро), кнопка внизу левого меню. Заявки — таблица `module_requests`, **арендаторская** (RLS по `workspace_id`): арендатор создаёт (владелец/админ,
  `POST /license/requests`) и читает свои, менять и удалять не может (нет прав), оператор читает все и ведёт статус `new → in_progress → done|rejected` + заметка функциями `app_operator_requests` и
  `app_operator_set_request` (`/admin/requests`). Новый корневой путь не заводился: заявки живут под `/license`. Вебхук: `POST /license/requests` в той же транзакции ставит задачу `module_request.notify`
  (ядро); воркер при заданном `OPERATOR_LEAD_HOOK_URL` отправляет лид (`name`, `company`, `email|phone`, `comment`, `utm_source`), не 2xx — повтор задачи с паузой (до 5 попыток), успех → `hook_sent_at`.
  Без адреса задача завершается ничего не делая. Переменная добавлена в `.env.example`, `.env.prod.example` и сервис `worker` обоих прод-compose.
- **403 на экранах выключенных модулей.** Проверено в браузере на тарифе «Базовый» (главная, CRM, каталог, торговля, документы, карточки контрагентов, товаров, проектов, палитра, настройки). Найденные запросы
  (`/contracts`, `/production/snapshot`, `/services/work-norms`, `/work-centers`, `/document-states`, `/work-order-kinds`) теперь не уходят: хук `useModuleReady(module)` в `enabled` соответствующих хуков.
  Новый хук данных чужого модуля, живущий на экране другого модуля, нужно закрывать так же.

**Не сделано / ограничения:** режим «только чтение» блокирует любой метод кроме GET/HEAD/OPTIONS, поэтому POST-запросы, которые только читают, в нём тоже получат `module_expired` (таких в модулях не искали).
Запись в режиме «только чтение» через интерфейс в браузере до ответа сервера не доведена (форма сделки требует контрагента и сумму) — проверено тестами API; баннер и меню проверены в браузере. Платежи ЮКассы в режиме
«только чтение» не обрабатываются. Объём файлов в S3 появится вместе с хранилищем. Заявку отправляют владелец и админ, страницу видят все. Журнал не ведёт историю статусов заявок. Тесты API: 5 падений в полном
прогоне (склады — регистронезависимая уникальность, фильтр товаров, биллинг 31-го, `next_contacts`) воспроизводятся и на коммите 1205 (кластер `--locale=C`, даты), к задачам не относятся.
