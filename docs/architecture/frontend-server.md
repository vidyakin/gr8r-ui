# Фронтенд на сервере

Реализовано на этапе 2. Код — `apps/web/src/app/data` (`session.tsx`, `store.tsx`, `engine.ts`, `specs.ts`, `realtime.ts`, `api.ts`).

- **Сессия и воркспейсы.** `SessionProvider` держит `GET /auth/me` (TanStack Query, ключ `['session']`): пользователь и мои воркспейсы. Вход,
  регистрация и выход — настоящие `/auth/*` (cookie httpOnly; токена в JS нет). Без сессии `RequireAuth` ведёт на `/signin`, без воркспейсов — на
  онбординг. Ответ API с кодом `unauthorized` (сессия истекла) сам возвращает на экран входа. Активный воркспейс — настройка просмотра, хранится
  в `localStorage` (`gr8r-ui.workspace`), уходит в запросы заголовком `X-Workspace-Id` (`apiFor(workspaceId)` — типизированный клиент
  `@gr8r/api/client`, по экземпляру на воркспейс), в WebSocket — `?workspace=`. Переключатель в сайдбаре, создание воркспейса — `POST /workspaces`,
  удаление — `DELETE /workspaces/:id` (только owner, данные арендатора уходят каскадом).
- **Данные = кэш запросов.** Каждая коллекция воркспейса — один запрос `['ws', id, имя]` (все страницы по 200; активность — только свежие 200;
  задачи и проекты — с архивными, у них есть флаг `archived`). Строка API превращается в локальную сущность на границе (`specs.ts`: uuid, время в
  epoch-миллисекундах, `null` → `''`/`undefined`, `Project.last` и `Member.last` — минуты с `lastActivityAt`/`lastSeenAt`, `numeric` → число,
  размер файла ↔ байты). Компоненты и reducer остались на прежней модели (`app/data/types.ts`). `useWorkspace()` отдаёт `{ data, dispatch }`,
  `data` собирается из кэша: вложения задач — это `files` с `taskId`, порядок проектов — из `sortOrder`. Пока данные не загружены, показывается
  экран ожидания; ошибка загрузки — экран с «Try again».
- **dispatch = мутации.** Семантика действий по-прежнему описана одним reducer'ом (`store.tsx`, `crm/store.tsx`). Слой `engine.ts`:
  `before → reducer → after`, diff по коллекциям (добавлено / изменено с перечнем полей / удалено), `after` пишется в кэш (интерфейс обновляется
  сразу), diff превращается в запросы и уходит в **одну очередь воркспейса** (порядок записи сохраняется: родители раньше детей, удаление — в
  обратном порядке). Соответствие «локальное поле → поля API» — таблицы `fields` в `specs.ts`; PATCH уходит только с изменёнными полями.
  После очереди изменённые коллекции перечитываются (ключ задачи `WEB-109`, активность и уведомления считает сервер). Ошибка запроса: toast с
  сообщением сервера, остаток запросов этого действия пропускается, коллекции перечитываются — оптимистичное состояние откатывается к серверному.
- **Идентификаторы создаёт клиент.** `uid()` — uuid v7; все схемы создания принимают необязательный `id`, поэтому карточку можно открыть и менять
  до ответа сервера, а повторное создание при Undo возвращает ту же запись. Повторное использование id — 409. Статус-колонка идентифицируется
  ключом (`StatusDef.id` = `statuses.key`), uuid строки хранится рядом. Задача при повторном создании (Undo удаления) может принести прежний
  `key` — он должен принадлежать проекту и быть свободным, счётчик проекта не уменьшается.
- **Undo (`data/restore`).** Компоненты по-прежнему передают снимок `data`, захваченный до действия. Для снимка запоминается состояние ПОСЛЕ
  действия (`WeakMap`), и откатывается только разница между ними — чужие изменения, пришедшие по WebSocket в промежутке, не затрагиваются.
  Что делает откат на сервере: удалённая задача/проект создаются заново вместе с зависимыми записями (комментарии, часы, файлы, виды) под теми же
  id, мягко удалённые (файл, сделка) возвращаются через `POST /:id/restore`, архив задачи снимается, изменённые поля возвращаются PATCH'ем.
- **Удаление.** Задачи, проекты, комментарии, часы, статусы, команды удаляются насовсем (`?hard=true`; для задач и проектов это права admin и выше —
  у остальных будет toast и откат), файлы и CRM-сделки — архивированием (`DELETE` без `hard`, Undo = restore). У сделки активности остаются на
  сервере и скрываются на клиенте, пока сделка в архиве. «Архив» задачи и проекта — флаг `archived` (`DELETE` без `hard` / `restore`).
  Участник «удаляется» деактивацией (`status: deactivated`): профиль остаётся в истории.
- **Realtime.** Один WebSocket `/ws?workspace=` на вкладку (`realtime.ts`). Событие журнала (конверт без payload) помечает коллекции сущности
  устаревшими (`collectionsFor`), они перечитываются целиком; пока в полёте свои запросы — после них, чтобы не затереть оптимистичное
  состояние. Точка отсчёта — последнее событие на момент загрузки, обрыв — переподключение с `?since=<id>` и полное перечитывание. Дедупликация
  по `event.id`. Перечитывание целой коллекции выбрано вместо точечных патчей: код проще, а при 50–500 записях на воркспейс запрос дешёв;
  точечный патч (`GET /:id` + upsert) — следующий шаг, если коллекции вырастут.
- **Формат API** (для границы слоя): строки таблиц в camelCase, даты `YYYY-MM-DD` / ISO 8601, `numeric` — строки, реакции комментариев —
  `re: {эмодзи: [member id]}`, участники проекта — `members: [{memberId, permission}]`, контакты сделки — `contactIds`. Демо-данные
  генерируются в `packages/shared/src/demo` и общие для сида БД (`bun run db:seed`); типы `Task`, `Project`, … — в `packages/shared/src/domain.ts`
  (фронтенд реэкспортирует их из `app/data/types.ts`).
- **Локально остаётся только настройка просмотра**: тема, акцент, плотность, свёрнутый сайдбар, фильтры видов, плавающие окна задач, активный
  воркспейс (`localStorage`).
- Отладка и браузерные тесты (только `import.meta.env.DEV`): `window.__qc` (QueryClient), `window.__ws.dispatch/read/settled()`, `window.__crm`.

Что пока не так, как в локальной модели:
  «избранное» (`fav`) общее для воркспейса (позже — по пользователю); дерево подзадач хранится JSON'ом в задаче, поэтому одновременная правка
  подзадач двумя людьми — «последний записал»; вложения — только метаданные файла (загрузки в S3/MinIO нет); активность — последние 200 записей;
  доступ к закрытым проектам (`isPrivate`/`access`) хранится, но API ещё не фильтрует по нему; сброс пароля и подтверждение почты (нужна отправка писем)
  и вход через внешних провайдеров не реализованы — экраны остались, но честно сообщают об этом.
