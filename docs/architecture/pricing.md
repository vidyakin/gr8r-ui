# Виды цен и прайс-листы (задача 1178, миграция `0051_price_kinds`)

Как в 1С:УНФ: несколько видов цен, история цен по датам, документ «Установка цен», подстановка цены в документы по приоритету, прайс-лист (экран, печать, Excel, загрузка из файла, публичная ссылка). Решения интервью 2026-10-29 — `docs/plans/2026-10-21-unf-services.md`, «Задача 1178». Скидки и карты лояльности — задача 1179 (поверх этих видов цен).

**Где код:**
- схема — `packages/db/src/schema/pricing.ts` (+ колонка `price_kind_id` в `documents`, `contracts`, `companies`, `work_order_kinds`);
- сервис — `packages/db/src/pricing.ts` (справочник, подстановка `resolvePrices`, история, установка цен, прайс-лист, импорт, ссылки);
- общее — `packages/shared/src/pricing.ts` (округление, наценка, выбор вида по приоритету, разбор ячеек), `schemas/pricing.ts`, `print/pricing.ts` (печатная форма); тесты `packages/shared/test/pricing.test.ts`;
- API — `apps/api/src/routes/pricing.ts` (`/pricing`), публичная страница `apps/api/src/routes/hooks.ts` (`GET /hooks/prices/:token`), XLSX/CSV без библиотек — `apps/api/src/xlsx.ts`; тест `apps/api/test/pricing.test.ts`;
- клиент — `apps/web/src/app/pricing/*` (`PricingPages.tsx` — виды, установка цен, прайс-лист, импорт, ссылки; `PublicPricePage.tsx`; `ProductPrices.tsx` — блок в карточке товара; `CompanyPriceKind.tsx`), словарь `pricing`;
- демо — `packages/db/src/seed-pricing.ts`.

## Данные

- `price_kinds` — справочник: название, способ `manual | derived | cost_based`; для `derived` — базовый вид и наценка/скидка в процентах (`markup_pct`, скидка — минус); для `cost_based` — база `avg_cost | last_purchase` и наценка; округление (`rounding_step` 0.01 / 1 / 10 / 100, `rounding_mode` `math | up`, `round_to_nine` — «до 9»: после округления вычитается 1, только при шаге 10 и 100); `includes_vat`; `supplier_id` — вид цен поставщика (ручной); `update_from_receipts` — проведение поступления обновляет цены вида. Системные: «Розничная» (`retail`) и «Закупочная» (`purchase`) — ручные, не архивируются; создаются с воркспейсом (`ensurePriceKinds`), у старых — миграцией.
- `product_prices (price_kind_id, product_id, date, price, document_id, line_id)` — история: «с этой даты цена такая». Цена на дату = последняя запись с `date <= дата`, при равных датах — позднее созданная (`id` — uuid v7). Уникальности по (вид, товар, дата) нет: две установки в один день не конфликтуют. Записи документа несут `document_id`, отмена проведения удаляет их.
- `price_setting_lines (document_id, product_id, price_kind_id, price, old_price)` — строки документа «Установка цен» (`price_setting`, префикс УЦ; `ownLines + section`: общий `POST/PATCH /documents` отвечает 422 `pricing_api_only`, правка — только `/pricing/settings`). `old_price` — цена до установки на дату документа, пишется при проведении. Пара (товар, вид) в документе одна (422 `duplicate_price_line`).
- `price_list_links` — публичные ссылки: в базе только sha-256 секрета (`token_hash`), виды цен и категории (jsonb), «только с остатком», срок, отзыв, счётчик просмотров.
- `documents.price_kind_id`, `contracts.price_kind_id`, `companies.price_kind_id`, `work_order_kinds.price_kind_id` — составные внешние ключи ставит миграция (схемы ссылаются друг на друга).

## Подстановка цены

`resolvePrices(db, ws, kindId, productIds, date)` — батч: история одним запросом `distinct on`. Порядок для вида и товара: **своя ручная запись → правило вида → карточка товара (только «Розничная»/«Закупочная») → цена родителя** (вариант без своей цены берёт цену родителя, правило применяется к базе варианта с тем же откатом). Своя запись важнее правила: расчётный вид можно переопределить установкой цен.
- `derived` — цена базового вида (рекурсивно, на ту же дату) × (1 + наценка), округление вида. Циклы запрещены при создании и правке (422 `price_kind_cycle`).
- `cost_based`: `avg_cost` — средняя себестоимость остатков (`loadAvgCosts`, та же, что в калькуляции; **текущая**, не на дату); `last_purchase` — цена строки последнего проведённого поступления не позже даты, иначе цена вида «Закупочная». Нет базы — нет цены (`null`).
- Без вида и без истории подстановка равна `products.price` / `purchase_price` — прежнее поведение.

**Вид цен документа** (`pickPriceKind`, `documentPriceKind`): шапка документа (`documents.price_kind_id`) ← договор (`contracts.price_kind_id`) ← контрагент (`companies.price_kind_id`) ← вид заказ-наряда ← «Розничная». Закупки: шапка ← договор ← вид цен поставщика (`supplier_id` = контрагент) ← «Закупочная». `POST /pricing/resolve` отдаёт вид, источник и цены на дату; клиент (`pickProduct` формы документа) подставляет цену при выборе товара, кнопка «Пересчитать цены» в шапке — для всех строк. Запись на приём берёт цену на сервере (`resolveOne`: вид клиента-компании, иначе розничная), в форме записи и в документе дня цена подставляется тем же запросом.

Поступление: если у вида включено «обновлять из поступлений» — вид цен поставщика этого контрагента и/или «Закупочная» (по умолчанию **выключено**, чтобы не менять `purchase_price` молча) получают записи истории по строкам проведённого поступления; отмена проведения убирает их. Хук поступления дополняет существующий (`materials.ts`), а не заменяет.

## Совместимость

`products.price` и `purchase_price` остаются кэшем текущей цены «Розничной» и «Закупочной»: их пересчитывает из истории проведение/отмена установки цен и правка цены в карточке товара (создание и PATCH товара пишут запись истории на сегодня, поэтому история не «перебивает» правку; повторная правка в тот же день заменяет запись дня). Калькуляция, спецификации и отчёты читают кэш как раньше. Миграция перенесла положительные цены товаров в историю датой создания товара; демо-сид — `backfillProductPrices`.
Известное ограничение: запись с будущей датой кэш не меняет, и когда дата наступит, кэш обновит только следующая установка/правка. Подстановка в документы считает по истории и от кэша не зависит. Для даты раньше первой записи истории розничной цены подставляется текущая карточка.
Текстовое поле договора `price_type` оставлено для совместимости; миграция сопоставила его с видами цен по названию (без учёта регистра), экран договора теперь выбирает вид из справочника.

## Установка цен

Документ `price_setting` (группа sales, в журналах продаж его нет — свои экраны «Установка цен»). Заполнение (`POST /pricing/settings/:id/fill`): по всем товарам, по категории (с подкатегориями) — текущие цены выбранных видов; из поступления — цены строк. Существующие пары не затираются. Массовое изменение (`/mass`): `+N %` с округлением, только округление, «рассчитать по правилу вида» (для расчётных видов, ручная запись не учитывается). Проведение пишет `product_prices` с датой документа, проверка закрытого периода для этого типа не применяется (цены не бухгалтерия), отмена удаляет записи и пересчитывает кэш.

## Прайс-лист

- `GET /pricing/price-list` — товары, услуги и работы (активные, не архивные) с ценами выбранных видов на дату, отбор по категории, «только с остатком», поиск; `/price-list/print` — печатная форма (HTML, A4; PDF — печатью страницы в браузере, воркер для этого не используется); `/price-list/export?format=xlsx|csv` — выгрузка. Заголовки колонок цен названы по видам: тот же файл загружается обратно.
- **Загрузка из файла:** `POST /pricing/import/preview` (XLSX/CSV в base64, до 10 МБ, 5000 строк) определяет колонки по заголовку (артикул, название, виды цен), сопоставляет товары по артикулу, затем по точному названию (неоднозначное название — не найдено), показывает «было → стало»; `POST /pricing/import/apply` создаёт **черновик** «Установки цен» — проверить и провести можно как обычно.
- **XLSX без новой зависимости:** `apps/api/src/xlsx.ts` пишет zip без сжатия и читает zip (стандартный `node:zlib` inflate) с лимитами на число файлов и размер; формулы не вычисляются (читается кэшированное значение).
- **Публичная ссылка:** токен `<workspace_id>.<секрет>`, секрет виден один раз при создании, в базе — хэш. `GET /hooks/prices/:token` — без сессии; лимит частоты по IP и по ссылке (`rate_limits`, настройки как у вебхука лидов); любая причина отказа (неверный, чужой, отозванный, просроченный токен) — один и тот же 404. Отдаёт название организации, дату, публикуемые виды и товары: артикул, название, единицу, категорию, цены и признак «в наличии» (количества остатков не раскрываются). Закупочная, расчётные от себестоимости и цены поставщиков не публикуются: проверка и при создании ссылки (422 `price_kind_not_public`), и при чтении (вид мог измениться после создания). Страница клиента — `#/p/price/<токен>` (приложение на hash-маршрутах), вне оболочки.

## Права

- Виды цен, установку цен, импорт и ссылки правит admin и выше; документы `price_setting` для участников закрыты (как зарплата: `payrollGuard` в `/documents`).
- Закупочная, расчётные от себестоимости и цены поставщиков (`isCostKind`) скрыты от участников в списке видов, карточке товара (`/pricing/products/:id/prices|history`) и прайс-листе.
- **Исключение:** `POST /pricing/resolve` работает для всех, включая закупочные цены для документов закупок: участник и сейчас видит `purchase_price` в карточке товара и подставляет её в поступления, ограничивать подстановку значило бы сломать закупки.

События outbox: `price_kind.created|updated|archived`, `price_list_link.created|updated|revoked`, `document.price_setting_posted`.
