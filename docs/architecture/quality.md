# Контроль качества и входной контроль

Задача 1186 добавляет контроль качества поверх партийного учёта.

## Модель данных

- `stock_batches.status`: `ok`, `quarantine` или `rejected`.
- `warehouses.kind = quarantine` обозначает карантинный склад.
- `defect_reasons` хранит архивируемый справочник причин брака воркспейса.
- `production_items.defect_reason_id`, `defect_member_id` и `qc_note` дополняют количество и режим брака.
- `batch_analyses` хранит показатель, результат, норму, признак прохождения и дату анализа партии.

Все новые таблицы являются tenant-таблицами, используют `workspace_id` и составные внешние ключи. Миграция: `0091_quality.sql`.

## Правила движений

Статус партии (`stock_batches.status`) управляет расходом. Проверки идут в общем обработчике складских движений (`applyStockMoves` → `assertNoQuarantineOut`, `assignBatches`) под блокировками остатков.

- Приход на склад `kind = quarantine` создаёт партию со статусом `quarantine`; на обычный склад — `ok`. Статус задаётся при создании, у существующей партии (тот же номер) не меняется.
- Обычный расход FEFO берёт только партии `ok`. Если строка явно указывает номер партии не в `ok` — `422 batch_blocked`. Если остаток лежит в заблокированных партиях (свободного остатка без партий не хватает) — тоже `batch_blocked`.
- С карантинного склада обычный расход — `422 quarantine_blocked`. Разрешены: перемещение (только партии `ok` — решение «принять», иначе `batch_blocked`; статус партии-источника переносится на партию-получатель), возврат поставщику (`supplier_return`) и списание на статью затрат `systemKey = 'brak'` (решение «брак», в том числе для `rejected`). Возврат и брак (`MoveRequest.qualityExit`) берут партии любого статуса и работают с любого склада.

## API

- `GET/POST/PATCH/DELETE /defect-reasons` — справочник, запись доступна admin и owner.
- `GET/POST/PATCH/DELETE /stock/batches/:id/analyses` — паспорт качества партии; анализ другой партии по этому пути — 404.
- `PATCH /stock/batches/:id/status` — статус входного контроля.
- `PATCH /production-orders/:id/accounting` с полем `qc[]` — причина, виновный и примечание по позиции выпуска.
- `POST /production/:id/rework` с `itemId` и необязательным `qty` — заказ на переделку брака.
- `GET /production/reports/defects` — статистика по участку, исполнителю и причине за период.

## Изоляция и аудит

Доступ к данным идёт через контекст арендатора и RLS. Ссылки на причины, участников и партии проверяются в текущем воркспейсе. Удаление причины выполняется через стандартное архивирование CRUD-фабрики, чтобы исторические позиции выпуска сохраняли ссылку.

## Экран

Раздел «Партии» показывает статус бейджем; клик по строке открывает диалог «Анализы партии» (`batch-quality.tsx`): смена статуса и ведение анализов доступны member и выше. Вид склада «Карантин» выбирается в настройках складов.
