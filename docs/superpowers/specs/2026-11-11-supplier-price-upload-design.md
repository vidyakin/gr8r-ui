# Загрузка прайсов поставщиков — проект

> **Для исполнителя:** документ фиксирует продуктовый замысел и подтверждённые требования. Это не утверждённое техническое задание на реализацию. Перед разработкой составить технический план (разбить на этапы) и реализовывать по нему.

**Дата:** 2026-11-11.

**Цель:** дать менеджеру закупок возможность загрузить прайс поставщика из файла, сопоставить его позиции с нашей номенклатурой по артикулам поставщика и применить цены — без ручного набора цен в карточках товаров.

**Связанные материалы:** [Виды цен и прайс-листы](../../architecture/pricing.md), [Коды и номенклатура контрагентов](../../architecture/counterparties.md), [Закупки](../../user/trade/purchases.md), [Артикулы поставщика](../../user/trade/purchases.md).

## 1. Контекст

Сейчас цены поставщика попадают в систему тремя путями:

1. поступление товара (если у вида цен включено «обновлять цены из поступлений»);
2. документ «Установка цен» — вручную или загрузкой из файла (`POST /pricing/import/preview` → `/import/apply`);
3. правка карточки товара.

Ни один из путей не описывает реальную работу закупщика: **поставщик присылает свой прайс, и его надо разложить по нашим товарам**. Сопоставление в существующей загрузке идёт по нашему SKU или по точному совпадению названия, что у поставщиков не работает: артикул у них свой. Механизм артикулов у контрагента в системе уже есть (`product_partner_articles`), но в импорте прайсов он не используется.

Сопоставление по артикулу поставщика — основной путь, но он требует, чтобы артикулы были заведены у нас. Где их нет, закупщик разбирает строки вручную: сначала ищет товар по названию («Найти по названиям»), а если такого товара у нас нет — создаёт его. Поэтому два шага разнесены по разным действиям.

У каждого поставщика свой формат файла: своя шапка, свои колонки, своя первая строка данных. Поэтому формат настраивается один раз и хранится как профиль — иначе каждая загрузка начиналась бы с ручного подбора колонок.

Отдельная потребность — **сравнение цен поставщиков**: у одного товара несколько поставщиков с разными ценами, нужно видеть разброс. Данные для этого появятся сами, если у каждого поставщика будет свой вид цен с историей.

## 2. Подтверждённые требования

| Вопрос | Решение |
| --- | --- |
| Что это за механизм | Отдельные прайсы поставщиков — своя сущность, не документ «Установка цен» |
| Где живёт | Вкладка «Прайсы» в карточке контрагента-поставщика |
| Как связано с ценами | Цены попадают в номенклатуру: пишем в **вид цен поставщика** (`price_kinds.supplier_id`) |
| Как сопоставлять строки с товарами | Сначала **только по артикулу поставщика** (`product_partner_articles` этого контрагента) |
| Что делать с ненайденными строками | Сначала ищем по названиям, и только если не нашли — создаём товар (два отдельных действия) |
| Когда применяются цены | Отдельное действие «Применить» — не сразу при загрузке |
| Даты и версии | У прайса есть дата действия; версий и отката нет |
| Жизненный цикл записи | После применения запись остаётся в списке со статусом «Применён» |
| Товары, отсутствующие в новом прайсе | Их цены не трогаем — остаются прежними |
| Артикул совпал с несколькими товарами | Выбираем вручную из кандидатов |
| Артикул не найден у нас | Отдельная кнопка «Найти по названиям»; если не нашлось — отдельная кнопка «Создать товар» |
| Колонки файла | Только вручную, по профилю формата поставщика |
| Форматов у поставщика | Несколько (каждый — со своим профилем) |
| Когда настраивается формат | Профиль настраивается один раз и переиспользуется |
| Что хранит профиль | Номер первой строки данных + номера колонок: артикул, наименование, цена, единица |
| НДС | У прайса своя настройка «Цены с НДС»; при применении цены приводятся к базе вида цен поставщика |
| Единица из файла | Текстом («кг», «м»): ищем в справочнике единиц по названию/символу, не нашли — берём «шт» |
| Старый импорт в «Установке цен» | Остаётся как есть |
| Где видно цены поставщика у товара | В карточке товара — список поставщиков с их артикулами и ценами |

## 3. Подход

### 3.1 Три новые сущности

Все — с `workspace_id`, составными FK `(workspace_id, id)`, RLS через `app_secure_tenant_table`, uuid v7, деньги `numeric(18,2)`.

**`supplier_price_profiles` — профиль формата прайса поставщика**

| Поле | Смысл |
| --- | --- |
| `company_id` | Поставщик (контрагент) |
| `name` | Название профиля: «Розница 2026», «Опт» |
| `first_row` | Номер строки, с которой начинаются данные (1-based) |
| `article_col` | Номер колонки с артикулом поставщика |
| `name_col` | Номер колонки с наименованием |
| `price_col` | Номер колонки с ценой |
| `unit_col` | Номер колонки с единицей (необязателен) |

У поставщика может быть несколько профилей. Уникальность — по `(workspace_id, company_id, lower(name))` среди неархивных.

**`supplier_prices` — загруженный прайс**

| Поле | Смысл |
| --- | --- |
| `company_id` | Поставщик |
| `profile_id` | Профиль формата, по которому разобран файл |
| `name` | Название прайса |
| `kind_id` | Вид цен поставщика, в который пишем цены |
| `date` | Дата действия цен |
| `status` | `draft` → `applied` |
| `prices_include_vat` | Настройка прайса «Цены с НДС»: цены в файле указаны с НДС |
| `attachment_id` | Файл прайса (вложение) |
| `file_name`, `file_size` | Имя и размер файла для показа |
| `lines_total`, `lines_matched`, `lines_unmatched`, `lines_conflict` | Счётчики для сводки |
| `created_at`, `created_by`, `applied_at` | Служебное |

**`supplier_price_lines` — строки прайса**

| Поле | Смысл |
| --- | --- |
| `price_id` | Прайс (каскад при удалении) |
| `row_no` | Номер строки в файле |
| `article` | Артикул поставщика из файла |
| `name` | Наименование из файла |
| `unit_code` | Единица из файла, если распознана |
| `price` | Цена |
| `product_id` | Наш товар (NULL — не сопоставлен) |
| `status` | `matched` / `unmatched` / `conflict` / `skipped` |
| `candidates` | jsonb: id наших товаров с тем же артикулом — для ручного выбора |

### 3.2 Файл прайса

Хранится **вложением** (`entity_type = 'supplier_price'`): переиспользуем готовую инфраструктуру — S3, квоты, версии, сборка мусора, скачивание. Форматы: XLSX и CSV (тот же `readTable`, что у прайс-листа и смет), до 10 МБ.

### 3.3 Вид цен поставщика

Берётся существующий неархивный вид с `price_kinds.supplier_id = поставщик`. Если такого нет — создаётся автоматически при первой загрузке: `method = 'manual'`, `name = «Цены <Название поставщика>»` (при конфликте имени — с номером: «Цены Ромашка (2)»).

Системную «Закупочную» не трогаем: цена поставщика живёт в своём виде. Права на вид цен — admin+, как и сейчас.

### 3.4 Поток

**Шаг 1. Профиль формата** (один раз на формат поставщика)

«Форматы файлов» в карточке поставщика → «Настроить формат»: выбрать файл-образец → сервер отдаёт сетку (заголовки и первые строки) → пользователь отмечает строку, с которой начинаются данные, и колонки «Артикул / Наименование / Цена / Ед.» → сохранить под именем. Дальше любой прайс этого поставщика читается по профилю.

**Шаг 2. Загрузка**

«Загрузить прайс»: выбрать профиль формата → файл → сервер разбирает файл по профилю (строки до `first_row` пропускаются, значения берутся из указанных колонок) → автоматически сопоставляет каждую строку **по артикулу поставщика** этого контрагента:

- нашёлся ровно один товар → `matched`;
- нашлось несколько (артикул не уникален) → `conflict`, кандидаты в `candidates`;
- не нашлось → `unmatched`.

**Шаг 3. Разбор**

Экран прайса: строки с фильтром по статусу.

- `conflict` (артикул совпал с несколькими нашими товарами) → выбрать товара из кандидатов вручную.
- `unmatched` (артикул не найден) → **отдельная кнопка «Найти по названиям»**: сервер ищет наши товары по точному совпадению наименования из файла (сравнение без учёта регистра и краёв, как в `matchImportRows`) и показывает кандидатов; при неоднозначности (несколько товаров с одинаковым названием) товар не подставляется — кандидаты показываются для ручного выбора. Выбранный товар связывается со строкой, и артикул сохраняется в `product_partner_articles`, чтобы в следующий раз строка нашлась сама.
- Если и по названию ничего не нашлось → **отдельная кнопка «Создать товар»**: создаём наш товар (наименование из файла, единица из файла или «шт», цена продажи 0) и сразу записываем артикул поставщика в `product_partner_articles`.

То есть поиск по названиям и создание товара — **разные действия**, а не одно: сначала пробуем найти существующий товар, товар создаём только когда не нашли.

**Шаг 4. Применение**

Отдельная кнопка «Применить» с датой действия. Показываем сводку «было → стало» по видам цен. Пишем `product_prices` по виду цен поставщика: дата — дата действия, `document_id` — NULL (как у ручных правок). Перед записью удаляем прежнюю ручную запись (`document_id IS NULL`) за эту же дату по тому же виду цен и товару — как это делает `recordProductPrice`, чтобы правки одного дня не копились. Товары, которых нет в прайсе, не трогаем.

**Про НДС.** Настройка прайса «Цены с НДС» отвечает на вопрос, что записано в файле. Вид цен поставщика со своей стороны отвечает, в какой базе цены живут (`price_kinds.includes_vat`). При применении:

- базы совпадают (в файле с НДС и вид с НДС, либо без НДС и вид без НДС) — пишем цену как есть;
- базы различаются — **приводим цену к базе вида цен**:
  - из цены с НДС в цену без НДС: `цена_без_ндс = цена_с_ндс × 100 / (100 + ставка)`;
  - из цены без НДС в цену с НДС: `цена_с_ндс = цена_без_ндс × (100 + ставка) / 100`.

  Ставка — `products.vat_rate` товара (`none` / `0` / `5` / `7` / `10` / `20`), округление до копейки. Формула та же, что в `lineKop` (`packages/shared/src/documents.ts`), где при «НДС в т.ч.» сумма без НДС = сумма с НДС × 100/(100+ставка). Если у товара ставка `none`, приведение невозможно — такую строку пропускаем с предупреждением.

Это нужно, чтобы цена поставщика не разошлась с ценами в закупочных документах: документ считает суммы по своему признаку `price_includes_vat` и по ставке строки.

### 3.5 Карточка товара

Блок «Артикулы контрагентов» (`apps/web/src/app/docs/partner-codes.tsx`) уже показывает поставщика, его артикул и наименование. Дополняем **колонкой «Цена»** — цена из вида цен этого поставщика на сегодня. Цены поставщика скрыты участникам (как и прочие закупочные), поэтому колонка видна admin+.

### 3.6 Куда подставляется цена поставщика

Вид цен поставщика выбирается для закупочных документов по общему правилу `pickPriceKind` (`packages/shared/src/pricing.ts`): **вид в шапке документа → вид в договоре → вид цен поставщика → «Закупочная»**. Значит цена из прайса подставится в заказ поставщику и поступление, если:

- в шапке документа не указан свой вид цен, и
- у договора с поставщиком не задан свой вид цен, и
- вид цен поставщика существует (создаётся автоматически при первой загрузке).

Это существующее поведение — отдельной работы не требует, но нужно держать в виду при обучении пользователя: прайс не перебивает явно выбранный в документе вид цен.

Запись в `product_prices` без документа считается ручной (`source: 'manual'` в `resolvePrices`) и имеет приоритет над правилами вида — это ровно то, что нужно для цены поставщика.

## 4. API

Все маршруты — под `/pricing` (модуль `trade`), admin+ на запись и на просмотр прайсов.

| Маршрут | Назначение |
| --- | --- |
| `GET /pricing/supplier-profiles?companyId=` | Профили формата поставщика |
| `POST /pricing/supplier-profiles` | Создать/обновить профиль |
| `DELETE /pricing/supplier-profiles/:id` | Удалить профиль |
| `POST /pricing/supplier-profiles/preview` | Файл-образец → сетка для настройки колонок |
| `GET /pricing/supplier-prices?companyId=` | Загруженные прайсы поставщика |
| `POST /pricing/supplier-prices/upload` | Загрузить файл по профилю → прайс со строками |
| `GET /pricing/supplier-prices/:id` | Прайс со строками |
| `PATCH /pricing/supplier-prices/:id/lines/:lineId` | Привязать товар / пропустить строку |
| `POST /pricing/supplier-prices/:id/match-by-name` | Найти наши товары по наименованию файла для ненайденных строк |
| `POST /pricing/supplier-prices/:id/create-products` | Создать товары для ненайденных строк |
| `POST /pricing/supplier-prices/:id/apply` | Применить цены с датой действия |
| `GET /pricing/products/:id/suppliers` | Поставщики товара с артикулами и ценами (для карточки товара) |

События outbox: `supplier_price_profile.created|updated|deleted`, `supplier_price.uploaded|applied|deleted`, `supplier_price_line.updated` → инвалидация кэшей прайсов и каталога.

## 5. Границы

**Не входит:** версии прайсов и откат к прежней версии; загрузка по расписанию и через API поставщика; несколько поставщиков в одном файле; автоматическое применение при загрузке; изменение существующей загрузки из «Установки цен»; импорт прайса из DOCX/PDF.

**Следующий шаг (отдельная задача):** сравнение цен поставщиков — у товара список поставщиков с ценами и разбросом. Фундамент появляется этой задачей: у каждого поставщика свой вид цен, цены лежат в `product_prices` с датами.

## 6. Проверка

- API-тесты: загрузка файла по профилю, разбор пропускает строки до `first_row`; сопоставление по артикулу поставщика; `unmatched` → создание товара с сохранением артикула; `conflict` → ручной выбор; применение пишет `product_prices` по виду цен поставщика с датой действия; товары вне прайса не трогаются; участнику (member) — 403.
- Общие правила: `bun run typecheck`, `bun run docs:check`, тесты по затронутым пакетам.

## 7. Открытые вопросы

- **Замена ранее применённого прайса.** Если загрузить новый прайс с той же датой действия, перезапишутся ли цены, записанные предыдущим прайсом? Пока предполагаем: записи с тем же видом цен, товаром и датой заменяются, остальные остаются.
- **Единицы без НДС в прайсе с НДС.** Если вид цен поставщика «с НДС», а товар имеет ставку `none` (НДС не облагается) — цена из файла с НДС не приводится ни к чему осмысленному. Такую строку предлагаем пропустить с предупреждением; альтернатива — записать как есть и положиться на ставку строки документа.
- **Прайс поставщика без единицы в файле.** Колонка единицы необязательна; при создании товара берём «шт».
