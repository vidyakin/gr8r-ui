# Объектный учёт (стройка, электромонтаж, EPC)

Статус: **ядро начато**: справочник объектов реализован (задача 1268, сессия 57). Решения пользователя — [docs/plans/2026-11-06-construction.md](../plans/2026-11-06-construction.md).
Блок включается отраслевой опцией `construction` (задача 1258). Раздел «Объект» ниже описывает фактическую реализацию; остальные разделы — проект.

## Слои

- **Ядро** (любая проектная компания): объект, смета-бюджет, факт затрат, вехи и процент выполнения, прогноз прибыли, контроль бюджета.
- **Полевые работы** (пилот электромонтажа): табель прораба с бейджами, сменный отчёт объёмов, щиты из производства.
- **Стройка РФ**: акты КС-2/КС-3, субподряд с актами субподрядчика.

## Объект

`objects` (схема `packages/db/src/schema/objects.ts`, миграция `0093_objects`): `workspace_id`, `number` (код, уникален в воркспейсе),
`name`, `customer_id` (`companies`, составной FK), `address`, `start_date`, `due_date`, статус (`planning | active | hold | done | closed`),
`manager_id` (`members`), способ выручки (`revenue_mode`: `acts | milestones | hours`), `overhead_pct numeric(5,2)`, `project_id`
(проект задач, составной FK с `ON DELETE SET NULL (project_id)`), `warehouse_id` (склад объекта), `note`, `archived_at`.
Прорабы — `object_foremen (workspace_id, object_id, member_id)`, договоры — `object_contracts (workspace_id, object_id, contract_id)`;
ссылки на проекты, склады и договоры — составные FK, добавленные миграцией.

Аналитика «объект» (`object_id`, составной FK с `ON DELETE SET NULL (object_id)`, индекс) у документов (`documents`),
строк платежей (`payment_lines`), задач (`tasks`) и записей времени (`time_logs`). Затраты и выручка объекта собираются из этих
источников, отдельного регистра-дубля нет. В документах, задачах и времени объект проверяется при записи: свой воркспейс, не в архиве.

Настройка воркспейса `workspaces.object_overhead_pct numeric(5,2) NOT NULL DEFAULT 0` подставляется в новый объект, если процент
не указан. При создании объекта без `project_id` сервис заводит проект задач модуля `general` с именем объекта и уникальным ключом.

Права: видеть объект может участник; создание и правка — member и выше; архивирование (`DELETE /objects/:id`, удаление = архив) —
admin и выше. Деньги карточки (суммы документов и платежей, себестоимость остатков) — owner и admin (`canSeeCost`), остальным
сервер отдаёт `null`. Прораб ведёт табель только назначенных ему объектов (следующие задачи блока).

Маршруты API (`apps/api/src/routes/objects.ts`, путь `/objects` в TENANT_PATHS и модуле `trade`): `GET/POST /objects`,
`GET/PATCH/DELETE /objects/:id`, `GET /objects/:id/summary`. Карточка: список, форма и вкладки «Задачи», «Документы», «Платежи», «Склад»
(`apps/web/src/app/objects/`). Раздел скрыт без опции `construction` (`INDUSTRY_OF_SECTION`), поля «Объект» в документе, строке платежа
и задаче показываются при включённой опции или если значение уже задано.

## Смета

`object_estimates` → разделы → позиции. Типы позиций: работа, материал, щит (собственное производство), субподряд, прочее.
Позиция хранит объём и единицу, цену заказчику, плановую внутреннюю стоимость; у работы — норма часов на единицу.

- Статусы: `draft → approved`. Согласование фиксирует снимок цен и норм — база план-факта; правка каталога и закупочных цен его не меняет.
- Допработы — отдельные дополнения к смете со своим статусом (`draft | approved | rejected`); несогласованные не увеличивают стоимость договора.
- Ввод вручную, копирование прошлой сметы, импорт Excel с сопоставлением колонок. Нормативных баз (ГЭСН/ФЕР) нет.
- Суммы без НДС, ставка НДС — у позиции.
- Из позиций создаются заказ поставщику (материалы, субподряд) и заказ на производство (щиты).

## Факт затрат

| Категория | Источник |
|---|---|
| Материалы | Перемещение на склад объекта — ещё не затрата; списание в работы с аналитикой объекта — затрата по себестоимости; возврат — обратное перемещение |
| Щиты | Себестоимость выпуска при передаче/списании на объект — один раз, комплектующие и труд сборки повторно не считаются |
| Труд | Подтверждённые часы табеля × стоимость часа на дату работы (снимок при подтверждении) |
| Субподряд | Принятые акты субподрядчика |
| Прочие прямые | Документы и платежи с аналитикой объекта и статьёй затрат |
| Накладные | Процент объекта от прямых затрат |

**Стоимость часа** — из зарплаты: оклад сотрудника (`employee_accruals`) / норма часов месяца по графику сотрудника, либо почасовая ставка
сотрудника (новое поле кадровых данных), плюс взносы `workspaces.payroll_insurance_rate`. Нет ставки — пробел в прогнозе, не ноль.

## Табель прораба

Итог часов за смену: прораб выбирает объект и дату, бригаду (вручную или сканом бейджа), ставит часы пакетом с исключениями и распределяет
по позициям сметы. Записи — в учёте времени (`time_logs` или его расширение с `object_id`, позицией сметы, автором записи и подтверждением);
второй копии часов не создаётся. Статусы смены: черновик → подтверждена; правка подтверждённой — с историей и причиной.
Рабочие без входа — участники без `user_id`; бейдж хранит только код участника, повторный скан не дублирует запись. Работа онлайн.

Сменный отчёт: выполненный объём по позиции вводится один раз на бригаду (метры кабеля не умножаются на число работников).

## Выручка

- **Акты (КС-2/КС-3):** принятые объёмы по позициям × цена согласованной сметы и допработ; печатные формы по-русски.
- **Вехи:** фиксированная сумма или процент договора за этап; аванс — отдельно, не выполнение.
- **Часы:** подтверждённые часы × ставка для заказчика.

Состояния не смешиваются: выполнено, принято заказчиком, выставлено, оплачено — разные показатели.

## Процент выполнения

Способ на объекте: по доле закрытых задач, по среднему прогрессу задач, по весам задач, по объёмам сметы, вручную.

## Прогноз прибыли и бюджет

- Остаток по позиции — по темпу: (факт затрат / факт объёма) × оставшийся объём; ответственный может заменить оценку с причиной.
- Прогноз себестоимости = факт + остаток; прибыль = подтверждённая стоимость (смета + согласованные допработы) − прогноз; маржа при нулевой стоимости не считается.
- Показываются источник и дата прогноза, пробелы данных (нет ставки, цены, оценки).
- Бюджет — согласованная смета по категориям; при проведении документа с аналитикой объекта сверх бюджета — реакция объекта: нет / предупредить / запретить (422).
